## 今日核心概念

### 1. 信息系统项目生命周期模型
定义：信息系统项目从立项到收尾的完整阶段划分，常见模型包括预测型（瀑布）、迭代型、增量型、敏捷型和混合型，每种模型对应不同的需求明确度、风险水平和交付节奏。
关键要点：
- 预测型（瀑布）：需求稳定、变更少、文档驱动，适合政府/合规类项目
- 迭代型：先解决高风险需求，通过多次循环完善方案
- 增量型：分批交付可用功能，每增量可独立运行
- 敏捷型：拥抱变化、短周期迭代、价值驱动
- 混合型：预测+敏捷组合，大框架预测、小功能敏捷
- 选型依据：需求清晰度、团队规模、风险等级、合规要求、交付节奏
- 与治理关系：模型决定变更控制、进度测量、质量保证方式

### 2. 项目范围管理与WBS分解
定义：将项目可交付成果和为产生这些成果所必须开展的工作，分解成更小、更易管理的组成部分，输出范围基准（范围说明书+WBS+WBS词典）。
关键要点：
- WBS分解原则：100%原则（全部范围）、可交付成果导向、8/80规则（工作包40-80小时）
- 分解层次：项目→阶段→工作包→活动
- WBS创建方法：自上而下分解、按可交付成果分解、按生命周期阶段分解
- 范围基准三件套：范围说明书、WBS、WBS词典
- 范围管理六过程：规划范围管理、收集需求、定义范围、创建WBS、确认范围、控制范围
- 范围蔓延vs镀金：蔓延是干系人推动加需求，镀金是团队主动加功能
- 范围控制输出：变更请求、经验教训、项目管理计划更新

### 3. 关键路径法CPM与进度网络分析
定义：在项目进度网络图中，从开始到结束所有路径中工期最长的一条，决定项目最短完工时间，浮动时间为零的活动构成关键路径。
关键要点：
- PDM四关系：FS（结束-开始）、FF（结束-结束）、SS（开始-开始）、SF（开始-结束）
- 提前量Lead与滞后量Lag：FS+5表示开始前等5天
- 关键路径特征：总浮动时间TF=0、自由浮动时间FF=0
- 进度压缩两种方式：赶工（增加资源，成本↑）和快速跟进（并行开展，风险↑）
- 蒙特卡洛模拟：基于概率分布得出完工日期的置信区间
- 关键链法CCPM：考虑资源约束、设置项目缓冲PB/接驳缓冲FB/资源缓冲RB
- 进度基准：经批准的进度模型，作为进度控制依据

### 4. 项目成本管理与挣值分析EVM
定义：通过已完工作的预算值(EV)、实际成本(AC)、计划值(PV)三个核心指标，对项目范围、进度、成本进行综合绩效测量的一体化方法。
关键要点：
- 三大指标：PV（计划值/BCWS）、EV（挣值/BCWP）、AC（实际成本/ACWP）
- 四大偏差：CV=EV-AC（成本偏差）、SV=EV-PV（进度偏差）
- 四大绩效指数：CPI=EV/AC（成本绩效）、SPI=EV/PV（进度绩效）
- 预测公式：EAC=BAC/CPI（典型偏差）、ETC=EAC-AC、VAC=BAC-EAC
- TCPI完工尚需绩效指数：TCPI=(BAC-EV)/(BAC-AC)
- 偏差分析：CV<0超支、SV<0滞后；CPI<1成本失控、SPI<1进度落后
- 挣值曲线：S曲线对比，预测完工趋势

### 5. 信息系统项目质量管理与七种工具
定义：通过质量规划、质量保证、质量控制三过程，应用老七工具（流程图/鱼骨图/帕累托图/控制图/散点图/直方图/趋势图/检查表）和新七工具（亲和图/树状图/矩阵图/优先矩阵/过程决策程序图/活动网络图/关联图）开展质量管理。
关键要点：
- 三过程：规划质量管理（制定标准）、管理质量（过程保证）、控制质量（成果检验）
- 质量七工具记忆口诀："因果帕控流核直散"（因果图/帕累托/控制图/流程图/核查表/直方图/散点图）
- 新七工具记忆口诀："亲树矩优过活联"
- 帕累托图二八原则：80%问题由20%原因引起
- 控制图：UCL/LCL/CL三线，7点规则判异常
- 质量成本COQ：预防成本、评估成本、内部失败成本、外部失败成本
- ISO 25010质量模型：功能适合性、性能效率、兼容性、易用性、可靠性、安全性、可维护性、可移植性

## 案例分析题

**题目**：
某省"智慧人社"一体化服务平台建设项目，总投资4500万元，工期18个月，由A公司总包，采用瀑布模型开发。系统涵盖就业服务、人才服务、社保服务、劳动监察四大模块。项目第6个月初进行绩效审查，相关数据如下：
- 第6个月初PV（计划值）=1200万元
- 第6个月初AC（实际成本）=1500万元
- 第6个月初EV（挣值）=960万元
- BAC（完工预算）=4500万元

项目实施过程中还出现以下问题：
1. 项目经理在项目启动时未制定质量管理计划，导致测试阶段发现大量接口兼容性问题，返工成本超300万元
2. 测试团队采用"边开发边测试"方式，未按需求规格说明书逐项验证，出现"测试通过但需求未实现"情况
3. 因某核心开发人员离职，未做好知识转移工作，导致后续维护困难，关键代码无人能解释
4. 客户提出在系统中增加"电子社保卡"新功能，项目经理直接安排开发团队实施，未走变更控制流程

请根据以上案例，回答以下问题：
1. 计算第6个月初的CV、SV、CPI、SPI，并分析项目绩效
2. 若按当前绩效预测EAC和VAC，项目最终成本会超支多少
3. 请分析本项目在质量管理、变更管理、知识管理方面存在的主要问题
4. 请给出相应的改进措施

**参考答案**：
1. 绩效计算与分析：
- CV = EV - AC = 960 - 1500 = -540万元（CV<0，成本超支）
- SV = EV - PV = 960 - 1200 = -240万元（SV<0，进度滞后）
- CPI = EV/AC = 960/1500 = 0.64（每花1元仅完成0.64元工作，成本绩效差）
- SPI = EV/PV = 960/1200 = 0.80（进度绩效不佳，只完成80%计划工作）
- 综合分析：项目成本严重超支（CPI=0.64），进度滞后（SPI=0.80），处于"双红"状态，需要立即采取纠偏措施。

2. 完工预测：
- 假设未来工作按当前绩效完成，EAC = BAC/CPI = 4500/0.64 ≈ 7031.25万元
- VAC = BAC - EAC = 4500 - 7031.25 ≈ -2531.25万元
- 即项目最终可能超支约2531.25万元

3. 主要问题分析：
- 质量管理问题：
  * 未制定质量管理计划，缺乏明确的质量标准和验收准则
  * 测试策略错误，"边开发边测试"违反瀑布模型V模型验证原则
  * 测试未对照需求规格进行需求跟踪验证
  * 接口兼容性等缺陷未在早期发现，返工成本高
- 变更管理问题：
  * 增加"电子社保卡"功能未走变更控制流程
  * 缺乏CCB（变更控制委员会）或CCB未发挥审批作用
  * 范围蔓延未得到控制
- 知识管理问题：
  * 核心开发人员离职前未进行知识转移
  * 关键代码缺乏文档说明和注释
  * 缺乏组织过程资产积累机制
  * 形成单点故障（bus factor=1）

4. 改进措施：
- 质量管理改进：
  * 在规划阶段制定质量管理计划，明确质量标准和度量指标
  * 按瀑布模型采用V模型验证方式，每个开发阶段对应测试验证
  * 建立需求跟踪矩阵RTM，确保每个需求都有对应测试用例
  * 引入代码评审、单元测试、集成测试、系统测试、验收测试五道质量关
  * 加强接口规范设计和评审，提前发现兼容性问题
- 变更管理改进：
  * 建立CCB变更控制委员会，所有变更必须书面申请、评估、审批
  * 实施整体变更控制流程：申请→记录→评估→审批→实施→验证→关闭
  * 评估变更对范围/进度/成本/质量的影响
  * 拒绝未经审批的"口头变更"
- 知识管理改进：
  * 建立代码规范和注释标准
  * 实施结对编程、代码评审制度
  * 关键人员离职前必须完成知识转移并签署交接文档
  * 建立组织过程资产库（OPA），积累经验教训
  * 推行"文档带教+独立演练"双重知识转移机制

**踩分要点**：
1. 挣值计算必须准确：CV/SV/CPI/SPI四个指标缺一不可，结果要带单位（万元）
2. 绩效判断要双指标：CPI和SPI同时分析，不要只看一个
3. EAC公式要选对：典型偏差用BAC/CPI，不要混淆其他三种
4. 问题分析要分层：质量管理、变更管理、知识管理三大类，每类至少2-3个具体问题
5. 改进措施要对应：每个问题都要有对应解决方案，体现"对症下药"
6. 要体现管理理念：质量前置、变更受控、知识积累

## 记忆口诀

**生命周期模型**："预迭增敏"——预测型、迭代型、增量型、敏捷型，按需求变化程度递进

**WBS分解**："100%原则+8/80规则+三件套基准"——说明书、WBS、词典缺一不可

**关键路径CPM**："TF=0是关键"——总浮动为零必为关键；"赶工加钱快跟加险"

**挣值EVM**："EVA PV三值，CV SV两偏，CPI SPI两指"——记住三值两偏两指六要素

**质量七工具**："因果帕控流核直散"——因果图/帕累托/控制图/流程图/核查表/直方图/散点图

**质量三过程**："规划定标准管理保过程控制查结果"

**变更控制流程**："申记评审实施验关"——申请、记录、评估、审批、实施、验证、关闭

**知识管理**："显性靠写隐性靠带"——文档化+师徒制双轮驱动
