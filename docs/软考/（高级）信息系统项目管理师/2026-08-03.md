## 今日核心概念
### 1. 商业论证与项目治理再探
定义：商业论证是从业务战略出发，以可量化方式证明项目投资合理性的文件体系，是项目治理委员会决策与项目持续存在的根本依据。
关键要点：
- 商业论证三要素：战略一致性、收益可衡量、风险可承受
- 项目章程是商业论证的浓缩快照，章程六要素（目的/可测目标/高层级需求/风险/里程碑/预算）
- 治理委员会对商业论证负问责责任，承诺ROI下降超阈值须启动复审决策
- 商业论证需动态更新，与变更控制联动，重大变更要回头校准商业论证
- 商业论证与项目集章程差异：项目集章程须增协同退出标准接口规范收益里程碑

### 2. 收益实现管理（BAM）
定义：BAM是确保项目交付物转化为业务价值并持续度量的结构化方法，覆盖识别/定义/规划/交付/维持/评估全周期。
关键要点：
- 收益实现四步骤：识别收益→规划路径→交付追踪→维持评估
- 收益责任人必须明确，与项目责任人分离，归属业务部门或PMO
- 收益度量三层：交付层/业务层/战略层，对应KPI/BSC/战略指标
- 收益转移计划：从项目移交到运营，明确运维责任与考核机制
- 收益后评价：项目关闭6~12个月后启动，验证实际vs承诺并提炼教训

### 3. 组织级项目管理（OPM）成熟度模型
定义：OPM成熟度模型是评价组织级项目管理能力的标准体系，用以发现差距、指导改进、提升价值交付。
关键要点：
- OPM3四阶梯：标准化→可测量→可控制→持续改进（标测控改）
- CMMI五级：初始级→已管理级→已定义级→定量管理级→优化级（初管定定优）
- P3M3五视角：管理控制→收益管理→风险管理→组织治理→信息管理
- 成熟度评估三阶段：启动（明确范围/组建团队）→评估（访谈/打分/差距分析）→改进（路线图/优先级）
- 提升路径：通常每年半级，每级3~6月改进周期，避免一刀切激进改造

### 4. 战略地图与项目组合对齐
定义：战略地图用BSC四视角描绘战略主题与因果链，项目组合对齐通过组合漏斗将战略转化为项目优先级与资源分配。
关键要点：
- BSC四视角：财务/客户/内部业务流程/学习与成长（财客流学）
- 战略地图三层：战略主题→战略目标→KPI指标
- 组合漏斗五层：战略过滤→财务约束→风险门槛→组合平衡→项目授权
- 战略对齐金字塔：战略层→组合层→项目集层→项目层→活动层（战组项活）
- 战略漂移检测：定期校准实际组合vs战略优先级，差距超15%须复审

### 5. 项目治理与PMO协同
定义：项目治理是对项目决策权问责机制与监督框架的安排，PMO通过支撑/控制/指令三种类型支持治理落地。
关键要点：
- 治理三要素：问责（谁负责）、决策（谁拍板）、监督（谁核查）
- PMO三类型：支持型（咨询/工具/培训）、控制型（流程/合规/审计）、指令型（直接管理项目）
- 治理vs管理：治理定方向（为什么做/不做什么），管理抓执行（如何按时按质做）
- 治理委员会组成：业务负责人+财务+合规+PMO负责人+外部专家，人数5~7人单数
- 治理失守三大信号：商业偏差隐瞒、ROI持续下降、关键变更未经复审

## 案例分析题
**题目**：
某银行启动"数字化转型三年项目集"，总投入8亿元，下设12个子项目（A公司数据中台8000万、B公司智慧网点2亿、C公司开放银行生态1.5亿等），项目集治理委员会由副行长挂帅，成员包括各业务部门总监与信息科技部总经理。项目实施两年后审计发现以下问题：
1. 项目集启动时商业论证承诺三年ROI 78%，但项目集章程中仅列项目预算与里程碑，未明确各子项目的协同退出标准与统一接口规范；
2. C公司在第10个月未经项目集CCB审批，直接修改与B公司对接的开放API规范，导致B公司接口联调返工3次，延误工期60天，超支300万；
3. 治理委员会第二次例会发现智慧网点项目业务回报率从78%降至51%，但未启动商业论证复审决策，仅要求项目经理"想办法补救"；
4. 项目集统一度量指标仅看各子项目交付进度（财务/进度），未覆盖业务收益指标（如手机银行月活、开放银行交易笔数）；
5. 智慧交通二期作为数据中台的下游应用，因数据中台交付延误2月而被迫推迟，但项目集层面未建立跨子项目依赖管理机制；
6. A公司项目经理反映其团队按敏捷Scrum实施，但B公司坚持瀑布开发并要求A公司提供完整设计文档才肯接口对接；
7. 项目集收尾阶段，B公司核心架构师离职后无人能维护开放API规范，导致接口文档与实际代码严重脱节，知识断链。

问题：
（1）请分析本项目集中商业论证与项目集章程管理存在的主要问题（至少4条）。
（2）请计算C公司因接口规范变更造成的成本绩效（已知B公司返工3次，每次50万，工期延误60天，原计划PV=2000万，第10月末EV=1200万）。
（3）请说明收益实现管理（BAM）视角下，本项目集应当如何完善收益度量体系？
（4）针对智慧网点项目ROI持续下降的问题，治理委员会应如何依法依规进行决策？请列出具体决策步骤。
（5）针对跨子项目依赖管理与知识管理断链问题，请提出改进措施。

**参考答案**：
（1）商业论证与项目集章程管理问题：
- 商业论证与项目集章程脱节：章程未引用商业论证关键指标（ROI 78%/三年收益），导致治理决策缺乏量化基准
- 章程缺失协同标准与退出标准：未明确12个子项目统一的接口规范、数据标准、里程碑依赖与退出条件
- C公司变更未走项目集CCB流程，章程中变更控制条款被架空
- 章程中缺少收益责任人明确安排，ROI下降无人问责
- 章程中风险与假设未更新，无法应对开放银行生态这种高变动环境

（2）成本绩效计算：
- 返工成本 = 3×50 = 150万
- 超支 = 300万（含返工与延误损失）
- 实际成本AC = 原预算2000万（PV对应）+ 超支300万 = 假设AC = 2300万（按题意B公司侧）
- 第10月末EV = 1200万，假设AC = 1500万（按PV-B公司预算2000万的阶段比例推算，简化）
- CV = EV-AC = 1200-1500 = -300万
- SV = EV-PV = 1200-2000 = -800万
- CPI = EV/AC = 1200/1500 = 0.80
- SPI = EV/PV = 1200/2000 = 0.60
- EAC（典型偏差）= BAC/CPI = 2000/0.80 = 2500万
- TCPI（按BAC）= (BAC-EV)/(BAC-AC) = (2000-1200)/(2000-1500) = 800/500 = 1.60
- 结论：项目严重超支且严重延误，必须立即启动变更控制与赶工决策

（3）BAM收益度量体系完善：
- 三层度量：交付层（各子系统上线率/接口联调通过率）+ 业务层（手机银行月活/开放银行交易笔数/智慧网点业务办理量）+ 战略层（数字化客户占比/客户净推荐值NPS/ROI）
- 每个收益指标明确：度量公式、数据来源、采集频率、责任人、目标值
- 收益责任人明确：业务部门总监负责业务收益，PMO负责交付收益，治理委员会负责战略收益
- 收益转移计划：每个子项目交付后30天内完成业务运营转移，明确运维责任
- 收益后评价：项目集关闭6~12个月后启动，独立评估实际vs承诺

（4）治理委员会决策步骤：
- 第一步：核实数据，要求项目经理与业务部门联合提交ROI下降分析报告
- 第二步：触发商业论证复审流程，重新评估收益、成本、风险、战略一致性
- 第三步：依据复审结果作决策：继续/调整/终止/暂停/重启，决策需治理委员会正式投票
- 第四步：若决定调整，需明确调整方案（缩小范围/追加投资/重组团队/延长周期）
- 第五步：决策结果书面化，更新商业论证与项目集章程，下达子项目执行
- 第六步：建立定期监控机制，每月度量ROI，每月向治理委员会汇报

（5）改进措施：
- 跨子项目依赖管理：建立项目集级依赖登记册+依赖可视化看板+月度跨子项目协调会+关键路径依赖优先级排序+接口Owner制（每个接口指定唯一责任人）
- 知识管理断链：建立项目集知识库+强制文档化要求+代码与文档同步审核+关键岗位AB角+核心架构师强制知识转移（含演练+独立接手证明）+季度知识审计
