# （中级）系统集成项目管理工程师 · 2026-08-11

## 今日核心概念

### 1. 项目成本管理与挣值分析EVM

**定义**：项目成本管理是在批准的预算内完成项目所需的过程，包含规划成本管理、估算成本、制定预算、控制成本四个子过程。挣值分析（EVM）是把范围、进度、成本三个基准整合到同一坐标系进行绩效度量与预测的方法体系。

**关键要点**：

1）**成本管理四过程**

| 过程 | 核心输出 | 关键工具 |
|------|----------|----------|
| 规划成本管理 | 成本管理计划 | 专家判断、数据分析 |
| 估算成本 | 成本估算、活动成本估算 | 类比估算、自下而上估算、三点估算、参数估算 |
| 制定预算 | 成本基准、项目资金需求 | 成本汇总、储备分析（应急储备vs管理储备） |
| 控制成本 | 成本预测、变更请求、绩效报告 | 挣值分析、预测、储备分析、绩效审查 |

2）**挣值三参数与四个指标（核心公式，必背）**

| 指标 | 公式 | 含义 |
|------|------|------|
| PV（计划值） | 计划完成工作的预算成本 | 截止日应花多少钱 |
| EV（挣值） | 实际完成工作的预算成本 | 截止日实际干了多少预算价值的活 |
| AC（实际成本） | 实际完成工作的实际成本 | 截止日实际花了多少钱 |
| CV（成本偏差）| EV - AC | >0节约、<0超支 |
| SV（进度偏差）| EV - PV | >0超前、<0滞后 |
| CPI（成本绩效）| EV/AC | >1节约、<1超支 |
| SPI（进度绩效）| EV/PV | >1超前、<1滞后 |

3）**预测公式（高频）**

- EAC（完工估算）= BAC / CPI（典型情况）
- EAC = AC + (BAC - EV)（按当前绩效）
- EAC = AC + 新估算剩余工作ETC
- VAC（完工偏差）= BAC - EAC
- TCPI（完工绩效指数）= (BAC - EV) / (BAC - AC)

4）**估算类型与精度**

| 类型 | 精度 | 适用阶段 |
|------|------|----------|
| 粗略量级估算（ROM） | -50%~+100% | 立项早期 |
| 预算估算 | -10%~+25% | 详细可研 |
| 确定性估算 | -5%~+10% | 详细设计 |

5）**储备分析（必考易错）**
- **应急储备**：应对"已知-未知风险"，包含在成本基准内，由项目经理动用。
- **管理储备**：应对"未知-未知风险"，不包含在成本基准内，需发起变更动用。
- 考试陷阱：管理储备动用需走整体变更控制；应急储备由项目经理自主决定。

6）**成本基准与成本预算的关系**
- 成本基准 = 批准的成本预算 + 应急储备（不含管理储备）。
- 项目总资金需求 = 成本基准 + 管理储备。

### 2. 项目质量管理七过程与质量工具

**定义**：质量管理是把组织的质量政策应用于规划、管理、控制项目质量要求的过程，包含规划质量管理、管理质量（QA）、控制质量（QC）三个过程组及七个子过程。系统集成项目的质量需覆盖产品（软件/硬件）与项目（过程）两个维度。

**关键要点**：

1）**质量管理三过程组、七过程（与六大知识领域对应）**

| 过程组 | 过程 | 核心输出 |
|--------|------|----------|
| 规划 | 规划质量管理 | 质量管理计划、质量测量指标 |
| 执行 | 管理质量（QA） | 质量报告、测试与评估文件、变更请求 |
| 监控 | 控制质量（QC） | 质量控制测量结果、验收可交付成果、变更请求 |
| - | - | 规划→管质→控质三过程不可省略 |

2）**七大质量工具（横道图必背）**

| 类别 | 工具 | 用途 |
|------|------|------|
| 原因分析 | 因果图（石川图、鱼骨图） | 寻找问题根本原因，4M1E（人机料法环） |
| 过程分析 | 流程图 | 分析过程环节、识别瓶颈 |
| 数据收集 | 帕累托图 | 二八法则，找关键少数问题 |
| 数据展示 | 直方图、控制图 | 展示分布、监控过程稳定性 |
| 趋势分析 | 散点图 | 展示两个变量相关性 |
| 质量检查 | 核对单 | 确认步骤是否完成 |
| 层级分析 | 亲和图 | 对语言资料分组归类 |

3）**七种基本质量工具口诀**
> **"因果流程图，帕累直方散，核对亲和加"**
> （因果图、流程图、帕累托图、直方图、散点图、核对单、亲和图）

4）**规划质量 vs 管理质量 vs 控制质量三过程辨析**

| 维度 | 规划质量管理 | 管理质量（QA） | 控制质量（QC） |
|------|--------------|----------------|----------------|
| 时点 | 规划过程组 | 执行过程组 | 监控过程组 |
| 对象 | 计划如何做质量 | 过程与产品的一致性 | 工作成果与质量要求的符合性 |
| 工具 | 标杆对照、成本效益、统计抽样 | 审计、过程分析、根本原因分析 | 检查、测试、统计抽样 |
| 思维 | 预防为主 | 过程导向、预防 | 检查导向、纠偏 |

5）**质量保证QA vs 质量控制QC（高频对比题）**

| 维度 | QA（质量保证） | QC（质量控制） |
|------|----------------|----------------|
| 目标 | 让过程正确（过程导向） | 让产品正确（产品导向） |
| 时机 | 过程进行中、提前预防 | 过程后/交付前、检查纠偏 |
| 角色 | 全员，过程改进 | QC人员，检测把关 |
| 工具 | 审计、培训、流程改进 | 测试、检查、统计抽样 |
| 关系 | QA提出"过程改进"要求 → QC执行检测 | QC发现问题 → QA分析根因 |

6）**质量测量指标与质量报告**
- 质量测量指标：缺陷密度、MTBF平均故障间隔时间、MTTR平均修复时间、SLA达成率、客户满意度。
- 质量报告：把测量结果、建议改进、风险信息向干系人汇报。

7）**质量成本（COQ）四大类**
- 预防成本（培训、过程改进）
- 评估成本（测试、检查）
- 内部失败成本（返工、报废）
- 外部失败成本（保修、召回、声誉损失）
- 经典原则：**预防成本增加 → 失败成本下降**，整体COQ下降。

### 3. 项目进度管理与关键路径CPM

**定义**：进度管理是确保项目按时完成所需的过程，包含规划进度管理、定义活动、排列活动顺序、估算活动持续时间、制定进度计划、控制进度六个过程。关键路径法（CPM）通过计算活动之间的逻辑关系确定项目最短工期与浮动时间。

**关键要点**：

1）**进度管理六过程**

| 过程 | 核心输出 | 工具 |
|------|----------|------|
| 规划进度管理 | 进度管理计划 | 专家判断 |
| 定义活动 | 活动清单、活动属性、里程碑清单 | 分解、滚动式规划 |
| 排列活动顺序 | 项目进度网络图、依赖关系 | PDM、ADM（箭线图） |
| 估算活动持续时间 | 持续时间估算 | 类比、参数、三点估算（PERT）、储备分析 |
| 制定进度计划 | 进度基准、项目进度计划 | 关键路径、资源优化、进度压缩 |
| 控制进度 | 工作绩效信息、进度预测 | 挣值分析、绩效审查、关键路径分析 |

2）**PDM四依赖关系（节点法）**

| 类型 | 关系 |
|------|------|
| FS（完成-开始） | 前置活动完成后，后续才能开始 |
| SS（开始-开始） | 前置开始后，后续即可开始 |
| FF（完成-完成） | 前置完成后，后续才能完成 |
| SF（开始-完成） | 前置开始后，后续才能完成（极少用） |

3）**关键路径计算**

- **最早开始ES** = max(所有前置活动的EF)
- **最早完成EF** = ES + 持续时间
- **最迟完成LF** = min(所有后续活动的LS)
- **最迟开始LS** = LF - 持续时间
- **总浮动TF** = LS - ES = LF - EF
- **自由浮动FF** = min(紧后活动的ES) - EF
- **关键路径** = 总浮动为0的活动组成的路径，**工期最长，决定项目最短工期**。

4）**进度网络图绘制规则**
- AOA（箭线图）：节点表示事件，箭头表示活动；只能表示FS依赖；需引入虚活动解决逻辑关系。
- AON（PDM节点图）：方框表示活动，箭头表示依赖；可表示四种依赖；现代项目主流。
- 考试陷阱：AOA只能表示FS，不能表示SS/FF/SF；要表示其他关系必须用AON或加虚工作。

5）**进度压缩技术（高频案例题）**

| 技术 | 含义 | 代价 |
|------|------|------|
| 赶工（Crashing） | 增加资源（人或加班）缩短工期 | 增加成本、风险增大 |
| 快速跟进（Fast-tracking） | 并行执行原计划串行活动 | 返工风险、质量风险 |
| 范围缩减 | 削减范围 | 影响功能、需CCB审批 |

6）**三点估算PERT公式**

- 三角分布：TE = (O + M + P) / 3
- β分布（标准PERT）：TE = (O + 4M + P) / 6
- 标准差σ = (P - O) / 6
- 方差σ² = ((P - O) / 6)²

7）**资源优化技术**

- **资源平衡**（Resource Leveling）：关键路径可能改变 → 工期可能延长
- **资源平滑**（Resource Smoothing）：关键路径不变 → 不超出资源限值、不延长工期
- 考试陷阱：资源平衡可能改变关键路径，资源平滑不改变。

### 4. 项目范围管理与WBS分解

**定义**：范围管理是确保项目"做且只做"所需的全部工作的过程，包含规划范围管理、收集需求、定义范围、创建WBS、确认范围、控制范围六个过程。WBS是范围管理的核心工具，把可交付成果逐层分解为可管理的工作包。

**关键要点**：

1）**范围管理六过程**

| 过程 | 核心输出 |
|------|----------|
| 规划范围管理 | 范围管理计划、需求管理计划 |
| 收集需求 | 需求文件、需求跟踪矩阵RTM |
| 定义范围 | 项目范围说明书（含范围、排除项、验收、可交付成果） |
| 创建WBS | 范围基准、WBS词典 |
| 确认范围 | 验收的可交付成果、变更请求 |
| 控制范围 | 工作绩效信息、变更请求 |

2）**WBS分解原则与要点**

- **100%原则**：所有下一层工作之和等于上一层工作，涵盖全部范围。
- **8/80原则**：工作包一般不小于8小时、不大于80小时。
- **4-6层原则**：通常分解到4~6层。
- **可交付成果导向**：按可交付成果分解，而不是按组织结构。
- **责任明确**：每个工作包对应唯一的责任人/责任部门。

3）**WBS分解方法**

- **按可交付成果分解**（主流）
- **按项目阶段分解**
- **按子项目分解**（适合大项目集）
- 三者关系：**阶段 + 可交付成果 + 责任** 三维交叉。

4）**WBS与WBS词典的区别（高频考点）**

| WBS | WBS词典 |
|-----|---------|
| 层次化的"工作分解结构图" | 每个WBS元素的详细说明文档 |
| 可视化分解结果 | 文字化定义 |
| 范围基准的一部分 | 范围基准的一部分 |

WBS词典包含：工作描述、责任人、责任人负责范围、进度里程碑、成本估算、验收标准、合同信息。

5）**需求管理核心点**

- 需求层次：**业务需求、干系人需求、解决方案需求、过渡需求、项目需求**（从上到下）。
- 需求收集工具：访谈、问卷、观察、原型法、焦点小组、JAD联合应用开发、群体创新、标杆对照。
- 需求跟踪矩阵RTM：实现需求从来源→设计→开发→测试→交付的双向追溯。
- 需求变更：必须走整体变更控制流程，由CCB审批。

6）**范围确认 vs 范围控制（易混淆）**

| 维度 | 范围确认 | 范围控制 |
|------|----------|----------|
| 目的 | 干系人验收已完成的可交付成果 | 监控范围状态、管控范围变更 |
| 时机 | 项目阶段末期 | 项目全过程 |
| 输出 | 验收可交付成果 | 变更请求、工作绩效信息 |
| 工具 | 检查、群体决策 | 偏差分析、趋势分析 |

7）**范围蔓延 vs 镀金（高频陷阱）**

- **范围蔓延**（Scope Creep）：未经控制的范围扩大，**项目团队被外部干系人强加**。
- **镀金**（Gold Plating）：未经批准的额外功能，**项目团队主动添加**。
- 两者都属"未经变更控制"，但责任主体不同；解决方案都是**走变更控制流程**。

### 5. 项目风险管理全流程与应对策略

**定义**：风险管理是系统化识别、分析、应对、监控项目风险的过程，包含规划风险管理、识别风险、定性风险分析、定量风险分析、规划风险应对、实施风险应对、监控风险七个过程。

**关键要点**：

1）**风险管理七过程**

| 过程组 | 过程 | 核心输出 |
|--------|------|----------|
| 规划 | 规划风险管理 | 风险管理计划 |
| 规划 | 识别风险 | 风险登记册、风险报告 |
| 执行 | 定性风险分析 | 风险登记册更新（概率/影响/优先级） |
| 执行 | 定量风险分析 | 数据分析（蒙特卡洛、决策树、敏感性分析） |
| 执行 | 规划风险应对 | 风险登记册更新（应对策略/预算/责任人） |
| 执行 | 实施风险应对 | 变更请求、经验教训 |
| 监控 | 监控风险 | 工作绩效信息、风险再评估 |

2）**风险分类**

- **已知风险**：已识别并可分析的风险，用应急储备应对。
- **未知风险**：未识别或无法分析的风险，用管理储备应对。
- **整体项目风险**：影响项目整体的不确定性，PMBOK第七版新增概念。
- **单个项目风险**：影响具体目标的风险。

3）**风险应对策略（威胁vs机会，必须区分）**

| 类型 | 威胁应对 | 机会应对 |
|------|----------|----------|
| 上策 | 规避（消除威胁源） | 开拓（确保机会实现） |
| 中策 | 转移（保险、外包） | 分享（合资、合作） |
| 下策 | 减轻（降低概率/影响） | 提高（提高概率/影响） |
| 兜底 | 接受（应急储备/不行动） | 接受（不行动） |

考试陷阱：威胁不能用"开拓"；机会不能用"规避/转移/减轻"。

4）**概率与影响矩阵**

- 矩阵单元格用"概率×影响"得出风险评分。
- 高中低风险的临界值由组织定义。
- 优先级排序：评分越高越优先应对。

5）**定量风险分析三大工具**

| 工具 | 适用 | 关键输出 |
|------|------|----------|
| 蒙特卡洛模拟 | 项目整体工期/成本分布 | 概率分布图、置信区间 |
| 决策树分析 | 多方案比较 | 期望货币值EMV、各方案比较 |
| 敏感性分析 | 单因素影响 | 龙卷风图（关键变量排序） |

6）**EMV计算公式**

- 期望货币值 = ∑(概率 × 影响金额)
- 决策树节点EMV = ∑(分支概率 × 分支EMV)
- 选择**EMV最大**的方案（收益）/**EMV最小**的方案（成本）。

7）**风险登记册演进路径**

- 识别风险：风险登记册雏形（已识别风险 + 潜在责任人 + 潜在应对）。
- 定性分析：加入概率/影响/优先级/分类。
- 定量分析：加入数值分析结果。
- 规划应对：加入应对策略、预算、触发条件、残余风险、次生风险。
- 监控风险：跟踪状态、新增风险、关闭已实现风险。

## 案例分析题

**题目**：

某市卫健委启动"智慧医疗一体化平台"建设项目，总投资 2600 万元，工期 18 个月，全部使用财政资金。目标是整合全市 12 家市级医院、58 家社区卫生服务中心的 HIS、LIS、PACS、电子病历等系统，向上对接省全民健康信息平台，向下服务 800 万市民健康档案与远程门诊。

项目实施过程中发生以下事件：

（1）**范围与WBS阶段**：项目经理小李直接按照"医院端系统、社区端系统、市民端系统、监管端系统"四个子系统分解WBS，每个子系统下设30~50个工作包。WBS未包含"项目管理""需求管理""变更管理""数据治理"等过程性工作，也未做范围基线确认。会议评审时业务部门提出"还有大量数据治理与接口对接工作没纳入"，小李回复"这些不是项目工作，会后单独讨论"。

（2）**进度计划阶段**：项目采用PDM节点图编制网络图，关键路径为"需求调研→概要设计→详细设计→HIS接口开发→LIS接口开发→PACS接口开发→系统集成测试→UAT验收→上线"，工期 78 周。小李审查发现"详细设计" 工期 12 周过长，启用资源平衡后将其缩短为 8 周；启用"快速跟进"将"概要设计"和"详细设计"两个阶段并行执行 4 天，并安排开发人员加班赶工。压缩后关键路径变为"需求调研→概要设计/详细设计并行→HIS接口开发→LIS接口开发→PACS接口开发→系统集成测试→UAT验收→上线"，工期仍为 75 周。

（3）**成本与挣值阶段**：项目执行到第 9 个月（工期已过 50%），小李汇总数据如下：
- BAC（完工预算）= 2600 万元
- PV（计划值）= 1300 万元（第 9 月末按计划累计应支出）
- AC（实际成本）= 1450 万元（实际已支出）
- EV（挣值）= 1100 万元（按实际完成工作的预算价值）

小李根据 CPI 数据直接判断"项目一定超支"，向财务申请追加预算 200 万元。财务未同意，建议先做完工预测后再议。

（4）**质量管理阶段**：小李认为系统集成项目"质量是开发出来的"，未单独编制质量管理计划，仅在开发规范中零散提及"应符合相关标准"。系统集成测试发现接口对接失败率高达 38%，部分医院系统版本差异较大、字段定义混乱。测试人员出具质量报告指出"过程未定义、测试用例覆盖不全、缺陷修复返工率高"，小李认为"这是测试部门责任"，未做过程改进。

（5）**风险管理与质量成本阶段**：项目识别出"医院核心系统宕机""数据迁移失败""接口厂商不配合""人员流动""需求变更频繁"等 30 余项风险。小李对所有风险都采用"接受"策略，理由是"概率都不高，没有必要花预算应对"。项目执行过程中"接口厂商不配合"实际发生，导致工期延误 6 周、成本超支 150 万元；"数据迁移失败"风险实际发生，损失 80 万元。

**参考答案**：

**问题 1：WBS分解与范围基线的错误及改进**

存在的错误：
- **WBS未包含过程性工作**。"项目管理""需求管理""变更管理""数据治理"等过程性工作虽然不直接产出可交付成果，但**100%原则要求WBS覆盖项目全部工作**，过程性工作必须纳入WBS。
- **WBS未做范围基线确认**。范围基线 = WBS + WBS词典 + 项目范围说明书，三者必须经过CCB/干系人审批签字，作为后续范围控制的依据。
- **小李未响应干系人提出的问题**。"会后单独讨论"违背范围管理流程，应立即纳入WBS或正式记录不纳入的理由。
- **未创建需求跟踪矩阵（RTM）**，需求—接口—测试无法双向追溯。

改进建议：
- 重新编制WBS，把"项目管理""数据治理""接口对接协调"等过程性工作纳入，作为独立的"项目管理"与"数据治理"分支。
- 编制完整的范围基准（WBS + WBS词典 + 项目范围说明书），组织CCB与关键干系人评审签字。
- 建立需求跟踪矩阵RTM，覆盖12家医院、58家社区的多源需求。
- 后续对范围变更严格执行整体变更控制流程。

**问题 2：进度计划与压缩的错误**

存在的错误：
- **"资源平衡"用于缩短工期的理解错误**。资源平衡是为了解决资源冲突，可能延长工期，**不会缩短工期**。若真把"详细设计"从12周压到8周，应使用"赶工"（增加资源）或"范围缩减"。
- **快速跟进的并行方式错误**。"概要设计"与"详细设计"在工程逻辑上**存在严格的依赖关系**（概要设计是详细设计的输入），不应并行4天；快速跟进应应用于**本可并行的串行活动**（如"概要设计"与"原型评审"）。
- **关键路径计算判断错误**。题干最后给的关键路径"概要设计/详细设计并行"仍为75周，比原始78周仅缩短3周，但同时启动了赶工与快速跟进，**与题干描述不符**（实际工期应小于资源平衡结果）。需要重新审查网络图逻辑关系。
- **赶工与快速跟进的风险未评估**。赶工增加成本、可能影响质量；快速跟进可能造成返工；均未做影响分析、未报CCB审批。

改进建议：
- 重新审视网络图逻辑关系，"概要设计→详细设计"应为严格的FS依赖，不能并行。
- 真正可压缩的活动往往是接口开发与测试之间、设计与编码之间；采用"快速跟进"应针对并行可能性强的环节。
- 任何压缩必须做进度、成本、质量、风险四维影响分析，并报CCB审批。
- 建立**进度储备**应对压缩带来的风险，避免"压完失控"。

**问题 3：挣值计算与预测**

计算：
- CV = EV - AC = 1100 - 1450 = **-350万元**（成本超支350万元）
- SV = EV - PV = 1100 - 1300 = **-200万元**（进度滞后）
- CPI = EV/AC = 1100/1450 ≈ **0.759**（<1，超支严重）
- SPI = EV/PV = 1100/1300 ≈ **0.846**（<1，进度滞后）

完工预测（按典型公式）：
- EAC = BAC / CPI = 2600 / 0.759 ≈ **3425.6万元**
- VAC = BAC - EAC = 2600 - 3425.6 ≈ **-825.6万元**（完工时将超支约826万元）
- TCPI = (BAC - EV) / (BAC - AC) = (2600-1100) / (2600-1450) = 1500 / 1150 ≈ **1.304**

判断项目状态：
- CPI=0.759，SPI=0.846，项目**成本超支、进度滞后**双重失控。

小李预算追加申请的评价：
- **追加200万元不合理**。按当前绩效预测，完工将超支约826万元，仅追加200万元**远不足以覆盖**未来成本缺口；正确的做法是先重新评估、制定纠偏计划，必要时整体变更基准、追加预算应基于重新核定的EAC。
- TCPI=1.304 > 1，意味着未来工作必须保持高于当前绩效才能完成原预算，**实现难度极大**。
- 财务建议"先做完工预测后再议"是正确的。

**问题 4：质量管理的错误与QA/QC职责划分**

存在的错误：
- **未单独编制质量管理计划**。系统集成项目涉及12家医院、58家社区，接口复杂、版本多样，必须有专门的质量管理计划，包含质量标准、测量指标、QA/QC角色与频率。
- **"质量是开发出来的"是片面认知**。质量应**通过规划、构建、测试、改进全过程保障**，把开发与测试割裂开是错误的。
- **小李错误地把质量问题归咎于测试部门**。接口对接失败率38%是过程管理（QA）问题，不是测试检测（QC）问题；测试只负责发现缺陷，根本原因在需求、设计、变更、接口治理等过程。
- **未做过程改进**。测试报告已指出"过程未定义、测试用例覆盖不全、缺陷修复返工率高"，QA部门应据此开展根本原因分析、改进开发与变更流程。

QA与QC的职责划分：
- **QA（质量保证，管理质量）**：聚焦**过程**，目标是让过程正确；关注活动是否按既定过程执行、过程是否需要改进；工具包括审计、过程分析、根本原因分析、培训。
- **QC（质量控制，控制质量）**：聚焦**产品**，目标是让产品正确；关注可交付成果是否符合质量要求；工具包括检查、测试、统计抽样、缺陷追溯。
- 正确顺序：QA建立过程→QC执行检测→QC发现问题→QA分析根因→QA改进过程→QC再验证。

COQ优化方向：
- 当前外部失败成本（接口返工、医院停机、上线失败）已大量发生，必须**增加预防成本**（标准化接口规范、统一数据字典、接口测试平台、培训）。
- **增加评估成本**（早期接口联调、自动化测试）。
- **降低内部失败成本**（减少返工、规范变更）。
- **降低外部失败成本**（避免上线后医院投诉、政府追责）。
- 原则：**预防成本增加 → 评估与失败成本下降 → 总COQ下降**。

**问题 5：风险应对的失误与处置**

失误分析：
- **所有风险统一采用"接受"策略是重大失误**。风险应对必须根据风险评分（概率×影响）选择策略，不能"一刀切"。高概率高影响的风险（如"接口厂商不配合""数据迁移失败""医院核心系统宕机"）必须采用规避、转移或减轻策略。
- **未识别次生风险**。"快速跟进"会增加返工风险（次生风险），"赶工"会引发质量风险、人员疲劳风险，本项目均未识别。
- **未做定量分析**。仅做定性分析，未用蒙特卡洛/决策树/敏感性分析，无法量化风险对工期/成本的影响。
- **未分配应急储备**。题干暗示"已识别风险"应使用应急储备应对，未分配应急储备意味着风险资金来源缺失。

已发生风险的处置：
- **"接口厂商不配合"风险**：启动应急储备 + 备用接口厂商 + 法律合同追责（合同约束条款）+ 第三方接口适配器破解。
- **"数据迁移失败"风险**：启动应急储备 + 数据双写校验 + 分批迁移 + 灰度切换 + 回滚预案 + 数据稽核。
- 同时进行**风险再评估**，识别新的次生风险，更新风险登记册，并向CCB与管理储备申请额外预算。
- 召开**经验教训总结会**，建立组织级风险知识库。

**踩分要点**：

**问题 1（WBS）——必写"100%原则 + 过程性工作 + 范围基准 + RTM"**
- 100%原则是WBS的核心法则，过程性工作（项目管理、变更、数据治理）必须纳入WBS。
- 范围基准 = WBS + WBS词典 + 项目范围说明书，三者缺一不可，且必须签字。
- 改进建议统一套用"流程 + 工具 + 制度 + 人员"四维。

**问题 2（进度）——必写"资源平衡 vs 资源平滑 + 赶工 vs 快速跟进的适用对象 + 关键路径变更判断"**
- 资源平衡可能改变关键路径、延长工期；不会缩短工期。
- 资源平滑不改变关键路径、不延长工期。
- 赶工增加资源、不改变依赖；快速跟进改变依赖关系、可并行。
- 快速跟进不适合有强依赖关系的活动（如概要设计→详细设计）。

**问题 3（EVM）——逐条算 + 给结论 + 评价决策**
- 必算出 CPI、SPI、CV、SV、EAC、VAC、TCPI 七项指标。
- 评价小李的预算追加申请是否合理（基于TCPI>1的不可达性论证）。
- 注意"项目成本超支"≠"必须追加预算"，需先纠偏再决策。

**问题 4（质量）——抓住"QA过程导向 vs QC产品导向 + COQ四类成本"**
- 必写关键词：**规划质量管理、管理质量QA、控制质量QC、过程审计vs产品测试、七种基本质量工具、COQ预防/评估/内部失败/外部失败**。
- 案例陷阱识别：把质量问题甩锅给测试部门是错误认知，必须明确"过程问题归QA，产品问题归QC"。

**问题 5（风险）——抓住"威胁vs机会应对策略 + 次生风险 + 应急储备vs管理储备"**
- 必写关键词：**威胁四策略（规避/转移/减轻/接受）+ 机会四策略（开拓/分享/提高/接受）、EMV、蒙特卡洛、敏感性分析、风险登记册演进路径**。
- 案例陷阱识别：所有风险"一刀切"接受是错误做法，必须按概率×影响矩阵分级应对。

**通用踩分纪律**
1. 每问先写"错误/问题"再写"理由/措施"，一问一段，编号分条。
2. 凡涉及数字的地方必须写出具体数字（CPI=0.759、TCPI=1.304、超支826万元等），只写"超支严重"不得分。
3. 措施类回答统一套用"**流程 + 工具 + 制度 + 人员**"四维度。
4. 案例细节（接口对接失败率38%、返工高、CPI/SPI具体数值、30项风险全部接受）均为采分点，必须逐一回应。

## 记忆口诀

**1. 挣值三参数与四指标**
> **"PV计划、EV挣、AC实花，CV减AC、SV减PV；CPI挣/AC、SPI挣/PV"**
> 数字判断：**"CV/SV>0好，<0糟；CPI/SPI>1好，<1糟"**

**2. 挣值预测四指标**
> **"EAC=BAC/CPI（典型），VAC=BAC-EAC，TCPI剩/剩"**
> TCPI公式：**（BAC-EV）/（BAC-AC）**，>1难达成

**3. 应急储备 vs 管理储备**
> **"应急在基线、项目经理动；管理在基外、变更才动"**
> 风险层级：**已知-未知用应急，未知-未知用管理**

**4. QA vs QC（必背对比）**
> **"QA管过程、QC管产品；QA预防、QC检查；QA用审计、QC用测试"**
> 一句话：**"过程对不对找QA，产品好不好找QC"**

**5. 七种基本质量工具**
> **"因果流程图，帕累直方散，核对亲和加"**
> （因果图、流程图、帕累托图、直方图、散点图、核对单、亲和图）

**6. 关键路径计算**
> **"ES取最大、EF=ES+D、LF取最小、LS=LF-D；TF=LS-ES，关键路径TF=0"**
> 关键路径 = **工期最长的路径，决定项目最短工期**

**7. PDM四依赖**
> **"FS最常用、SS并行起、FF并行结、SF极少用"**
> AOA只能表示FS；表示其他关系必须用AON或加虚工作

**8. 进度压缩三技术**
> **"赶工加资源、快速跟进并行、范围缩减减内容"**
> 适用：**"赶工不改依赖，快速跟进改依赖，范围缩减需CCB"**
> 代价：**"赶工加成本，快速跟进加风险，范围缩减缩功能"**

**9. 资源平衡 vs 资源平滑**
> **"平衡改关键、可能延工期；平滑不改关键、不延工期"**
> 目的：**平衡解决资源冲突，平滑解决资源限值**

**10. 三点估算PERT**
> **"三角（O+M+P）/3，β分布（O+4M+P）/6"**
> 标准差：**（P-O）/6**，方差：**（P-O）²/36**

**11. WBS三原则**
> **"100%全覆盖、8/80时限制、4-6层适中"**
> 分解方法：**"按可交付、按阶段、按子项目，三维交叉"**

**12. 范围蔓延 vs 镀金**
> **"蔓延是外部强加，镀金是内部自加"**
> 对策：**"二者都要走变更控制流程"**

**13. 风险应对四威胁四机会**
> **"威胁：规避/转移/减轻/接受；机会：开拓/分享/提高/接受"**
> 威胁不能用开拓，机会不能用规避/转移/减轻

**14. 风险储备双轨**
> **"应急储备→项目经理→已知-未知；管理储备→变更动用→未知-未知"**
> 储备层级：**"应急在成本基准内，管理在成本基准外"**

**15. COQ质量成本四类**
> **"预防/评估/内部失败/外部失败，加预防降失败"**
> 一句话：**"把钱花在预防上，远比花在失败上划算"**
