## 今日核心概念
### 1. 项目质量管理（Project Quality Management）
定义：在项目全生命周期中，应用组织的质量方针，策划质量目标、过程与职责，并通过质量保证与质量控制活动，确保项目交付物满足干系人明示与隐含需求的过程。
关键要点：
- 三大过程组：① 规划质量管理（Plan Quality Management）；② 管理质量 / 质量保证（Manage Quality / QA）；③ 控制质量（Control Quality / QC）。
- 核心理念：质量是规划出来的，不是测试出来的；预防胜于检查（Prevention over Inspection）。
- 与进度/成本关系：质量提升通常伴随成本上升、进度延长，三者需通过规划阶段平衡。
- 软考高频考点：质量管理横跨 49 个过程，规划阶段输出"质量管理计划"，执行阶段做"管理质量"，收尾阶段做"控制质量"。

### 2. 规划质量管理（Plan Quality Management）
定义：识别项目及其可交付成果的质量要求与标准，并书面描述如何通过项目质量活动达到这些标准的过程。
关键要点：
- 输入：项目章程、干系人登记册、需求文件、风险登记册、组织过程资产。
- 输出：质量管理计划、质量测量指标、需求跟踪矩阵（可作为输出更新）。
- 工具与技术：① 成本效益分析（COQ）；② 质量成本（COQ：预防成本+评估成本+失败成本）；③ 七种基本质量工具；④ 标杆对照（Benchmarking）；⑤ 实验设计（DOE）。
- 软考高频陷阱：质量管理计划 ≠ 质量测量指标，前者是"如何做"，后者是"度量什么"。

### 3. 管理质量（Manage Quality / QA）
定义：把组织的质量政策与质量标准应用到项目全过程中，转化为可执行的合格性活动，并审计质量活动执行情况的过程。
关键要点：
- QA 是过程导向（Process-oriented）：审计过程是否合规、是否按计划执行、是否持续改进。
- 核心动作：质量审计（Quality Audit）、过程分析、根本原因分析（5 Why、鱼骨图）、预防措施。
- 与 QC 区别：QA 关注"过程是否正确"，QC 关注"产品是否正确"。
- 工具：亲和图、PDCA 循环（计划-执行-检查-行动）、质量改进方法（Kaizen）。
- 软考考点：QA 输出"变更请求"和"经验教训登记册"，是 PDCA 中"Check & Act"的载体。

### 4. 控制质量（Control Quality / QC）
定义：监督并记录质量活动的执行结果，评估绩效并提出变更建议，确保项目输出物符合明示与隐含质量标准的过程。
关键要点：
- QC 是产品导向（Product-oriented）：检验可交付成果是否满足质量标准。
- 核心工具：① 七种基本质量工具（因果图、流程图、核对单、帕累托图、直方图、控制图、散点图）；② 统计抽样；③ 检查（Inspection）；④ 测试/产品评估。
- 输出：质量控制测量结果、核实可交付成果、变更请求、工作绩效信息。
- 七工具口诀：因果流程核对单，帕累直方控制散；前因对策后展布，因果查根散点关联。
- 软考高频考点：控制图用于判断过程是否"受控"（In Control），超出控制界限即异常。

### 5. 质量成本（Cost of Quality, COQ）
定义：在项目全生命周期内，为确保产品质量而支出的所有成本，以及因未达标造成的失败成本之和。
关键要点：
- 三大类别：① 预防成本（Prevention，培训、流程优化、文档）；② 评估成本（Appraisal，测试、检查、审计）；③ 失败成本（Failure，内部返工 + 外部索赔、保修）。
- 失败成本细分：内部失败（交付前发现）+ 外部失败（交付后客户发现，后者代价通常是前者 10 倍以上）。
- 黄金法则：预防成本 < 评估成本 < 失败成本，最优策略是加大预防成本投入。
- 软考高频考点：COQ 是规划质量管理的"成本效益分析"核心，常以选择题形式考查三类辨析。

### 6. 软件质量模型（ISO/IEC 25010 / McCall）
定义：用于衡量软件产品质量的多维度模型，为质量度量与评价提供标准框架。
关键要点：
- ISO/IEC 25010 八大特性：功能适合性、性能效率、兼容性、易用性、可靠性、安全性、可维护性、可移植性。
- McCall 经典三维度：产品运行（正确性、可靠性、效率、完整性、易用性）、产品修订（可维护性、可测试性、灵活性）、产品迁移（可移植性、可重用性、互操作性）。
- 与政务系统对应：可靠性（7×24 不中断）+ 安全性（等保三级）+ 可维护性（运维变更快速响应）是政务项目核心质量子特性。
- 软考考点：八大特性名称易混淆，需结合"功能-性能-兼容-易用-可靠-安全-维护-移植"顺口溜记忆。

## 案例分析题
**题目**：
某省"互联网+政务服务"平台二期项目总投资 8200 万元，工期 14 个月，包含统一受理、协同办理、智能问答、效能监察、电子证照共享 5 大子系统。2026 年 3 月项目进入系统测试阶段，8 月底计划初验。
问题背景：
- 系统测试阶段累计发现缺陷 380 个，其中"协同办理"子系统 210 个，占 55%。
- 项目经理老张采用"帕累托图"分析，识别出 80% 的缺陷集中在 8 个核心模块，决定优先修复。
- 8 月初版本灰度发布后出现 2 次严重故障：① 智能问答 API 响应超时（>30s）；② 电子证照共享接口返回数据错乱。
- 客户以"性能不达标"为由，要求赔偿 120 万元，并暂停初验。
- 项目组内部有人认为"功能都实现了，不影响验收"，老张坚持先修缺陷再初验。
- 项目章程中质量目标："系统可用率 ≥ 99.95%（7×24），平均响应时间 ≤ 3s，严重故障恢复 ≤ 30 分钟"。
- QA 审计发现：未按项目章程要求进行"性能压测"和"安全渗透测试"，质量审计未形成报告。

请回答：
1. 项目质量管理包含哪些过程？本案例中哪类质量工具被正确使用？漏掉了哪些关键审计？
2. 帕累托图属于哪类质量工具？请画出帕累托图的典型形态，并解释如何应用于缺陷修复优先级排序。
3. 控制质量过程应输出哪些成果？针对本案例 2 次严重故障，应采取哪些具体质量控制措施？
4. 客户的"性能不达标"赔偿要求是否合理？合同角度应如何处置？涉及哪些质量保证责任？
5. 项目经理老张"先修缺陷再初验"的做法是否正确？质量与进度冲突时如何抉择？请结合预防胜于检查理念说明。

**参考答案**：
1. 项目质量管理三大过程：① 规划质量管理；② 管理质量（QA）；③ 控制质量（QC）。
本案例正确使用的工具：帕累托图（控制质量过程，七种基本质量工具之一）。
漏掉的关键审计：
- ① 质量审计（QA 过程核心）：未按项目章程要求进行性能压测和安全渗透测试，质量审计未形成报告。
- ② 过程审计：测试用例评审、设计评审、代码走查记录缺失。
- ③ 风险审计：未识别灰度发布的性能风险。
2. 帕累托图属于"七种基本质量工具"之一，是控制质量（QC）过程的核心工具。
帕累托图典型形态：双柱状图 + 累计折线图。横轴按缺陷类别降序排列，纵轴左侧为缺陷数量（柱状）、右侧为累计百分比（折线），80% 缺陷集中在 20% 模块的关键少数上。
应用步骤：
- ① 收集缺陷数据，按模块分类统计。
- ② 按频次降序排列。
- ③ 计算累计百分比。
- ④ 划定 80% 关键少数，形成"重点修复清单"。
- ⑤ 集中资源（80% 资源）攻克关键少数缺陷，剩余 20% 资源覆盖长尾问题。
3. 控制质量过程应输出 6 类成果：
- ① 质量控制测量结果（缺陷密度、可用率、响应时间实测值）。
- ② 核实可交付成果（NV：Validated Deliverables）。
- ③ 工作绩效信息（缺陷修复率、回归通过率）。
- ④ 变更请求（针对不可接受缺陷）。
- ⑤ 质量报告（Quality Report）。
- ⑥ 经验教训登记册更新。
针对 2 次严重故障的具体措施：
- ① 智能问答 API 响应超时：性能压测（JMeter/Locust）、慢 SQL 优化、加缓存、增加超时告警、限流降级。
- ② 电子证照共享接口数据错乱：接口字段校验、加密签名校验、回归测试、灰度发布逐步放量。
- ③ 共同动作：根因分析（5 Why）、故障复盘报告、纳入缺陷库、回归测试覆盖。
4. 客户"性能不达标"赔偿要求合理性分析：
- 合理性：项目章程已明确"平均响应时间 ≤ 3s"是质量目标，实际 >30s 严重偏离，属合同违约。
- 合同处置流程：
  - ① 双方核对项目章程中的质量目标条款（已签字盖章，是合同附件）。
  - ② 调阅性能测试报告与压测数据，确认偏差事实。
  - ③ 承建方在 28 天内提交《质量问题整改方案 + 索赔答辩书》。
  - ④ 友好协商赔偿金额（建议采用"实际损失 + 适度补偿"原则）。
  - ⑤ 协商一致签订《索赔处理备忘录》；未达成则走 DAB/仲裁/诉讼。
- 质量保证责任：① 承建方未完成性能压测 → 违约；② 灰度发布未走 CCB → 流程违规；③ 修复延误 → 间接损失扩大。
- 建议处置：暂停初验 → 修复缺陷 → 第三方复测 → 性能达标后再启动初验 → 同步协商赔偿。
5. 老张"先修缺陷再初验"的做法正确：
- ① 符合"质量第一"原则：严重缺陷不修复，初验必失败，反而推迟进度。
- ② 符合"预防胜于检查"理念：初始阶段投入修复成本，远低于交付后客户发现的失败成本（10 倍以上）。
- ③ 符合合同义务：质量不达标即初验，是将风险后置，承建方违约责任加重。
质量与进度冲突时的抉择原则：
- ① 不可妥协类：合同/章程明文规定的质量目标、安全合规底线（如等保三级）—— 质量优先。
- ② 可妥协类：非核心功能的体验优化、UI 美化、文档完善—— 进度优先。
- ③ 黄金法则：质量成本最低点 = 预防成本 < 评估成本 < 失败成本；质量让步越多，后返工成本越高。
- ④ 软考答题套路：先讲原则（预防胜于检查），再讲平衡（COQ），最后讲流程（变更控制 CCB）。

**踩分要点**：
- 题 1：必须列出三大过程名称 + 帕累托归属（七种基本质量工具）+ 至少 2 项漏掉的审计。
- 题 2：双柱状图 + 累计折线图 + 80/20 原则 + 5 步应用流程是满分点。
- 题 3：6 类输出名称 + 2 次故障各 3 个具体措施 + 根因分析。
- 题 4：合理 + 28 天 + 协商 → DAB → 仲裁/诉讼四层级 + 至少 3 项质量保证责任。
- 题 5：判断正确 + 预防胜于检查 + 不可妥协/可妥协分类 + 黄金法则（COQ）。

## 记忆口诀
**质量管理三过程口诀**：
规划质量管理，输出计划指标；管理质量 QA，过程审计预防；控制质量 QC，产品检验核实。

**七种基本质量工具口诀**：
因果流程核对单，帕累直方控制散；前因对策后展布，因果查根散点关联。

**七工具分类口诀**：
分析原因三工具：因果图+流程图+核对单（找问题）。
展示结果三工具：直方图+帕累托图+控制图（看分布）。
寻找关联一工具：散点图（验相关）。

**质量成本三类口诀**：
预防成本投培训，评估成本测与检；失败成本内部返，外部索赔代价高。
预防 < 评估 < 失败，加大预防最划算。

**QA vs QC 区别口诀**：
QA 管过程对不对，QC 管产品好不好；QA 审计找根因，QC 检验判合格。

**ISO/IEC 25010 八大特性口诀**：
功能性能兼容三，易用可靠安全强；可维护性可移植，八大特性要记详。

**预防胜于检查口诀**：
计划阶段定标准，执行阶段勤审计；检查阶段明偏差，预防投入省成本。
外部失败十倍贵，内部返工可承受。

**控制图判稳口诀**：
上下控制界限内，过程受控无异常；超出界限有偏差，七点同侧也异常。
样本特征八九随，规则判定见图样。

**质量与进度冲突口诀**：
安全合规不可让，质量底线须守牢；非核体验可妥协，变更控制 CCB 调。
预防成本最便宜，失败代价十倍高。
