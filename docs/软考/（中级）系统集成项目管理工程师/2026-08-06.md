## 今日核心概念
### 1. 项目沟通管理
定义：在项目全生命周期内，对沟通活动进行规划、收集、生成、分发、储存、检索、管理、控制、监督和处置的过程，确保信息及时适当地生成、收集、分发和储存。
关键要点：
- 沟通模型：编码-发送-解码-反馈-噪声五要素，沟通是双向闭环
- 沟通方式：书面、口头、非语言、正式、非正式、垂直、水平、官方、非官方
- 沟通渠道数：n(n-1)/2，5人项目10条、10人项目45条，渠道数随团队规模平方增长
- 沟通方式选择：交互式(会议/电话)、推式(邮件/报告)、拉式(网盘/知识库)
- 沟通渠道数公式：潜在渠道=n(n-1)/2，团队人数增加渠道数爆炸性增长
- 沟通模型要素：编码(发送方把思想转化为语言)、信息(编码结果)、解码(接收方翻译信息)、噪声(干扰)、反馈
- 推式沟通：发给特定接收方，但不确认收到(信件/邮件/报告)
- 拉式沟通：接收方主动获取，适用于大量信息或不同受众(网盘/内网/知识库)
- 互动式沟通：多方交换信息，效率最高(会议/电话/视频)
- 沟通技能：写作、演讲、倾听、跨文化沟通、情商、冲突管理
- 沟通管理计划：信息收集、分发格式、发布时间、信息负责人、接收方、传递方式
- 会议管理：会前准备(议程)、会中控制(时间)、会后跟进(纪要)、会议分类(决策/问题解决/信息分享)

### 2. 项目风险管理
定义：对项目可能遇到的风险进行规划识别、分析、应对和监控的过程，是降低不确定性、提高项目成功率的关键知识领域。
关键要点：
- 风险六过程：规划风险管理、识别风险、定性风险分析、定量风险分析、规划风险应对、监控风险
- 风险分类：已知未知(应急储备应对)、未知未知(管理储备应对)、业务/项目/产品风险、正向/负向风险
- 定性分析：概率-影响矩阵、风险数据质量评估、风险分类、紧迫性评估
- 定量分析：蒙特卡洛模拟、决策树分析、敏感性分析、PERT三点估算
- 风险应对策略(威胁)：规避(Eliminate)、转移(Transfer)、减轻(Mitigate)、接受(Accept)、开拓(Escalate)
- 风险应对策略(机会)：开拓(Exploit)、分享(Share)、提高(Enhance)、接受(Accept)
- 风险责任人：威胁事件分配给最有影响力的人，机会分配给最能把握机会的人
- 风险登记册：记录已识别风险、潜在应对、责任人、风险等级、应对措施
- 风险再评估：监控阶段定期复盘，识别新风险，关闭已发生风险

### 3. 项目干系人管理
定义：对干系人进行分析、规划、识别、管理需求期望与参与程度，调动干系人参与项目决策与执行的全过程。
关键要点：
- 干系人分类：内部(项目团队/管理层/发起人)与外部(客户/供应商/监管/公众)
- 干系人分析：权力/利益矩阵、权力/影响矩阵、影响/作用矩阵、凸显性模型
- 干系人参与级别：不了解、抵制、中立、支持、领先(由低到高)
- 干系人参与矩阵：当前参与度与期望参与度对比，识别差距制定策略
- 干系人管理策略：不知晓权高时满足利益，不知晓利益高时特别关注
- 干系人登记册：身份信息、评估信息、干系人分类(核心/次要/边缘)
- 干系人期望管理：不要过度承诺、明确沟通、持续关注期望变化
- 干系人参与：及时提供信息、咨询关键决策、邀请参与评审
- 隐性干系人识别：合同方员工、家属、竞争对手、媒体记者等

### 4. 项目变更管理
定义：对项目基准(范围、进度、成本、质量等)发生的变更进行识别、评估、审批、实施、确认的全过程，是项目基线控制的核心机制。
关键要点：
- 变更触发：需求变化、技术问题、外部事件、错误识别、产品改进
- 变更控制委员会(CCB)：评审批准变更的决策机构，成员由干系人代表组成
- 变更控制六步法：识别变更→提交变更请求→评估变更影响(影响分析)→CCB审批→实施变更→跟踪确认
- 变更请求类型：纠正措施(纠偏)、预防措施(防问题)、缺陷补救(修缺陷)、更新(基线/计划)
- 变更影响分析：范围、进度、成本、质量、资源、风险、收益多维度评估
- 配置管理：配置项识别、版本控制、变更控制、配置审计、基线管理
- 基线管理：功能基线、分配基线、产品基线，基线变更需走变更流程
- 变更日志：记录所有变更请求及审批状态，便于追溯与审计
- 范围蔓延vs变更：未经控制的额外工作叫范围蔓延，范围变更必须走变更流程
- 变更原则：所有变更必须书面、必须评审、必须记录、必须沟通、必须验证

### 5. 项目绩效度量与报告
定义：通过系统化指标体系对项目执行情况进行定量评估并形成报告的过程，为管理决策提供数据支撑。
关键要点：
- 挣值管理(EVM)：PV/EV/AC/CPI/SPI/CV/SV七大指标，整合范围-进度-成本
- 预测指标：EAC/BAC/ETC/VAC/TCPI五指标，预测完工状态
- 进度绩效指标：SPI、关键路径偏差、里程碑达成率、剩余缓冲
- 成本绩效指标：CPI、成本偏差率、TCPI完工尚需绩效
- 质量绩效：缺陷密度、测试覆盖率、MTTF平均故障时间、可用性
- 风险绩效：风险触发次数、应急储备消耗率、风险登记册更新频次
- 范围绩效：范围完成率、变更请求数、范围蔓延指数
- 报告类型：状态报告(定期)、进度报告(里程碑)、挣值报告(财务)、预测报告(完工)
- 报告原则：客观准确、及时完整、突出重点、问题导向、行动建议
- 仪表盘与可视化：燃尽图、燃起图、挣值曲线、S曲线、风险热图

## 案例分析题
**题目**：
某市级"政务大数据共享交换平台"集成项目，总预算1500万元，工期24个月，项目经理小李负责实施。项目进行到第12个月时发生以下事件：

1. 客户方局长提出新增"跨部门数据核验"模块需求，预计增加工作量80人天，成本约150万元
2. 主要开发人员老张被竞争对手挖走，关键模块代码交接不完整，新接手人员需要3个月才能上手
3. 项目监理发现3份重要技术文档未按配置管理规定走变更流程就修订了
4. 用户单位信息处主任对项目进度不满，认为汇报材料过于专业、问题描述不直观
5. 风险登记册中原标记"中等"的"供应商接口延迟"风险已实际发生，损失工时25天

问题：
1. 变更控制流程应该是什么？局长提出的需求变更应如何处理？
2. 人员流失应采取哪些应对措施？知识管理缺失如何补救？
3. 文档未走变更流程属于什么问题？配置管理应该怎样改进？
4. 干系人沟通方面存在什么问题？应如何改进？
5. 已发生的风险应如何在风险登记册中处理？请简述风险监控过程。

**参考答案**：
1. 变更流程与需求处理：
- 变更控制六步法：识别变更→提交书面变更请求→影响分析(范围/进度/成本/质量/风险)→CCB评审审批→实施变更→跟踪确认
- 局长需求处理：要求客户方提交书面变更请求，组织CCB评审影响(工期延长40天/成本增加150万/质量收益等)
- CCB评估后给出三种选择：批准(调整基线BAC=1650万、工期延长40天)、拒绝(说明理由)、折中(分期实施)
- 无论结果都要书面回复客户方，留痕可追溯，更新范围基准、进度基准、成本基准

2. 人员流失应对：
- 立即启动应急储备，紧急招聘或调用外部资源填补空缺
- 强制知识管理：要求老张完成工作交接清单、代码注释补充、核心逻辑文档化
- 团队建设激励：团队奖金、薪酬调整、关键岗位备份机制(B角)、师徒制
- 风险再评估：识别其他可能流失的关键岗位，提前制定保留计划
- 长期：建立知识库、CodeReview机制、代码规范、技术分享会、团队凝聚力

3. 文档与配置管理问题：
- 性质：违反变更控制流程擅自修订受控文档，属配置管理失控
- 改进措施：
  - 立即冻结相关文档，盘点修订内容并评估影响
  - 配置管理委员会评审修订合规性，必要时回滚
  - 重新宣贯配置管理流程：所有基线变更走CCB+配置管理员
  - 配置项分级：产品基线/功能基线/分配基线三级管理
  - 引入配置管理工具(SVN/Git)、版本号规范、变更日志
  - 定期配置审计与基线检查

4. 干系人沟通改进：
- 问题：汇报内容专业术语多、信息处主任非技术背景理解困难、沟通方式不匹配干系人
- 干系人分析：信息处主任权力中、利益高，应重点关注
- 改进措施：
  - 沟通方式分类：管理层用高层摘要+图表+问题对策，技术层用详细数据
  - 制作可视化报告：进度甘特图、问题鱼骨图、风险热图、里程碑看板
  - 沟通频率调整：信息处主任两周一次汇报，紧急问题随时沟通
  - 沟通模型应用：编码-发送-反馈闭环，确保接收方真正理解
  - 预期管理：避免过度承诺、明确说明风险与决策点

5. 风险监控处理：
- 风险登记册更新：将"供应商接口延迟"标记从"中等"调整为"已发生"，记录实际损失
- 风险审计：复盘风险识别是否及时、应对措施是否到位
- 储备消耗：从应急储备中扣除25天损失工时的成本
- 新风险识别：分析此事件是否引发其他连锁风险
- 风险监控过程：定期风险再评估、储备分析、趋势分析、风险审计、偏差分析
- 经验教训归档：记录"如何识别供应商延迟早期信号"，更新风险识别清单

**踩分要点**：
1. 变更处理必须扣"六步法"，CCB评审和影响分析是核心得分点
2. 人员流失要分"短期应急"和"长期机制"两层答，知识管理是高频考点
3. 配置管理问题要扣"基线"、"变更控制"、"版本控制"、"审计"四大要素
4. 干系人沟通要扣"权力/利益矩阵"和"沟通方式选择"，不要只回答"多沟通"
5. 风险已发生要回答"登记册更新+储备消耗+新风险识别+经验教训"完整闭环

- 沟通三方式：交互(最高效)、推式(单向)、拉式(自助)
- 沟通模型五要素：编码-发送-解码-反馈-噪声
- 风险六过程：规划识别定性定量应对监控
- 风险四应对(威胁)：规避转移减轻接受开拓
- 风险四应对(机会)：开拓分享提高接受
- 风险二分法：已知未知应急储备、未知未知管理储备
- 风险定量三工具：蒙特卡洛、决策树、敏感性分析
- 干系人参与五级：不了解抵制中立支持领先
- 干系人权力利益矩阵：高权力高利益重点管理
- 干系人分类：内部(团队管理层发起人)+外部(客户供应商监管公众)
- 变更控制六步：识别变更-提交请求-影响分析-CCB审批-实施变更-跟踪确认
- 变更请求四类型：纠正预防缺陷补救更新
- 配置管理基线三级：功能基线、分配基线、产品基线
- 范围蔓延vs变更：蔓延无控、变更有流程
- 挣值预测五指标：EAC/BAC/ETC/VAC/TCPI
- 绩效报告原则：客观准确、及时完整、突出重点、问题导向、行动建议
- 沟通规划要素：信息内容、格式、频率、负责人、接收方、传递方式
