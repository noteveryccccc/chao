## 今日核心概念
### 1. 项目质量管理
定义：在项目生命周期内，指挥和控制组织关于质量的相互协调的活动，由质量规划、质量保证、质量控制三个过程构成，贯穿于项目全过程，目的是满足干系人明确的或隐含的质量要求。

关键要点：
1. 三个过程相互作用：质量规划（Plan）输出质量管理计划和度量指标；质量保证（Do）按计划执行并审计过程合规性；质量控制（Check）按度量指标检查产品并识别低质量原因。
2. 质量与等级的区别：质量是满足要求的程度，等级是设计特性差异；低质量是问题，高等级不一定是高质量。
3. 预防胜于检查：将错误消灭在源头比返工成本低得多——检查发现的缺陷1个，返工成本=原始成本+查找成本+修复成本，预防成本远低于此。
4. 质量成本（COQ）四类：预防成本（培训/文件化）、评估成本（测试/检查）、内部失败成本（返工/废品）、外部失败成本（保修/召回）；预防+评估占比越大，总COQ越低。
5. 七种质量工具：因果图、流程图、核查表、帕累托图、直方图、控制图、散点图，前四用于找原因，后三用于查分布和变差。

### 2. 质量保证与质量控制
定义：质量保证（QA）是按质量计划系统性地审计过程与活动，让团队对满足相关标准的信心增强，关注过程；质量控制（QC）是按度量指标监督并记录质量执行结果，识别低质量原因并消除，关注产品。

关键要点：
1. 两者关系：QA为过程提供信心，QC为产品提供信心；QA贯穿项目全周期，QC针对具体可交付成果；QA属于"做对的事"，QC属于"做对的事是否被正确执行"。
2. 七项质量保证活动：通用质量规划方法的恰当应用、产品和过程的质量审计、过程改进的审核、批准的变更请求实施情况审核、变更控制的执行情况、变更控制的完整性测量、变更控制与配置管理系统集成情况。
3. 质量控制七种工具：老七工具（流程图、因果图、帕累托图、控制图、直方图、散点图、核查表）用于发现过程问题，新七工具（亲和图、关联图、树形图、矩阵图、优先级矩阵图、过程决策程序图、活动网络图）多用于收集整理信息。
4. 质量控制产出：质量控制测量结果（确定可交付成果正确性/合规性/适用性的可测量结果）、确认的变更（已批准并实施的缺陷修复）、确认的可交付成果（经测试验收满足质量要求的成果）、核实的可交付成果（产品描述+偏差说明+验收依据）。

### 3. 控制图与帕累托图
定义：控制图（Control Chart）是按时间顺序排列的、反映过程在稳定状态下波动的折线图，由中心线（CL）、控制上限（UCL）、控制下限（LCL）三条横线构成，用于判断过程是否处于统计受控状态；帕累托图是按频率降序排列的直方图，基于二八原理区分关键少数与次要多数。

关键要点：
1. 控制图七要素：上控制限UCL、控制中线CL、下控制限LCL、过程点位置、时序、数据点、特殊原因变差与普通原因变差，UCL/CL/LCL计算基于±3σ控制限规则。
2. 控制图两类变差：普通原因变差（系统固有、可预测、过程受控）需要变更过程管理方法；特殊原因变差（非随机、外来干扰、过程失控）需识别并消除。
3. 七点法则：连续7个点在中心线同一侧，或连续7个点呈上升/下降趋势，判为异常模式，提示非随机性、过程出现系统偏移。
4. 帕累托图分类80/20：80%的问题由20%的重要原因引起——A类（0~80%累计频率，关键少数）B类（80%~90%）C类（90%~100%，次要多数），管理者集中资源处理A类。
5. 控制图用于监控过程稳定性，帕累托图用于聚焦少数关键问题——两者配合是先稳定过程，再消灭主要矛盾。

### 4. 项目质量管理的过程对应
定义：质量管理与项目其它九大知识领域相互交融，通过规划阶段、质量、执行阶段、监控阶段的过程组，与范围、时间、成本、风险、采购、人力资源等知识领域形成统一的项目管理体系统一治理质量。

关键要点：
1. 启动阶段：项目章程输入项目产品描述（描述特性但不描述需求）；干系人登记册初步识别质量需求；项目经理必须在规划阶段覆盖质量管理。
2. 规划阶段：质量规划过程输出质量管理计划、过程改进计划、质量测量指标；与范围管理形成WBS可交付成果验收准则、与时间管理形成质量检查里程碑、与采购管理形成供方质量协议。
3. 执行阶段：质量保证过程按质量管理体系要求执行过程审计和合规检查，与团队建设、人员培训、采购供方管理等并行支撑；项目团队绩效评估要把质量纳入评估指标。
4. 监控阶段：质量控制过程通过七种质量工具识别质量差距和缺陷，提出变更请求（修复/预防/纠正），与整体变更控制、风险监控、绩效审查并行治理。
5. 收尾阶段：质量报告作为项目收尾过程输出存档，干系人对最终成果验收，经验教训登记册更新质量相关教训——为后续项目历史经验提供依据。

### 5. 质量管理成熟度与持续改进
定义：组织质量管理体系从传统质量控制（QC）→质量保证（QA）→全面质量管理（TQM）→六西格玛→CMMI分级递进，逐级走向系统化、过程化、数据驱动化，本质是戴明PDCA循环与朱兰质量三部曲的持续演化。

关键要点：
1. 戴明PDCA循环：Plan（计划，分析现状找问题原因）→Do（执行，实施计划）→Check（检查，对比结果找差距）→Act（处理，标准化成功经验和未解决问题）；循环每转一圈质量提升一级。
2. 朱兰质量三部曲：质量规划（设定质量目标+识别客户需求+研发产品功能）→质量控制（评估实际绩效+比较绩效差异+采取纠正措施）→质量改进（建立质量基础设施+确立改进项目+组建项目团队+供应培训资源）。
3. 戴明七点原则：以客户为中心、领导参与、持续改进、全员参与、以过程方法管理、系统管理、以事实决策。
4. CMMI五级：初始级（混乱）→可重复级（项目管理有纪律）→已定义级（过程标准化）→定量管理级（数据度量）→优化级（持续优化）；集成系统项目招标常要求CMMI3或CMMI5资质。
5. 全面质量管理（TQM）核心：全员、全过程、全方位；三全一多样（多方法：戴明环、朱兰、统计技术、老七新七工具）。

## 案例分析题
**题目**：
A公司承接某市政务数据治理平台项目，预算800万元，工期10个月。项目验收标准包括：数据准确率≥99.5%、接口响应时间≤2秒、系统可用性≥99.9%。

项目进行到第6个月时开展了全面质量审计，发现以下问题：
（1）开发组未按质量管理计划要求提交单元测试用例，按计划应完成300个用例，实际只提交150个；
（2）性能测试组在接口响应时间测试中发现的3个超标接口未走变更控制流程，已被擅自优化部署到生产环境；
（3）客户要求引入新数据源（医保数据），原计划中无此工作内容，开发经理口头同意已开始改造，未更新WBS和质量管理计划。

问题：
1. 质量保证与质量控制的区别是什么？结合本案，简述质量保证应发挥的作用。
2. 本案中发现的问题分别属于预防成本、评估成本、内部失败成本、外部失败成本哪一类？请说明理由。
3. 针对问题（2），开发组的做法违反了变更控制流程。请说明正确的变更控制流程及本案的纠偏步骤。
4. 针对问题（3），试分析项目经理在范围管理和质量管理方面存在哪些不足，并提出改进建议。

**参考答案**：
1. 质量保证（QA）与质量控制（QC）的区别：QA关注过程，按质量管理体系系统性地审计过程和活动，让团队对满足标准的信心增强；QC关注产品，按度量指标监督并记录质量执行结果，识别低质量原因并消除。本案中质量保证应发挥的作用：
   ①按质量管理计划定期审计单元测试执行情况，发现用例缺失及时纠正，不应等到第6个月才暴露；
   ②审计变更控制流程合规性，确保任何已部署变更都经过整体变更控制评审；
   ③审计WBS和质量管理计划更新情况，确保新增工作纳入受控范围；
   ④审计过程改进的执行情况，识别反复出现问题的根本原因并入经验教训库。
2. 问题类别划分：
   问题（1）属于评估成本中的预防控制不足——测试用例属于发现缺陷的评估活动，不交付用例就减少评估投入，本质是评估成本节省（错误地把评估成本当节约）；
   问题（2）属于内部失败成本——接口响应时间超标且未经授权擅自部署，可能引发生产事故；但因变更已部署未发现生产事故，按潜在风险定性为内部失败成本；若投产后发现客户损失则为外部失败成本；
   问题（3）属于预防成本（极端不足）——不按变更流程扩大范围是典型的预防体系崩溃，可能导致的返工、返修、客户投诉将转化为内部失败成本和外部失败成本；
   此外项目未来若因数据准确性不达标被验收驳回，则按外部失败成本（保修/返工责任）由公司承担。
3. 正确变更控制流程及纠偏：
   正确流程：变更请求提交→变更影响分析（范围/进度/成本/质量/风险）→CCB综合评审→批准/拒绝→实施变更→确认缺陷修复→更新项目管理计划。
   本案纠偏步骤：
   ①立即停用此3个接口的优化部署（rollback）；
   ②由变更控制委员会（CCB）评估变更影响（性能改善幅度、回归测试覆盖度）；
   ③回到原版本，补充完整变更请求单，包含变更描述、影响分析、回归测试方案；
   ④获批准后实施变更，并执行质量控制测试（回归测试、性能测试）；
   ⑤更新配置管理记录、版本管理记录、质量管理计划；
   ⑥记录经验教训，纳入质量保证审计清单。
4. 项目经理不足及改进建议：
   范围管理不足：
   ①没有按需求变更管理流程规范进行范围变更确认——医保数据源应通过客户正式书面变更请求引入；
   ②没有更新WBS（可交付成果）和范围基准；
   ③没有更新项目管理计划和子计划。
   质量管理不足：
   ①没有定期审计质量管理计划的执行情况，6个月才发现问题为时过晚；
   ②没有识别客户隐含的质量需求（医保数据源可能影响数据准确率标准）；
   ③没有把质量保证过程作为日常工作，由QA团队按周/月度审计关键过程；
   ④没有实施质量控制测量指标（单元测试用例通过率、变更请求合规率）的持续监控。
   改进建议：
   ①严格执行整体变更控制流程，所有变更必须通过书面申请、影响分析、CCB评审、批准实施四个步骤；
   ②建立每周QA审计机制，覆盖单元测试、集成测试、性能测试、变更合规性等关键过程；
   ③重新确认范围基准，将医保数据源纳入WBS，评估对成本/进度/质量的影响，必要时申请变更；
   ④建立质量测量指标看板：单元测试用例完成率、变更请求合规率、缺陷逃逸率等实时监控；
   ⑤更新质量管理计划，加入新数据源的质量验收准则（数据准确率、接口响应时间、数据完整性）；
   ⑥组织团队进行质量管理培训，强化QA过程意识和变更流程合规性；
   ⑦提交经验教训并复盘根因，避免重复发生。

**踩分要点**：
1. 答1题必须分点说明QA与QC的"过程vs产品"区别，并按本案具体问题给出QA应发挥的4个审计场景。常见漏点：只写定义未结合本案审计场景。
2. 答2题必须对每个问题给出成本类别判断及理由，不能直接给结论。易错点：把"未经授权变更"定性为预防成本——变更合规性属预防控制；擅自部署的生产风险属内部失败成本。
3. 答3题必须按完整变更控制流程（6步或更多）作答，并明确"先停后退再变更"的纠偏顺序。漏点：只写纠正步骤不写回退（rollback）步骤。
4. 答4题必须分范围管理+质量管理两块写不足+建议，建议必须对应不足，不能虚泛而谈。常见漏点：忘记写"更新质量管理计划加入新数据源验收准则"。

## 记忆口诀
质量三过程：规保控（质量规划、质量保证、质量控制）—— 规划是定标准，QA是保过程，QC是测产品。
预防胜检查：检1返=1+查找+修复，预防便宜一百倍—— 越是上游发现问题代价越小。
七点法则：7点连同侧或7点连升降，过程必偏移—— 7是个魔法数字。
80/20原则：80%问题20%原因，找A类下手—— 帕累托图聚焦关键少数。
戴明PDCA：P计划D执行C检查A处理—— 每转一圈质量升一级。
朱兰三部曲：规控改——先规划目标再控制实绩再持续改进—— 缺一不可。
CMMI五级：初重定量优——初始级→可重复级→已定义级→定量管理级→优化级。
三全一多样：三全TQM（全员、全过程、全方位）+多样方法（戴明、朱兰、老七新七）。
COQ四成本：预评内外——预防成本、评估成本、内部失败成本、外部失败成本——前后两头投入越多，越省中间失败成本。
新老七工具：老七找问题（因果流核帕直控散）、新七理信息（亲关树矩优过活）。
变更六步法：提评批施验结——变更请求、影响分析、CCB评审、批准实施、确认验证、收尾关闭。
