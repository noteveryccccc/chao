# （中级）系统集成项目管理工程师 · 2026-08-07

## 今日核心概念

### 1. 项目整合管理七过程与项目章程

**定义**：项目整合管理是对项目管理各知识领域的过程和活动进行识别、定义、组合、统一与协调的过程，是项目经理专属的、不可授权的核心职责。它贯穿五大过程组，负责在相互竞争的目标与方案之间做出权衡取舍。

**关键要点**：

1）**七个过程及其所属过程组**（务必背准归属，选择题高频）

| 序号 | 过程 | 过程组 | 核心输出 |
|------|------|--------|----------|
| 1 | 制定项目章程 | 启动 | 项目章程、假设日志 |
| 2 | 制订项目管理计划 | 规划 | 项目管理计划 |
| 3 | 指导与管理项目工作 | 执行 | 可交付成果、工作绩效数据、变更请求、问题日志 |
| 4 | 管理项目知识 | 执行 | 经验教训登记册、组织过程资产更新 |
| 5 | 监控项目工作 | 监控 | 工作绩效报告、变更请求 |
| 6 | 实施整体变更控制 | 监控 | 批准的变更请求、变更日志 |
| 7 | 结束项目或阶段 | 收尾 | 最终产品/服务/成果移交、最终报告、OPA更新 |

2）**项目章程的本质**
- 由**项目发起人（或项目集/PMO/组织外部机构）签发**，而非项目经理编写签发；项目经理可参与编写，但无权批准。
- 章程的作用：**正式批准项目立项**、**授权项目经理动用组织资源**、把项目与组织战略目标挂钩。
- 章程一经批准即为**基准性文件**，项目经理的权力来源于章程。
- **项目章程不可外包**给承建方编写（考试陷阱：让供应商代写章程属错误做法）。

3）**项目章程的典型内容**（案例简答常考）
项目目的或立项理由 / 可测量的项目目标及成功标准 / 高层级需求 / 高层级项目描述与边界定义 / 整体风险 / 总体里程碑进度计划 / 预先批准的财务资源 / 关键干系人清单 / 项目审批要求（什么是成功、谁决定、谁签字）/ 项目退出标准 / 委派的项目经理及其职责和职权 / 发起人姓名和职权。

4）**项目章程 vs 项目管理计划 vs 合同 vs SOW**
- 项目章程：**为什么做、做什么**（高层级、粗粒度、一般不变更）。
- 项目管理计划：**怎么做**（含各子计划与三大基准，需经CCB审批后才能变更）。
- 工作说明书SOW：对项目所需交付的产品/服务的**叙述性说明**，是章程的输入之一。
- 合同：外部项目情形下，合同是制定项目章程的**输入**。

5）**制定项目章程的输入/工具**
- 输入：立项管理文件（商业论证、效益管理计划）、协议（合同）、事业环境因素EEF、组织过程资产OPA。
- 工具：专家判断、数据收集（头脑风暴、焦点小组、访谈）、人际关系与团队技能（冲突管理、引导、会议管理）、会议。

### 2. 项目知识管理（显性知识与隐性知识）

**定义**：管理项目知识是使用已有知识并生成新知识，以实现项目目标并帮助组织学习的过程。其关键价值在于把**个人经验转化为组织资产**，避免"人走知识走"。

**关键要点**：

1）**两类知识的对比**（选择题高频）

| 维度 | 显性知识（Explicit） | 隐性知识（Tacit） |
|------|---------------------|------------------|
| 特征 | 可用文字、图片、数字编码 | 个人化、经验性、难以表达 |
| 举例 | 文档、手册、数据库、规程 | 经验、洞察、诀窍、直觉、信念 |
| 传递难点 | 易复制传播，但**缺乏语境易被误解** | 难以固化，需要**建立信任与互动** |
| 主要手段 | 知识库、文档管理、编码归档 | 社交网络、导师制、结对工作、实践社区、非正式交流 |

2）**知识管理的核心工具与技术**
- **知识管理工具**：人际交往、实践社区（CoP）、会议、工作跟班（Shadowing）与反向跟班、讨论会、研讨会、讲故事、创意会议、焦点小组、知识展会与咖啡屋、培训。
- **信息管理工具**：经验教训登记册、图书馆服务、信息收集（网络搜索、文献综述）、项目管理信息系统PMIS。
- **人际关系与团队技能**：积极倾听、引导、领导力、人际交往、政治意识。

3）**经验教训登记册 vs 经验教训知识库**
- **经验教训登记册**：项目**早期**创建，项目**期间持续更新**，属于项目文件。
- **经验教训知识库**：项目或阶段**结束时**，把登记册内容转移进组织级知识库，属于**组织过程资产（OPA）**。
- 考试陷阱：登记册不是收尾时才写的，而是项目一开始就建、全程滚动更新。

4）**知识管理失败的典型表现**（案例题识别点）
只有文档没有归档制度 / 只在项目末期做总结 / 核心人员离职无交接 / 隐性经验无人传承 / 各项目组重复踩坑 / 知识库无人维护更新。

### 3. 招投标法核心时限与法定情形

**定义**：《中华人民共和国招标投标法》及其实施条例是系统集成项目立项与采购阶段的法定依据，考试以**具体天数、人数、比例**为主要考点。

**关键要点**：

1）**必背数字表**（每年必考，务必逐条记牢）

| 事项 | 法定要求 |
|------|----------|
| 招标文件发出至投标截止 | 依法必须招标的项目，**不得少于20日** |
| 邀请招标邀请对象 | 向**3个以上**具备相应能力的特定法人或组织发出邀请书 |
| 投标人数量 | 投标人**少于3个**的，招标人应当**重新招标** |
| 评标委员会组成 | **5人以上单数**，其中技术、经济等方面专家**不得少于成员总数的2/3** |
| 开标时间 | 在投标文件提交截止时间的**同一时间**公开进行 |
| 开标地点 | 招标文件中预先确定的地点 |
| 中标通知书后签合同 | 中标通知书发出之日起**30日内**订立书面合同 |
| 招投标情况书面报告 | 中标通知书发出之日起**15日内**向行政监督部门提交 |
| 投标保证金 | 不超过招标项目估算价的**2%**，且最高不超过**80万元** |
| 履约保证金 | 不超过中标合同金额的**10%** |
| 中标候选人公示期 | 不得少于**3日** |
| 对招标文件异议 | 投标截止时间**10日前**提出，招标人3日内答复 |
| 对开标异议 | **开标现场**提出，招标人当场答复并记录 |
| 对评标结果异议 | **中标候选人公示期间**提出，招标人3日内答复 |
| 投诉时限 | 知道或应当知道之日起**10日内**向行政监督部门投诉 |

2）**必须招标的范围**
大型基础设施、公用事业等关系社会公共利益、公众安全的项目；全部或部分使用国有资金投资或国家融资的项目；使用国际组织或外国政府贷款、援助资金的项目。达到规模标准的**勘察、设计、施工、监理以及与工程建设有关的重要设备、材料采购**。

3）**可以不进行招标（可直接发包）的情形**
涉及国家安全、国家秘密、抢险救灾；需要采用不可替代的专利或专有技术；采购人依法能够自行建设/生产/提供；已通过招标方式选定的特许经营项目投资人依法能够自行建设；需要向原中标人采购工程、货物或服务，否则将影响施工或功能配套要求；国家规定的其他特殊情形。

4）**招投标中的违法行为识别**（案例题判断点）
- 招标人**泄露标底**、泄露潜在投标人名称数量。
- 以**不合理条件限制或排斥**潜在投标人（如指定特定品牌、设置与项目无关的资质门槛、以特定行政区域业绩作条件）。
- 投标人**相互串通投标**、与招标人串通投标。
- 以**他人名义投标**（挂靠）、以低于成本的报价竞标。
- 中标人**转让中标项目**，或将中标项目肢解后分别转让；将中标项目的**主体、关键性工作分包**。
- 中标后与招标人**另行订立背离合同实质性内容的协议**（阴阳合同）。
- **必须招标的项目化整为零**或以其他方式规避招标。

5）**政府采购的差异点**（易混淆）
- 采购方式：公开招标、邀请招标、竞争性谈判、**竞争性磋商**、单一来源采购、询价，以及国务院政府采购监督管理部门认定的其他方式。**公开招标是主要采购方式**。
- 质疑与投诉：供应商应在知道或应知其权益受损之日起**7个工作日内**提出质疑，采购人在收到后**7个工作日内**答复；对答复不满的，可在答复期满后**15个工作日内**向同级财政部门投诉。
- 政府采购合同适用《民法典》；采购人与中标供应商应在中标通知书发出之日起**30日内**签订合同。

### 4. 合同管理与违约责任

**定义**：合同是平等主体之间设立、变更、终止民事法律关系的协议。系统集成项目中合同是约束甲乙双方权利义务、界定风险分担、处理争议的根本依据。

**关键要点**：

1）**合同的法定必备条款**
当事人名称/住所、标的、数量、质量、价款或报酬、履行期限地点和方式、违约责任、解决争议的方法。

2）**信息系统工程合同的特殊约定项**（案例常考"合同缺陷"）
项目范围与验收标准 / 知识产权归属 / 源代码与技术文档交付 / 保密条款 / 变更处理机制与计价方式 / 付款节点与比例 / 质保期与运维责任 / 人员配置及更换限制 / 不可抗力 / 争议解决方式（协商、调解、仲裁、诉讼）。

3）**违约责任的四种承担方式**
继续履行、采取补救措施、赔偿损失、支付违约金（或定金罚则）。
- **违约金过高**：约定违约金过分高于造成损失的，当事人可请求法院或仲裁机构**适当减少**（司法实践一般以超过损失30%为"过分高于"）；过低的可请求增加。
- **定金**：定金数额不得超过主合同标的额的**20%**；违约方为给付定金一方则不得请求返还，收受定金一方违约则**双倍返还**。
- **定金与违约金不能并用**，只能择一主张。

4）**合同变更与索赔**
- 合同变更须经**双方协商一致并书面确认**，口头变更不具约束力；变更内容约定不明的，推定为**未变更**。
- 索赔程序：**索赔事件发生 → 28天内发出索赔意向通知 → 28天内提交索赔报告及资料 → 监理/发包方审核答复 → 索赔认可或谈判 → 争议解决**。
- 索赔的成立条件：与合同对照事件已造成实际损失、**属于非索赔方责任**、索赔按合同规定程序和时限提交。

5）**争议解决四途径的效力**
协商 → 调解 → 仲裁 → 诉讼。**仲裁实行一裁终局**，且**仲裁与诉讼只能择一**（有效仲裁协议排除法院管辖）。

6）**合同收尾与合同管理档案**
合同收尾包括：产品核实、行政收尾、合同档案归档、更新经验教训。**提前终止合同**是合同收尾的一种特殊情况。

### 5. 信息安全管理与网络安全等级保护2.0

**定义**：信息安全管理是通过技术与管理手段，保障信息系统的保密性、完整性、可用性，并满足国家法律法规合规要求的持续过程。等级保护制度是我国网络安全的基本国策与法定要求。

**关键要点**：

1）**信息安全五要素**
- **保密性（Confidentiality）**：信息不被未授权者获知 → 加密、访问控制、脱敏。
- **完整性（Integrity）**：信息未被非授权篡改 → 哈希校验、数字签名、数据库约束。
- **可用性（Availability）**：授权用户在需要时可正常访问 → 冗余、备份、负载均衡、容灾。
- **真实性/可认证性**：确认主体身份真实 → 身份认证、CA证书。
- **不可抵赖性（不可否认性）**：行为不可否认 → **数字签名 + 时间戳 + 审计日志**。

2）**等保2.0五个安全保护等级**

| 等级 | 名称 | 受侵害客体与危害程度 |
|------|------|---------------------|
| 一级 | 用户自主保护级 | 损害公民、法人合法权益，不损害国家安全、社会秩序 |
| 二级 | 系统审计保护级 | 严重损害公民法人权益，或损害社会秩序和公共利益 |
| 三级 | 安全标记保护级 | 严重损害社会秩序和公共利益，或损害国家安全 |
| 四级 | 结构化保护级 | 特别严重损害社会秩序公共利益，或严重损害国家安全 |
| 五级 | 访问验证保护级 | 特别严重损害国家安全 |

- 一般政务外网业务系统定**三级**；涉及重要民生、公共服务的定**三级及以上**。
- **三级及以上系统每年至少测评一次**，二级系统按行业主管要求执行。

3）**等保实施五个环节**（顺序题必考）
**定级 → 备案 → 建设整改 → 等级测评 → 监督检查**
- 定级：由运营使用单位自主定级，经专家评审、主管部门审核。
- 备案：**三级以上系统在30日内**到当地公安机关网安部门备案。

4）**等保2.0技术要求："一个中心，三重防护"**
- 安全管理中心（统一管理、审计、运维的中心）
- 三重防护：**安全通信网络 + 安全区域边界 + 安全计算环境**
- 再加**安全物理环境**，共构成五大技术层面。

5）**等保2.0管理要求五方面**
安全管理制度 / 安全管理机构 / 安全管理人员 / 安全建设管理 / 安全运维管理。

6）**安全扩展要求**（2.0新增，区别于1.0的关键）
云计算安全扩展、移动互联安全扩展、物联网安全扩展、工业控制系统安全扩展、**大数据安全扩展**。

7）**灾备关键指标**
- **RTO（恢复时间目标）**：业务中断后恢复所需的**时间**上限。
- **RPO（恢复点目标）**：可容忍丢失的**数据量**（时间跨度）。
- 灾备等级由低到高：基本支持 → 备用场地支持 → 电子传输和部分设备支持 → 电子传输及完整设备支持 → 实时数据传输及完整设备支持 → **数据零丢失和远程集群支持**（第6级）。

## 案例分析题

**题目**：

某市人力资源和社会保障局拟建设"市级人才服务一体化平台"，项目总预算 2800 万元，全部使用财政资金，建设周期 18 个月。平台需汇聚全市人才落户、职称评审、人才补贴发放、企业用工需求等业务数据，并与市政务云、公安人口库、社保库对接，最终面向社会公众提供在线申报与查询服务。

项目实施过程中出现以下情况：

（1）为赶在市里"人才周"活动前上线，局办公室将项目拆分为"平台开发"（1400 万）、"数据治理"（900 万）、"运维服务"（500 万）三个包，其中"数据治理"包以"技术特殊、时间紧迫"为由采用单一来源方式直接委托给上一年度合作过的 A 公司。

（2）"平台开发"包公开招标。招标公告于 3 月 1 日发布，招标文件同日发出，规定投标截止时间为 3 月 16 日。招标文件中要求"投标人须具有本市人才服务类系统建设业绩不少于 2 项"。开标时共有 B、C、D 三家单位投标，评标委员会由 4 人组成，其中招标人代表 2 人、技术专家 2 人。B 公司中标，中标通知书于 3 月 25 日发出，双方于 5 月 10 日签订合同。

（3）合同签订后，B 公司项目经理小张组建团队进场。合同中仅约定"按用户需求完成平台建设，验收合格后付款"，未对需求范围、验收标准、知识产权归属、源代码交付作具体约定。开发过程中，局业务处室陆续提出补贴测算规则调整、增加人才码扫码核验、对接省级人才库等 20 余项新要求，小张认为都是"用户需求"，全部安排开发，未走任何书面流程。项目进行到第 12 个月时，进度滞后约 3 个月，成本已使用预算的 85%。

（4）第 13 个月，小张与两名核心开发人员因个人原因先后离职。接手的项目经理发现：需求变更没有任何记录，设计文档停留在项目初期版本，多处业务规则只存在于离职人员的记忆和个人电脑中，团队需花大量时间重新梳理。

（5）第 15 个月平台试运行期间，安全测评机构进场，指出平台承载人才身份证号、学历、薪酬等大量敏感个人信息，但至今未开展等级保护定级备案工作，且未部署日志审计与数据脱敏措施。项目组回复"等上线稳定后再补做"。

**问题**：
1. 指出本项目在采购与招投标环节存在的问题，并说明理由。
2. 指出本项目在合同管理与变更管理方面存在的问题，并给出改进措施。
3. 结合项目知识管理，分析第（4）项情况暴露的问题及应采取的措施。
4. 针对第（5）项情况，说明该平台应如何开展信息安全等级保护工作。

**参考答案**：

**问题 1：采购与招投标环节的问题**

（1）**化整为零规避招标**。项目总预算 2800 万元全部使用财政资金，属依法必须招标项目。将项目人为拆分为三个包，使"数据治理"包脱离公开招标，属于《招标投标法实施条例》明令禁止的"将必须招标的项目化整为零或者以其他任何方式规避招标"。

（2）**单一来源采购适用理由不成立**。"时间紧迫"不是法定的单一来源情形；单一来源仅适用于只能从唯一供应商处采购、发生不可预见紧急情况、或为保证一致性需继续从原供应商添购（且添购金额不超过原合同金额10%）等情形。"上一年度合作过"更不构成合法理由，且未履行专家论证与公示程序。

（3）**招标文件发出至投标截止时间不足 20 日**。3 月 1 日发出、3 月 16 日截止仅 15 日，违反《招标投标法》"依法必须招标项目自招标文件发出之日起至投标截止之日止最短不得少于二十日"的规定。

（4）**以不合理条件限制、排斥潜在投标人**。要求"本市人才服务类系统建设业绩"，以特定行政区域业绩作为资格条件，属于对潜在投标人的差别待遇和歧视待遇。

（5）**评标委员会组成不合法**。评标委员会应为 5 人以上单数，且技术经济专家不得少于成员总数的三分之二。本项目 4 人为偶数且专家仅占二分之一，双重违法。

（6）**超期签订合同**。中标通知书 3 月 25 日发出，应在 30 日内即 4 月 24 日前签订书面合同，实际 5 月 10 日签订，超期。

（7）（补充）**未在中标通知书发出之日起 15 日内向行政监督部门提交招投标情况书面报告**，案例中未体现该程序。

**问题 2：合同管理与变更管理的问题及改进措施**

存在的问题：
- 合同条款**严重缺失**：未约定项目范围与可交付成果清单、未约定验收标准与验收流程、未约定知识产权归属、未约定源代码与技术文档交付、未约定变更处理机制与计价方式、未约定分期付款节点、未约定违约责任与质保期。
- **"按用户需求完成建设"属于范围约定不明**，为后续范围蔓延埋下根因。
- 项目经理**未建立变更控制流程**，20 余项新增需求全部无书面申请、无影响分析、无 CCB 审批，属典型的**镀金与范围蔓延（Scope Creep）**。
- 变更未评估对**进度、成本、质量、风险的综合影响**，也未相应调整范围基准、进度基准和成本基准，导致进度滞后 3 个月、成本超支风险已现（85% 预算对应约 67% 工期）。
- **无变更日志、无需求跟踪矩阵**，变更不可追溯。

改进措施：
- 立即**补充签订合同补充协议**，明确范围边界、验收标准、知识产权、文档与源代码交付、变更计价规则。
- 建立**变更控制委员会（CCB）**，明确成员构成与审批权限分级。
- 严格执行**整体变更控制流程**：提出变更申请 → 变更影响分析（范围/进度/成本/质量/风险）→ CCB 审批 → 发布实施 → 验证变更效果 → 更新基准与相关文件。
- 建立**需求跟踪矩阵（RTM）**和**变更日志**，实现需求—设计—开发—测试—验收的双向可追溯。
- 对已发生的 20 余项变更**补办书面确认与影响评估**，重新核定范围基准、进度基准与成本基准，必要时向发包方提出工期与费用索赔。
- 加强**范围确认**，每个阶段可交付成果由业务部门书面签字确认。

**问题 3：知识管理暴露的问题及措施**

暴露的问题：
- **项目知识严重依赖个人隐性知识**，业务规则只存在于离职人员的记忆与个人电脑中，未转化为显性知识。
- **配置管理与文档管理失效**：设计文档停留在初期版本，未随变更同步更新，未建立配置基线与版本控制。
- **未建立经验教训登记册**，项目全程无知识沉淀。
- **无人员离职交接机制**，关键岗位无备份人员，形成单点依赖（关键人员风险未识别未应对）。
- 项目资料**存放在个人电脑**而非受控的项目知识库/配置库，存在资产流失与信息安全双重风险。

应采取的措施：
- 建立**统一的项目知识库与配置管理库**，规定所有需求、设计、代码、测试、会议纪要必须入库，禁止个人电脑单独存储项目资产。
- 实施**配置管理**：识别配置项、建立配置基线、变更需经 CCB 审批、定期开展配置审计与配置状态报告，确保文档与代码版本一致。
- **项目初期即创建经验教训登记册并全程滚动更新**，项目收尾时转入组织级经验教训知识库形成组织过程资产。
- 针对隐性知识，采用**结对开发、导师制、工作跟班、实践社区、定期技术分享会**等方式促进知识转移。
- 建立**关键岗位 AB 角制度**与人员离职强制交接清单（代码、文档、账号、未完事项、待办风险），交接经项目经理书面验收后方可离岗。
- 在人力资源计划中识别**关键人员流失风险**，制定应急预案（人才储备池、供应商增派、知识固化优先级）。
- 对已离职人员遗留内容，组织**逆向梳理与业务规则复核**，由业务处室确认后补齐文档。

**问题 4：等级保护工作的开展**

（1）**认识合规刚性**："等上线稳定后再补做"的做法错误。《网络安全法》规定国家实行网络安全等级保护制度，等保工作应与信息系统**同步规划、同步建设、同步运行（三同步）**，不能后补。

（2）**定级**：平台承载全市人才身份证号、学历、薪酬等大量敏感个人信息，面向社会公众提供服务，一旦泄露或中断将严重损害社会秩序和公共利益，应定为**第三级**。由运营使用单位（市人社局）初步定级，组织专家评审，报行业主管部门审核。

（3）**备案**：定级结果确定后，**在 30 日内**到市级公安机关网安部门办理备案手续，提交定级报告等材料，取得备案证明。

（4）**建设整改**：依据 GB/T 22239 三级要求开展差距分析并整改，覆盖"一个中心、三重防护"：
- 安全物理环境：机房门禁、防火防水防雷、电磁防护（依托政务云可继承部分）。
- 安全通信网络：网络架构冗余、通信数据加密传输、带宽保障。
- 安全区域边界：边界访问控制、入侵防范、恶意代码防范、**安全审计（补齐日志审计）**。
- 安全计算环境：身份鉴别（双因素）、访问控制、**数据完整性与保密性（补齐敏感字段加密存储与展示脱敏）**、数据备份恢复、个人信息保护、剩余信息保护。
- 安全管理中心：集中管控、集中审计、集中运维。
- 管理层面同步建立安全管理制度、安全管理机构、人员安全管理、建设与运维管理五方面制度文件。
- 因平台部署于政务云，还须落实**云计算安全扩展要求**，明确云服务商与运营单位的安全责任边界。

（5）**等级测评**：整改完成后委托具备资质的等级测评机构开展测评，**三级系统每年至少测评一次**，测评结论应达到"良好"及以上方可上线。

（6）**监督检查**：配合公安机关的日常监督检查与年度检查，对发现的问题限期整改并复查。

（7）**纳入项目管理**：将等保定级、备案、测评作为项目**里程碑和验收前置条件**写入项目计划与合同验收标准，相应费用纳入项目预算；同时开展个人信息保护影响评估，落实《个人信息保护法》最小必要原则。

**踩分要点**：

**问题 1（招投标）——按"数字+法条"逐条给分，漏一条丢一条**
- 必须点名 **20 日**（15 日不足）、**5 人以上单数**、**专家不少于 2/3**、**30 日签合同**（超期）、**化整为零规避招标**、**以特定区域业绩限制排斥潜在投标人**、**单一来源理由不合法**七个采分点。
- 答题模板固定为"**存在问题 + 违反的具体规定/理由**"两段式，只写"不合规"不写理由不得分。
- 注意"投标人 3 家"本身**合法**（少于 3 家才需重新招标），不要误判，误判反而扣分。

**问题 2（合同与变更）——分"合同缺陷"和"变更失控"两块写**
- 合同缺陷必写：**范围/验收标准/知识产权/源代码与文档/变更机制/付款节点/违约责任**。
- 变更失控必写：**无书面申请、无影响分析、无 CCB 审批、无变更日志、未更新三大基准、范围蔓延与镀金**。
- 改进措施必须落到**整体变更控制六步流程**上，并点出**需求跟踪矩阵**和**范围确认书面签字**。
- 加分项：指出"成本已用 85% 而工期仅过 67%"，用挣值思路点明 **CPI<1、SPI<1，双超支滞后**，说明需重新做完工估算 EAC。

**问题 3（知识管理）——抓住"隐性知识未显性化"这条主线**
- 必写关键词：**隐性知识/显性知识、经验教训登记册（项目初期创建、全程更新、收尾转入组织过程资产）、配置管理与配置基线、关键人员单点风险、AB 角、离职交接清单**。
- 注意区分**经验教训登记册（项目文件）**与**经验教训知识库（OPA）**，写反了不给分。
- 措施必须"制度 + 工具 + 人"三层齐全，只写"加强文档管理"这类空话不得分。

**问题 4（等级保护）——按"五环节 + 一个中心三重防护"的骨架答**
- 五环节顺序不能乱：**定级 → 备案 → 建设整改 → 等级测评 → 监督检查**。
- 数字采分点：**定三级**、**30 日内备案**、**三级系统每年测评一次**。
- 必须点出**"同步规划、同步建设、同步运行"三同步**，直接驳斥"上线后再补"的错误说法。
- 技术措施要对应案例给出的具体缺陷：**日志审计对应"安全区域边界/安全管理中心"，数据脱敏与加密对应"安全计算环境"**，泛泛而谈不给分。
- 加分项：提及**政务云的云计算安全扩展要求与责任边界划分**、**《网络安全法》《个人信息保护法》合规**、**将等保作为验收前置条件并纳入预算**。

**通用踩分纪律**
1. 每问先写"存在问题"再写"原因/措施"，一问一段，**编号分条**，阅卷按点给分。
2. 凡涉及数字的地方**必须写出具体数字**，"时间太短"不得分，"不足 20 日"得分。
3. 措施类回答统一套用"**流程 + 工具 + 制度 + 人员**"四维度，保证覆盖面。
4. 案例中给出的每一个异常细节（4 人评标、5 月 10 日签约、个人电脑存文档、"以后再补做"）都是**故意埋的采分点**，必须逐一回应，不能遗漏。

## 记忆口诀

**1. 整合管理七过程**
> **章 计 导 知 监 变 收**
> （制定**章**程 → 制订**计**划 → 指**导**管理工作 → 管理**知**识 → **监**控工作 → 整体**变**更控制 → 结束**收**尾）
> 补一句：**"章由发起人签，计划才是干活书"**——章程不是项目经理批的。

**2. 项目章程记忆**
> **"目标高层里程碑，钱人风险审批批"**
> （目的、可测量目标、高层需求与描述、里程碑、财务资源、干系人与项目经理授权、审批要求）

**3. 显性隐性知识**
> **"显性靠文档，隐性靠交流；文档易复制，经验要传帮带"**
> 登记册口诀：**"早建、常更、末归档"**——早期建立、全程更新、收尾转 OPA。

**4. 招投标数字串烧（一句话背全）**
> **"二十日出题，三家才开标，五单人评标，三分之二专家；十日前提异议，十五日交报告，三十日签合同；保证金二八十（2%、80万），履约金一成（10%）。"**

**5. 政府采购质疑投诉**
> **"七日质疑七日答，十五日内可投诉"**（均为工作日）

**6. 违约责任四方式**
> **"继 补 赔 违"**（继续履行、补救措施、赔偿损失、违约金）

> **"两个二十八，意向在前报告在后"**（28 天发意向通知，28 天交索赔报告）

> **"保 完 可 真 不"**（保密性、完整性、可用性、真实性、不可抵赖性）

> **"自 指 监 强 专"**

**10. 等保实施五环节**
> **"定 备 建 测 查"**（定级 → 备案 → 建设整改 → 等级测评 → 监督检查）
> 加一句：**"三级三十日备案，每年一测不能省"**

**11. 等保2.0技术骨架**
> **"一个中心，三重防护"**
> 中心 = 安全管理中心；三重 = **通信网络、区域边界、计算环境**；外加安全物理环境。
> 扩展要求：**"云 移 物 工 大"**（云计算、移动互联、物联网、工业控制、大数据）。

**12. 灾备指标**
> **"RTO 看时间，RPO 看数据"**——T 是 Time（多久恢复），P 是 Point（丢多少）。

**13. 三同步铁律**
> **"同步规划、同步建设、同步运行"**——凡案例中出现"等以后再补安全措施"，一律以此驳斥。
