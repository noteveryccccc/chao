# （中级）系统集成项目管理工程师 · 2026-08-12

## 今日核心概念

### 1. 项目资源管理与团队组建

**定义**：项目资源管理是有效利用人力、物力、财力等资源完成项目目标的过程，包含规划资源管理、估算活动资源、获取资源、建设团队、管理团队、控制资源六个过程。团队建设是把分散的个人整合成高绩效团队的核心活动。

**关键要点**：

1）**资源管理六过程**

| 过程 | 核心输出 | 工具 |
|------|----------|------|
| 规划资源管理 | 资源管理计划、团队章程 | 专家判断、数据分析 |
| 估算活动资源 | 资源需求、资源分解结构RBS | 专家判断、自下而上估算 |
| 获取资源 | 实物资源分配单、项目团队派工单 | 谈判、采购、多标准决策分析 |
| 建设团队 | 团队绩效评估、变更请求 | 培训、团建、集中办公、激励 |
| 管理团队 | 变更请求、经验教训 | 冲突管理、领导力、绩效评估 |
| 控制资源 | 工作绩效信息、变更请求 | 数据分析、问题解决 |

2）**冲突管理五种方法（高频案例题）**

| 方法 | 适用场景 | 特点 |
|------|----------|------|
| 撤退/回避 | 冲突升级、紧迫性低 | 暂时搁置、不解决 |
| 缓和/包容 | 鸡毛蒜皮、人际关系 | 求同存异、不追根因 |
| 妥协/调解 | 双赢不可达、时间紧 | 各退一步、临时方案 |
| 强迫/命令 | 紧急情况、必须执行 | 赢输局面、影响士气 |
| 合作/解决问题 | 复杂冲突、根本解决 | 根本解决、最佳方案但费时 |

考试口诀：**"退缓妥强合，紧急用强，根本用合"**。

3）**马斯洛需求层次与赫兹伯格双因素**

| 马斯洛需求 | 对应激励手段 |
|-----------|--------------|
| 生理需求 | 薪酬、福利、工作环境 |
| 安全需求 | 劳动合同、稳定雇佣 |
| 社会需求 | 团队归属、团建 |
| 尊重需求 | 表彰、晋升、授权 |
| 自我实现 | 挑战性任务、成就感 |

赫兹伯格双因素：**保健因素**（薪酬、工作条件，不足则不满但足也不激励）vs **激励因素**（成就、认可、责任，激励作用）。

4）**领导风格与情境领导**

| 风格 | 适用阶段 | 特点 |
|------|----------|------|
| 指挥型（告知） | 能力强意愿低（R1） | 指令清晰 |
| 教练型（推销） | 能力低意愿高（R2） | 解释决策 |
| 支持型（参与） | 能力中意愿中（R3） | 鼓励决策 |
| 授权型（授权） | 能力强意愿高（R4） | 自主决策 |

5）**团队建设五阶段（塔克曼模型）**

> **"形成-震荡-规范-成熟-解散"**（Forming-Storming-Norming-Performing-Adjourning）

- 形成期：相互了解、谨慎试探。
- 震荡期：观点冲突、矛盾爆发。
- 规范期：建立规则、合作默契。
- 成熟期：高绩效、自驱运行。
- 解散期：项目结束、释放资源。

### 2. 项目沟通管理与干系人管理

**定义**：沟通管理是确保及时、适当地生成、收集、分发、存储、检索、管理项目信息的过程，包含规划沟通管理、管理沟通、监督沟通三个过程。干系人管理是识别、分析、规划、管理干系人参与的过程。

**关键要点**：

1）**沟通管理三过程**

| 过程 | 核心输出 | 工具 |
|------|----------|------|
| 规划沟通管理 | 沟通管理计划 | 沟通需求分析、沟通模型 |
| 管理沟通 | 项目沟通记录、变更请求 | 沟通技术、沟通模型、报告 |
| 监督沟通 | 工作绩效信息、变更请求 | 专家判断、会议 |

2）**沟通渠道计算公式（高频必考）**

- 公式：**n(n-1)/2**，n为干系人/团队成员数。
- 例：10人项目团队，沟通渠道 = 10×9/2 = **45条**。
- 增加1人，渠道增量 = n-1。
- 考试陷阱：**渠道数 = 有效沟通总和**，包含所有可能的成对沟通。

3）**沟通方式分类**

| 方式 | 特点 | 适用 |
|------|------|------|
| 书面/正式 | 有据可查、严谨 | 合同、报告、章程 |
| 口头/非正式 | 灵活、快速 | 会议、面谈 |
| 推式沟通 | 单向发送 | 邮件、群发通知 |
| 拉式沟通 | 主动获取 | 知识库、文档库 |
| 交互式沟通 | 多方实时 | 会议、电话、即时通讯 |

4）**干系人管理四过程**

| 过程 | 输出 |
|------|------|
| 识别干系人 | 干系人登记册 |
| 规划干系人参与 | 干系人参与计划 |
| 管理干系人参与 | 变更请求 |
| 监督干系人参与 | 工作绩效信息 |

5）**权力/利益方格（必背）**

| 维度 | 权力高 | 权力低 |
|------|--------|--------|
| 利益高 | **重点管理**：密切沟通、定期汇报 | **随时告知**：及时通报 |
| 利益低 | **令其满意**：有限满足需求 | **监督监测**：定期关注 |

6）**干系人参与级别（从不了解→反对→中立→支持→领导）**

- 通过**干系人参与矩阵**跟踪实际参与级别与计划参与级别的差距。
- 差距为"当前未达到计划"时，需采取引导措施。

### 3. 项目采购管理与合同类型

**定义**：采购管理是从外部获取项目所需产品、服务或成果的过程，包含规划采购管理、实施采购、控制采购三个过程。合同类型的选择直接影响项目风险分配与成本控制。

**关键要点**：

1）**采购管理三过程**

| 过程 | 核心输出 | 工具 |
|------|----------|------|
| 规划采购管理 | 采购管理计划、采购策略、招标文件 | 自制/外购分析、专家判断、市场调研 |
| 实施采购 | 选定的卖方、合同、协议 | 投标人会议、建议书评估、谈判 |
| 控制采购 | 采购合同变更、工作绩效信息 | 索赔管理、采购审计、绩效审查 |

2）**合同类型对比（高频）**

| 类型 | 风险承担 | 适用场景 |
|------|----------|----------|
| 固定总价FFP | 买方风险低 | 范围明确、需求稳定 |
| 总价加激励FPIF | 共担 | 有目标、有上限 |
| 总价加经济调整FP-EPA | 双方共担 | 长期合同、跨年度 |
| 成本加固定费用CPFF | 卖方无激励 | 范围不清 |
| 成本加激励费用CPIF | 有激励 | 范围部分清楚 |
| 成本加奖励费用CPAF | 有奖励 | 卖方表现可衡量 |
| 工时材料T&M | 双方风险高 | 小项目、外包服务 |

3）**合同类型选择原则**

- **范围清楚→固定总价**；范围不清→成本补偿。
- 紧急项目→T&M工时材料。
- 卖方违约→买方受益则用**惩罚条款**；卖方超标→用**奖励条款**。

4）**采购管理核心工具**

- **自制/外购分析**：决定是否外购。
- **投标人会议**：保证公平公正、所有投标人信息一致（**不能私下透露给某一投标人**）。
- **建议书评估**：多标准决策分析（技术、价格、资质）。
- **采购审计**：识别可成功/失败的经验教训。

5）**索赔与争议解决**

- 索赔管理：合同变更、违约处理。
- 争议解决方式（**首选替代争议解决ADR**）：谈判→调解→仲裁→诉讼。
- 仲裁条款：**"或裁或审"无效**，必须明确单一选择。

6）**采购合同与工作说明书**

- **工作说明书SOW**：详细描述采购项的技术要求，是招标文件核心。
- **采购管理计划**：描述如何管理采购过程。
- 考试陷阱：SOW描述"做什么"，采购管理计划描述"怎么做"。

### 4. 项目整体管理与变更控制

**定义**：项目整体管理是协调各知识领域过程组的过程，包含制定项目章程、制定项目管理计划、指导与管理项目工作、管理项目知识、监控项目工作、实施整体变更控制、结束项目或阶段七个过程。整体变更控制是项目管理核心枢纽。

**关键要点**：

1）**整体管理七过程**

| 过程组 | 过程 | 输出 |
|--------|------|------|
| 启动 | 制定项目章程 | 项目章程、假设日志 |
| 启动 | 识别干系人 | 干系人登记册 |
| 规划 | 制定项目管理计划 | 项目管理计划 |
| 执行 | 指导与管理项目工作 | 变更请求、绩效报告 |
| 执行 | 管理项目知识 | 经验教训登记册 |
| 监控 | 监控项目工作 | 工作绩效报告、变更请求 |
| 监控 | 实施整体变更控制 | 批准的变更请求、变更日志 |
| 收尾 | 结束项目或阶段 | 最终产品/服务、经验教训 |

2）**项目章程与项目管理计划**

| 项目章程 | 项目管理计划 |
|----------|--------------|
| 授权项目存在 | 指导项目执行 |
| 由发起人签发 | 由项目经理编制 |
| 高层级需求、风险、里程碑 | 各知识领域子计划 |
| 任命项目经理、授予权力 | 经CCB/干系人审批 |

3）**整体变更控制流程（CCB核心流程）**

```
申请变更 → 影响分析（成本/进度/范围/质量/风险）→ CCB审查 → 批准/拒绝
→ 更新项目管理计划/基线 → 通知干系人 → 执行变更 → 记录变更日志
```

考试重点：**所有变更都必须走整体变更控制流程**，含紧急变更。

4）**变更控制委员会CCB**

- 组成：项目经理、发起人、关键干系人、技术专家。
- 职责：审查变更请求、批准/拒绝。
- 注意：**CCB不是项目经理的下属**，是独立决策机构。

5）**项目管理计划与基线**

- 项目管理计划 = 范围/进度/成本/质量/资源/沟通/风险/采购/干系人参与计划 + 三大基准（范围、进度、成本）。
- **基准一旦确立，变更必须走整体变更控制流程**。
- 应急储备动用由项目经理决定；管理储备动用需发起整体变更。

6）**项目收尾与经验教训**

- 合同收尾：结算、未完索赔、档案归档。
- 管理收尾：经验教训登记册更新、项目终验、文档移交。
- 考试陷阱：**经验教训应在项目全过程收集**，不只是收尾阶段。

### 5. 项目绩效域与PMBOK第七版新框架

**定义**：PMBOK第七版从"五大过程组+十大知识领域"演进为**八大绩效域+十二项原则**的新框架，强调价值导向、敏捷适应、系统思考。

**关键要点**：

1）**八大绩效域（替代十大知识领域）**

| 绩效域 | 核心目标 |
|--------|----------|
| 干系人 | 建立有效工作关系 |
| 团队 | 培养团队领导力 |
| 开发方法与生命周期 | 选择合适开发方式 |
| 规划 | 制定并维护项目计划 |
| 项目工作 | 建立过程、管理物理资源 |
| 交付 | 交付范围、质量 |
| 测量 | 评估项目绩效、采取纠正措施 |
| 不确定性 | 风险识别、评估、应对 |

2）**十二项项目管理原则**

| 编号 | 原则 |
|------|------|
| 1 | 成为勤勉、尊重、关心他人的榜样 |
| 2 | 营造协作的团队环境 |
| 3 | 有效地让干系人参与 |
| 4 | 聚焦价值 |
| 5 | 识别、评估、响应系统交互 |
| 6 | 展现领导力 |
| 7 | 根据环境剪裁 |
| 8 | 把质量融入过程与可交付成果 |
| 9 | 驾驭复杂性 |
| 10 | 优化风险应对 |
| 11 | 拥抱适应性 |
| 12 | 实现变革以推动价值交付 |

3）**新旧框架对比**

| 旧版（第六版） | 新版（第七版） |
|----------------|----------------|
| 5过程组+10知识领域 | 8绩效域+12原则 |
| 输入-工具-输出ITTO | 价值导向、系统思考 |
| 瀑布/预测为主 | 预测+敏捷+混合 |
| 过程驱动 | 原则驱动 |

4）**项目价值与商业论证**

- 商业论证：项目的商业价值证明，包含成本效益分析。
- 价值交付：贯穿项目始终，是PMBOK第七版核心。
- 项目集/项目组合：通过治理实现战略价值对齐。

5）**混合方法与敏捷裁剪**

- **预测型**：需求清晰、范围稳定。
- **敏捷型**：需求模糊、快速迭代。
- **混合型**：核心稳定、外层敏捷；当前主流趋势。
- 敏捷Scrum：Product Owner + Scrum Master + 团队，迭代冲刺、每日站会、评审、回顾。

## 案例分析题

**题目**：

某市"一网通办"政务服务平台建设项目，总投资 1800 万元，工期 14 个月，由市大数据局牵头，整合公安、社保、医保、教育、公积金、不动产等 12 个部门的 200 余项政务事项。项目采用"政府投资+总集成商+部门分承建"模式，集成商 A 公司中标承建全市统一受理平台、统一身份认证、电子证照库、统一支付四大基础平台。

项目实施过程中发生以下事件：

（1）**启动阶段**：大数据局领导签发项目章程，任命项目经理小王。章程明确"总投资1800万元，工期14个月，整合12部门200项事项"为高层级需求。但章程未明确"项目验收标准"和"项目成功标准"，也未任命关键干系人代表进入项目治理结构。小王接到章程后立即启动项目，无项目管理计划。

（2）**团队组建与采购阶段**：项目需组建30人团队（含小王），含平台开发、接口对接、数据治理、安全运维四个小组。8名核心开发人员从集成商A公司内部抽调，22名外包人员分别由3家外包公司（B、C、D）提供。3家外包公司同时承担"接口对接"工作（公安、社保、医保三组）。小王采用"固定总价合同"与B公司签订公安接口外包合同（合同价300万，期限8个月）。社保接口外包合同采用"成本加固定费用"方式（预算200万，期限8个月）。医保接口外包合同采用"工时材料"方式（预算150万，期限6个月）。

（3）**沟通管理与冲突管理阶段**：项目执行至第5个月，社保接口对接进展严重滞后，B公司公安组负责人与C公司社保组负责人因"统一身份认证接口规范"产生冲突，双方各自坚持自家方案，影响整体进度。小王紧急召开协调会，宣布"由我决定采用B公司方案，C公司必须配合"，要求3天内完成接口对接。但C公司负责人认为"决定未走变更控制流程、不公平"，并以"接口厂商不配合"为风险类别拒绝执行。小王与C公司关系紧张，C公司核心开发人员 2 人提出离职。

（4）**变更控制阶段**：第7个月，公安部门提出"增加人脸识别登录功能"，业务部门提出"增加电子证照共享接口30个"，领导批示"原则上同意，请小王评估影响后实施"。小王未做影响分析、未召开CCB会议，紧急安排B公司团队加班赶工实施。变更实施1个月后发现"电子证照共享接口30个"实际需要改造 60 个接口（含上游与下游），工期增加 60 天、预算增加 380 万元；同时人脸识别登录引发系统安全漏洞，第三方测评机构通报要求紧急修复。

（5）**绩效与收尾阶段**：项目执行至第 12 个月（工期已过 85%），关键绩效数据如下：
- BAC（完工预算）= 1800 万元
- PV（计划值）= 1620 万元
- AC（实际成本）= 1700 万元
- EV（挣值）= 1450 万元

3家外包公司均出现不同程度的人员流动，B公司公安组离职1人、C公司社保组离职2人、D公司医保组离职1人。团队出现士气下降、加班常态化。经验教训登记册已记录12条，但小王未在项目过程中组织过正式的"经验教训总结会"。

**问题**：

1. 分析项目章程的缺陷，指出其对项目管理的影响。说明项目管理计划与项目章程的区别。
2. 分析本项目团队组建、采购策略、合同类型选择中存在的问题。
3. 分析小王在沟通管理、冲突管理中的错误，给出正确的冲突解决方法与变更控制建议。
4. 评估变更控制阶段的失误，计算变更后的挣值指标变化，说明应吸取的教训。
5. 分析项目绩效、人员流动、收尾管理的现状，给出纠偏与收尾建议。

**参考答案**：

**问题 1：项目章程缺陷与项目管理计划区别**

存在的缺陷：
- **章程未明确"项目验收标准"和"成功标准"**。项目章程必须包含高层级需求、风险、里程碑、预算、验收标准、成功标准、可发起人授权等，缺一不可。
- **未任命关键干系人代表进入治理结构**。12个部门、3家外包公司、集成商均为关键干系人，章程应指定代表进入变更控制委员会CCB、督导委员会等治理机构。
- **章程仅给出"整合200项事项"这种抽象描述**，缺乏可衡量的成功指标（如办件量、办结时效、市民满意度）。
- **小王接到章程后未编制项目管理计划就直接启动**，违反整体管理流程。

影响：
- 验收标准缺失 → 项目后期争议大、收尾困难。
- 干系人治理缺位 → 变更决策无法落地、CCB无法有效运转。
- 章程过于宏观 → 各部门对项目范围理解不一致。

项目管理计划与项目章程的区别：

| 维度 | 项目章程 | 项目管理计划 |
|------|----------|--------------|
| 编制方 | 发起人签发 | 项目经理编制 |
| 时机 | 启动前 | 启动后、规划过程组 |
| 内容 | 高层级、原则性 | 各知识领域子计划 |
| 作用 | 授权项目存在 | 指导项目执行与控制 |
| 变更 | 章程变更需发起人 | 子计划变更可由项目经理 |
| 关系 | 章程是项目管理的输入 | 计划是章程的具体化 |

改进建议：
- 补充章程附件：详细验收标准、成功度量指标、干系人治理结构表。
- 编制完整的项目管理计划（含12项子计划+3大基准）。
- 召开项目启动会，向所有干系人宣讲章程与计划。

**问题 2：团队组建、采购与合同类型问题**

存在的问题：
- **3家外包公司同时承担同一类工作（接口对接）**，接口协调工作量剧增，且容易出现"标准之争"（事件3已暴露）。
- **8名核心开发人员与外包人员比例失衡**（核心8人 vs 外包22人），核心人员难以全面管控外包质量，关键技术决策易失控。
- **3家外包合同类型不一致**：公安用固定总价（范围清楚）、社保用成本加固定费用（范围不清）、医保用工时材料（范围不清但金额灵活）。问题在于**社保与医保接口范围实际不清楚**——题干未做充分需求调研就贸然外包。
- **未做自制/外购分析**：30人团队中各小组是否必须外包？核心架构团队可否A公司自建？未做权衡。
- **合同未明确知识产权、源代码归属、违约责任**等关键条款。

合同类型选择改进：
- 公安接口（需求明确）→ **固定总价FFP**（正确）。
- 社保接口（部分清楚）→ **成本加激励费用CPIF**或**总价加激励FPIF**，避免"成本加固定费用"过度保护卖方。
- 医保接口（短期小项目）→ **工时材料T&M**（合理）。
- 所有合同应明确SOW、验收标准、知识产权、违约责任。

团队改进：
- 增加核心人员比例至40%以上，关键模块由A公司核心团队主导。
- 接口对接工作按"业务条线"切分，**避免3家外包做同一类工作**。
- 统一接口规范、强制代码评审与持续集成。

**问题 3：沟通与冲突管理错误**

错误分析：
- **小王在事件3中采用"强迫/命令"方式解决冲突**：未做根本原因分析、未让双方陈述理由、直接宣布采用B公司方案。这是"赢输局面"，会损害C公司积极性，违背"合作/解决问题"原则。
- **未做冲突的根源分析**：冲突的根因是"统一身份认证接口规范"未在项目早期统一，导致各外包公司各自理解不同。
- **C公司拒绝执行的法律分析错误**："接口厂商不配合"是风险类别，与合同履约是两个问题；C公司拒绝合规变更控制流程下的合理决策，确实违约，但小王未走合同条款处理。
- **未及时与C公司核心员工沟通**：2名核心员工提出离职，反映小王与C公司关系管理失败。

正确的冲突解决方法（按优先级）：
1. **合作/解决问题**（根本解决）：召集B/C/D三方+技术专家，统一接口规范、形成书面共识。
2. **妥协/调解**：若短期不可达，各退一步采纳临时方案。
3. **强迫/命令**：仅在紧急情况下使用，并需配套变更控制流程。
4. **缓和/包容**：仅适用于小冲突。
5. **撤退/回避**：避免用于复杂冲突。

变更控制建议：
- 任何接口规范变更必须走整体变更控制流程：申请→影响分析（接口数量、测试影响、风险）→CCB审批→通知所有相关方→执行→验证。
- 召开CCB会议，由发起人、大数据局代表、3家外包代表共同决策。
- 引入**接口适配层**作为折中方案，避免让一方完全让步。

**问题 4：变更控制失误与挣值计算**

失误分析：
- **未做影响分析**就直接实施变更，违反整体变更控制流程。
- **未召开CCB会议**：领导批示"原则上同意"不等于CCB批准，不能作为变更依据。
- **范围蔓延**：从"电子证照30个接口"蔓延到"60个接口"，属于**范围蔓延**（未受控的范围扩大）。
- **未评估技术可行性**：人脸识别登录未做安全评估，埋下安全漏洞。
- **未识别次生风险**：变更引发的"工期风险""成本风险""安全风险"均未识别。

变更前挣值指标（第7个月）：
- 题目未给出第7个月的精确值，但项目持续超支与滞后趋势明显。
- 假设变更前项目尚可维持CPI=0.95、SPI=0.92左右。

变更后影响（第8个月）：
- 工期增加60天（原工期14个月→约16个月）。
- 预算增加380万元（原预算1800万→2180万元）。

挣值计算（第12个月）：
- CV = EV - AC = 1450 - 1700 = **-250万元**（成本超支250万）
- SV = EV - PV = 1450 - 1620 = **-170万元**（进度滞后170万）
- CPI = EV/AC = 1450/1700 ≈ **0.853**（<1，超支）
- SPI = EV/PV = 1450/1620 ≈ **0.895**（<1，滞后）

完工预测：
- EAC = BAC / CPI = 1800 / 0.853 ≈ **2110万元**（典型公式）
- 但实际变更后BAC已调整为2180万元，需重新计算：
- 新EAC = 2180 / 0.853 ≈ **2555万元**
- VAC = BAC - EAC = 2180 - 2555 ≈ **-375万元**
- TCPI = (BAC - EV) / (BAC - AC) = (2180-1450) / (2180-1700) = 730 / 480 ≈ **1.521**（极高，基本不可能完成原预算）

教训总结：
- **所有变更必须走整体变更控制流程**——申请、影响分析、CCB审批、实施、验证。
- **影响分析必须量化**：不能只说"工期增加"，要列出具体天数、接口数量、风险等级。
- **变更引发的次生风险必须独立识别**（安全漏洞即为典型次生风险）。
- **领导批示不代替CCB决策**，必须区分行政管理与项目治理。
- **建议引入变更分级机制**：紧急变更走快速通道，普通变更走标准CCB流程。

**问题 5：项目绩效、人员流动与收尾管理**

现状分析：
- 挣值指标：CPI=0.853、SPI=0.895，**双重失控**，但仍在可控范围（>0.8）。
- TCPI=1.521，未来必须保持远高于当前绩效才能完成原预算，**实现可能性极低**。
- 人员流动：3家外包公司合计流失4人，约占外包22人团队的18%，**远超10%警戒线**。
- 士气下降、加班常态化 → 易引发更多人员流失，形成恶性循环。
- 经验教训登记册已记录12条，但小王未召开正式经验教训总结会 → 知识沉淀失效。

纠偏建议：
- **进度纠偏**：分析关键路径、识别可并行任务、引入快速跟进；同步评估加班的边际效用，避免疲劳作战。
- **成本纠偏**：识别非关键活动，削减范围或延期（需CCB审批）；严格控制变更；启用应急储备。
- **绩效纠偏**：对CPI<0.85的活动进行根本原因分析（人/方法/工具/管理），重点整改。
- **人员保留**：紧急与4名离职员工沟通挽留；启动B/C/D公司备用资源池；增加团队激励（奖金、表彰、调休）。
- **氛围改善**：小王主动与C公司修复关系、召开团队士气提升会议、引入团建活动。

收尾管理建议：
- **立即召开2次经验教训总结会**：1次面向内部团队、1次面向12部门干系人。
- **建立经验教训分级**：技术类、管理类、流程类、外包类。
- **更新组织级知识库**：把12部门政务集成经验入库，供后续项目复用。
- **项目收尾文档清单**：最终验收报告、合同结算单、未完索赔清单、档案归档清单。
- **项目后评价**：商业论证回顾、价值实现评估、ROI分析。
