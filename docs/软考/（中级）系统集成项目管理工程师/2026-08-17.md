# （中级）系统集成项目管理工程师 · 2026-08-17

## 今日核心概念

### 1. 项目质量管理

**定义**：质量管理是确定质量方针、目标，并通过质量规划、质量保证、质量控制确保项目满足干系人需求的过程。系统集成项目涉及软件、硬件、网络、数据多维度，质量是验收核心。

**关键要点**：

1）**质量管理三大过程**

| 过程 | 目标 | 关键产出 |
|------|------|----------|
| 规划质量管理 | 制定质量标准 | 质量管理计划、度量指标 |
| 管理质量（QA）| 过程合规审计 | 质量报告、变更请求 |
| 控制质量（QC）| 检验可交付物 | 核实的可交付物、变更请求 |

考试口诀：**"QA管过程、QC管结果"**。

2）**质量核检表 vs 帕累托图（高频工具）**

| 工具 | 用途 |
|------|------|
| 质量核检表 | 收集数据、记录缺陷类型与频次 |
| 帕累托图 | 二八原则，识别"关键的少数"缺陷 |
| 因果图（鱼骨图）| 分析缺陷根本原因（4M1E：人机料法环）|
| 控制图 | 监控过程是否稳定（七点规则）|
| 散点图 | 分析两变量相关性 |

考试陷阱：**帕累托识别"主要问题"，因果图追"根本原因"，控制图判"稳定性"**。

3）**七点规则（控制图判异）**

> 连续 7 个点落在均值一侧，或连续 7 个点呈单调上升/下降趋势，**判过程异常**。

- 例：监测每日缺陷数，7 天连续上升 → 流程失控，必须调查。
- 例：连续 7 个点都在均值上方 → 系统性偏差。

4）**质量成本四类**

| 类型 | 含义 | 例 |
|------|------|-----|
| 预防成本 | 预防缺陷发生 | 培训、过程评审 |
| 评估成本 | 发现缺陷 | 测试、检查 |
| 内部失败成本 | 交付前返工 | 返工、废品 |
| 外部失败成本 | 交付后失败 | 保修、赔偿、口碑损失 |

考试口诀：**"预评内外"**，**预防成本最低、外部失败成本最高**——早投入预防最划算。

5）**质量管理 vs 质量控制区别（高频）**

| 维度 | QA（管理质量） | QC（控制质量） |
|------|---------------|---------------|
| 时机 | 全过程 | 阶段结束/交付前 |
| 对象 | 过程、流程 | 可交付物 |
| 方法 | 审计、过程分析 | 测试、检查 |
| 输出 | 过程改进建议 | 验收结论 |

6）**测试类型（系统集成高频）**

| 类型 | 对象 |
|------|------|
| 单元测试 | 模块/函数 |
| 集成测试 | 模块间接口 |
| 系统测试 | 完整系统（功能、性能、安全）|
| 验收测试 | 用户/客户（α测试=内测，β测试=公测）|

7）**质量保证体系**

- ISO 9001：通用质量管理标准。
- CMMI 5 级：**初始→已管理→已定义→定量管理→优化级**。
- 系统集成项目常要求 CMMI 3 级以上或 ISO 9001 认证。

### 2. 项目风险管理

**定义**：风险管理是系统识别、分析、应对、监控项目风险的过程。系统集成项目跨厂商、跨平台、跨网络，风险管理是降低项目失败概率的核心。

**关键要点**：

1）**风险管理六过程**

| 过程 | 核心活动 |
|------|----------|
| 规划风险管理 | 制定风险管理计划 |
| 识别风险 | 识别风险、记录风险登记册 |
| 定性风险分析 | 概率影响矩阵、优先级排序 |
| 定量风险分析 | 蒙特卡洛、期望货币值 EMV |
| 规划风险应对 | 制定应对策略 |
| 实施风险应对 | 执行应对策略、签订合同 |
| 监督风险 | 监控残余风险、新风险 |

注：PMBOK 七版将"实施风险应对"并入规划。考试仍按六过程记忆。

2）**风险分类（必背）**

| 类型 | 含义 | 例 |
|------|------|-----|
| 已知风险 | 已识别、可分析 | 关键人员离职 |
| 未知风险 | 不可预见 | 政策突变、地震 |
| 已知-未知风险 | 已识别但概率/影响不确定 | 接口对接失败 |
| 残余风险 | 应对后仍存在 | 备份恢复后仍丢失 |

3）**风险应对策略（高频必考）**

| 风险类型 | 策略 | 例 |
|---------|------|-----|
| 威胁（负面）| 规避 | 取消风险源 |
| 威胁 | 转移 | 购买保险、外包 |
| 威胁 | 减轻 | 降低概率/影响 |
| 威胁 | 接受 | 应急储备 |
| 机会（正面）| 开拓 | 确保机会实现 |
| 机会 | 分享 | 与第三方共担 |
| 机会 | 提高 | 增加概率 |
| 机会 | 接受 | 抓住机会但不主动追求 |

考试口诀：**"威胁规避转移减轻接受，机会开拓分享提高接受"**。

4）**EMV 期望货币值（定量分析核心）**

> EMV = 概率 × 影响金额

例：项目进度延迟风险 P=30%，影响 100 万元 → EMV = 30 万。
例：技术失败风险 P=20%，损失 50 万 → EMV = 10 万。
**EMV 为负 → 风险应对成本不应超过 EMV**。

5）**风险登记册内容**

- 风险编号、描述、类别。
- 概率、影响、风险值（概率×影响）。
- 应对策略、责任人。
- 触发条件、应急计划。
- 状态（新识别/已发生/已关闭）。

6）**风险监控工具**

| 工具 | 用途 |
|------|------|
| 风险再评估 | 定期重新评估 |
| 风险审计 | 审计风险应对有效性 |
| 偏差与趋势分析 | CPI/SPI 偏离识别风险 |
| 储备金分析 | 应急/管理储备消耗 |
| 状态会议 | 例会审视风险 |

7）**应急储备 vs 管理储备**

| 储备 | 用途 | 批准人 |
|------|------|--------|
| 应急储备 | 应对已识别风险 | 项目经理 |
| 管理储备 | 应对未识别风险 | 高层/发起人 |

### 3. 项目成本管理

**定义**：成本管理是规划、估算、预算、控制项目成本，确保在批准预算内完成项目的过程。系统集成项目软硬件兼有，成本管理精度直接影响盈利。

**关键要点**：

1）**成本管理四过程**

| 过程 | 核心活动 |
|------|----------|
| 规划成本管理 | 制定成本管理计划、精度等级 |
| 估算成本 | 自下而上/类比/参数估算 |
| 制定预算 | 汇总活动成本 → 成本基准 |
| 控制成本 | 监控成本、变更请求、EVM分析 |

2）**估算方法三选（高频）**

| 方法 | 精度 | 适用 |
|------|------|------|
| 类比估算 | -50% ~ +50% | 早期、信息少 |
| 参数估算 | -30% ~ +30% | 有历史数据、参数模型 |
| 自下而上估算 | -10% ~ +10% | 详细、WBS 完整 |

考试口诀：**"类比参数自下而上，精度递增"**。

3）**成本基准与预算三要素**

> **成本基准 = 管理储备 + 应急储备 + 活动成本估算**

- 活动成本估算 → 工作包成本。
- 工作包成本 + 应急储备 = 控制账户预算。
- 控制账户预算汇总 = 成本基准。
- 成本基准 + 管理储备 = 项目预算。

4）**挣值管理 EVM（再强化，必考）**

| 指标 | 公式 | 含义 |
|------|------|------|
| PV | 计划值 | 应完成工作的预算 |
| EV | 挣值 | 实际完成工作的预算 |
| AC | 实际成本 | 实际花费 |
| CV | EV-AC | 成本偏差 |
| SV | EV-PV | 进度偏差 |
| CPI | EV/AC | 成本绩效 |
| SPI | EV/PV | 进度绩效 |
| BAC | 完工预算 | 原始预算 |
| EAC | 完工估算 | 预计总成本 |
| VAC | BAC-EAC | 完工偏差 |
| TCPI | (BAC-EV)/(BAC-AC) | 完工绩效指数 |

5）**完工预测三公式**

| 公式 | 适用 |
|------|------|
| EAC = BAC / CPI | 当前绩效持续 |
| EAC = AC + (BAC-EV) | 未来按计划执行 |
| EAC = AC + 自下而上重估 | 重大变更后 |

6）**TCPI 评价标准**

| TCPI 值 | 含义 |
|---------|------|
| < 1 | 容易达成 |
| 1 ~ 1.2 | 正常范围 |
| 1.2 ~ 1.5 | 高难度 |
| > 1.5 | **几乎不可能** |

7）**成本控制措施**

| 情况 | 措施 |
|------|------|
| CPI<1 超支 | 赶工、范围削减、并行工程 |
| 需求蔓延 | 变更控制、需求冻结 |
| 资源浪费 | 资源平衡、生产率提升 |
| 应急储备消耗快 | 风险审视、申请管理储备 |

### 4. 项目进度管理

**定义**：进度管理是确保项目按时完成的全部过程，含活动定义、排序、估算、计划制定、控制。系统集成项目多任务并行，进度管理是项目管理核心难点。

**关键要点**：

1）**进度管理六过程**

| 过程 | 输出 |
|------|------|
| 规划进度管理 | 进度管理计划 |
| 定义活动 | 活动清单、里程碑清单 |
| 排列活动顺序 | 项目进度网络图、依赖关系 |
| 估算活动持续时间 | 持续时间估算 |
| 制定进度计划 | 进度基准、进度模型 |
| 控制进度 | 工作绩效信息、变更请求 |

2）**依赖关系四类型**

| 类型 | 含义 | 例 |
|------|------|-----|
| FS（结束-开始）| A 完 B 始 | 编码→测试 |
| FF（结束-结束）| A 完 B 完 | 验收A+验收B 同步 |
| SS（开始-开始）| A 始 B 始 | 编码+单元测试同步 |
| SF（开始-结束）| A 始 B 完 | 监理开始 → A 整体完成 |

考试口诀：**"FS 最常用，FF/SS 并行，SF 极少"**。

3）**关键路径法 CPM**

- 关键路径 = 项目网络图中最长路径。
- 关键路径上的活动 = 关键活动（延误=项目延误）。
- 非关键路径有时差（Slack/Float）可缓冲。
- **关键路径可能有多条**，但不一定是活动最多的路径。

4）**进度压缩两方法**

| 方法 | 做法 | 代价 |
|------|------|------|
| 赶工（Crash）| 增加资源 | 成本↑、风险↑ |
| 快速跟进（Fast-Tracking）| 并行活动 | 风险↑、返工率↑ |

考试口诀：**"赶工花钱，快速跟进加风险"**。

5）**资源平衡 vs 资源平滑**

| 方法 | 改变路径 | 改变工期 |
|------|---------|---------|
| 资源平衡 | 改变 | 可能改变 |
| 资源平滑 | 不改变 | 不改变 |

考试陷阱：**资源平滑必须保证关键路径不变**。

6）**PDM 网络图绘制**

- 方框节点法（PDM）= AON（活动节点法），主流方法。
- 与 AOA（箭线图法）区别：AOA 仅支持 FS 关系。
- **PDM 支持 FS/FF/SS/SF 四种依赖**。

7）**关键链法 CCPM**

- 关键链 = 考虑**资源约束**后的最长路径。
- 三类缓冲：**项目缓冲（PB）、接驳缓冲（FB）、资源缓冲（RB）**。
- 关键链 = 关键路径 + 资源约束调整。

8）**进度绩效指标**

- SV = EV - PV，<0 滞后。
- SPI = EV / PV，<1 滞后。
- 进度偏差不能靠"加人"解决（Brook's Law：增加人手反而延迟）。

### 5. 项目范围管理与需求管理

**定义**：范围管理是确保项目包含且仅包含完成所需工作的全部过程；需求管理是收集、分析、记录、确认干系人需求的过程。系统集成项目范围蔓延是失败主因。

**关键要点**：

1）**范围管理六过程**

| 过程 | 输出 |
|------|------|
| 规划范围管理 | 范围管理计划、需求管理计划 |
| 收集需求 | 需求文件、需求跟踪矩阵 |
| 定义范围 | 项目范围说明书 |
| 创建 WBS | WBS、WBS 词典、范围基准 |
| 确认范围 | 验收的可交付物、变更请求 |
| 控制范围 | 工作绩效信息、变更请求 |

2）**需求层次（再强化）**

| 层次 | 含义 |
|------|------|
| 业务需求 | 高层战略目标 |
| 干系人需求 | 干系人期望 |
| 解决方案需求 | 功能+非功能需求 |
| 过渡需求 | 从现状到未来的过渡 |
| 项目需求 | 范围、SLA 等约束 |

3）**WBS 工作分解结构**

- 100% 原则：覆盖全部工作，不多不少。
- 8/80 原则：工作包 8~80 小时可估算。
- 4-6 层：通常 4-6 层，太多增加管理成本。
- WBS 最底层 = 工作包（可估算、可分配、可验收）。
- WBS 不包含依赖关系（依赖关系在网络图）。

4）**范围基准三件套**

> **范围基准 = 范围说明书 + WBS + WBS 词典**

- 范围基准是变更控制的"参照物"。
- 任何范围变更必须走整体变更控制流程。

5）**范围蔓延 vs 镀金 vs 范围蠕变**

| 概念 | 含义 |
|------|------|
| 范围蔓延 | 未控制的范围扩大 |
| 镀金 | 团队主动加"客户没要求但看起来好的"功能 |
| 范围蠕变 | 渐进式范围蔓延 |

考试陷阱：**镀金和蔓延都需禁止**，但镀金是善意，结果同样不可控。

6）**需求跟踪矩阵 RTM（高频）**

- 双向追溯：每个需求可追溯到来源（业务、用户、合同）。
- 每个需求可追溯到设计、实现、测试。
- 跟踪矩阵是变更影响分析的关键工具。
- 公式：**需求数 → 设计项数 → 实现项数 → 测试用例数**。

7）**范围确认 vs 质量控制**

| 维度 | 范围确认 | 质量控制 |
|------|---------|---------|
| 关注 | 可交付物验收 | 可交付物质量 |
| 主体 | 客户/发起人 | QA/QC 团队 |
| 输出 | 验收结论 | 核实的可交付物 |

考试陷阱：**范围确认不等于质量检查**，必须分别做。

## 案例分析题

**题目**：

某省"智慧医疗"系统集成项目，总投资 2200 万元，工期 14 个月，由省卫健委牵头，整合 8 家三甲医院、15 家区级医院、若干社区卫生服务中心的信息系统，建设省级医疗云平台、远程会诊系统、AI 影像诊断系统、电子病历共享平台。项目采用"总集成商+硬件+软件分包"模式，A 公司中标作总集成商，承担云平台搭建、AI 系统集成；B 公司承担硬件（服务器、存储、网络）；C 公司承担电子病历软件开发；D 公司承担远程会诊系统；E 公司承担安全等保建设。

项目执行过程发生以下事件：

（1）**范围与需求阶段（第1-2月）**：项目启动后，A 公司项目经理小王组织需求调研，与 8 家三甲医院分别召开 3 天需求研讨会，收集需求 380 项。但小王发现"不同医院对电子病历的要求差异很大"，决定"按 80% 共同需求 + 20% 定制需求"实施。第 2 个月末，需求文档已包含 380 项需求，但 WBS 只定义了 250 个工作包（小王解释"另外 130 项是次要需求，后续细化"），范围说明书经卫健委签字确认。

（2）**进度与关键路径阶段（第3-5月）**：项目共 14 个月，里程碑节点：第 4 月硬件到货、第 7 月云平台上线、第 10 月电子病历开发完成、第 12 月联调测试、第 14 月验收。小王采用关键路径法（CPM）制定进度计划，识别关键路径为"硬件到货→云平台搭建→电子病历开发→联调测试→验收"，共 14 个月。第 5 月，硬件延迟 1 个月到货（B 公司解释"芯片全球短缺"），小张采用"快速跟进"压缩进度，让云平台搭建与硬件调试并行，导致云平台与硬件接口多次冲突。

（3）**成本与挣值阶段（第6-8月）**：第 8 个月关键数据：
- BAC = 2200 万元
- PV = 1200 万元
- AC = 1450 万元
- EV = 1050 万元

小王发现"成本超支、进度滞后"，但仍未启动纠偏措施，认为"再观察一个月"。

（4）**质量与测试阶段（第9-11月）**：第 10 月电子病历系统完成开发，C 公司提出"已完成内部测试"请求验收。A 公司测试团队进行系统测试时发现：
- 系统在 500 并发用户下崩溃（要求支持 5000 并发）；
- 80% 病历数据迁移失败；
- AI 影像诊断系统误诊率高达 8%（要求 < 2%）。

C 公司负责人说"测试用例由 C 公司自定，按 C 公司测试标准算 90 分"，拒绝返工。E 公司交付的安全等保方案未通过等保 2.0 三级测评。

**问题 2：挣值计算与绩效分析**

挣值计算（第 8 月）：
- CV = EV - AC = 1050 - 1450 = **-400 万元**（成本超支 400 万）
- SV = EV - PV = 1050 - 1200 = **-150 万元**（进度滞后 150 万）
- CPI = EV / AC = 1050 / 1450 ≈ **0.724**（<1，超支严重）
- SPI = EV / PV = 1050 / 1200 = **0.875**（<1，进度滞后）

完工预测：
- EAC = BAC / CPI = 2200 / 0.724 ≈ **3039 万元**（典型公式，按当前绩效持续）
- VAC = BAC - EAC = 2200 - 3039 ≈ **-839 万元**（完工超支 839 万）
- TCPI = (BAC - EV) / (BAC - AC) = (2200-1050) / (2200-1450) = 1150 / 750 ≈ **1.533**
  - TCPI > 1.5：**几乎不可能完成原预算**。
  - **建议：追加预算 800~900 万元 + 砍掉部分非核心功能**。

绩效状态判断：

| CPI | SPI | 状态 |
|-----|-----|------|
| 0.724 (<1) | 0.875 (<1) | **双重失控** |

小王"再观察一个月"决策的问题：
- **错过最佳纠偏时机**：CPI 0.724 已是严重失控，"再观察"会加剧失控。
- **违反成本控制原则**：成本控制要求**持续监控、即时纠偏**，而非观望。
- **应急储备/管理储备未审视**：未检查储备余额、是否需要动用管理储备。
- **责任未落实**：未指定纠偏责任人、纠偏措施、纠偏时限。
- **风险升级**：未启动 L3 升级机制，卫健委/发起人未及时知情。

正确做法：
1. **立即启动重大纠偏**：识别成本超支原因（采购、设计变更、返工、范围蔓延）。
2. **储备审视**：检查应急储备余额，必要时申请管理储备（发起人批准）。
3. **范围调整**：与卫健委协商砍掉部分"应该实现（Should）"或"可以实现（Could）"功能。
4. **赶工或快速跟进**：对关键路径上剩余活动谨慎采用，权衡成本/风险。
5. **趋势分析**：连续 3-5 个周期观察 CPI/SPI 走势，下降趋势必须立即升级。
6. **责任追究**：对成本失控责任人追责，制定后续预防措施。

考试陷阱：**TCPI > 1.5 几乎不可能，必须追加预算或调整范围**。

**问题 3：进度管理与关键路径失误**

关键路径分析：
- 识别结果"硬件→云平台→电病→联调→验收"基本正确。
- 但未识别**多条关键路径**的可能性（如远程会诊、安防等可能并行关键路径）。
- 未考虑**资源约束**对关键路径的影响（关键链法）。

快速跟进失误：
- **"硬件延迟→快速跟进"是错误决策**：
  - 快速跟进只适用于"活动间存在依赖但可并行"的场景。
  - 硬件到货是云平台搭建的强依赖（FS），**不能并行**。
  - 强行并行导致接口冲突，反而延后。
- **正确做法应是"赶工"或"接受延期"**：
  - 赶工：增加资源（加派人手、加班）压缩后续活动。
  - 接受延期：调整后续里程碑，与卫健委协商延后 1 个月。
  - **风险与裕度评估**：赶工成本 vs 延期影响。

关键链未应用：
- 项目涉及 5 家公司，**资源冲突明显**（高级工程师、测试设备、网络带宽），但未用关键链法。
- 关键链应在关键路径基础上，识别资源约束后的最长路径。
- 三类缓冲（PB 项目缓冲、FB 接驳缓冲、RB 资源缓冲）可吸收不确定性。

正确进度压缩方法：
1. **赶工（Crash）**：增加资源、加班，但增加成本和风险。
2. **快速跟进（Fast-Tracking）**：并行可并行活动，仅适用于弱依赖关系。
3. **资源平衡**：调整非关键路径活动，解决资源冲突。
4. **关键链管理**：识别资源约束最长路径，设置项目缓冲、接驳缓冲。
5. **范围调整**：砍掉非核心功能腾出时间。
6. **接受延期**：与客户协商延后里程碑。

考试口诀：**"赶工花钱、快速跟进加风险、关键链管资源、范围调整最稳妥"**。

2. **性能测试必做**：压测工具（JMeter、LoadRunner）模拟 5000+ 并发。

7. **质量成本投入**：增加预防成本（培训、评审），降低外部失败成本。

考试口诀：**"测试标准依合同，性能压测必做，AI 训练重数据，等保合规前置"**。
