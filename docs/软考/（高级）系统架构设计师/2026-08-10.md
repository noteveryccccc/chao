## 今日核心概念

### 1. 云原生应用架构演进
定义：云原生应用架构是以容器、服务网格、微服务、不可变基础设施和声明式 API 为基础构建的、面向云环境充分利用弹性与可观测能力的应用架构形态，强调以应用为中心、平台化交付和持续演进。
关键要点：
- 容器化解决环境一致性，应用以镜像为基本交付物，配合 Kubernetes 实现调度、自愈、扩缩容和滚动升级。
- 微服务设计要点是单一职责、独立部署、技术异构、团队小而自治；服务间通过 API 网关、服务注册中心、配置中心和分布式追踪进行治理。
- 服务网格 Sidecar 模式把通信、安全、可观测从应用中剥离，形成数据面与控制面解耦，Istio 与 Linkerd 是典型实现。
- 不可变基础设施要求镜像构建后只读，运行时通过替换实例实现变更，运维操作靠版本和配置而非 SSH 登录修改。
- 声明式 API 让工程师描述目标态，平台自动收敛到目标态，典型例子是 Kubernetes CRD 与 Operator 模式。

### 2. 多云与混合云架构
定义：多云架构指企业同时使用多个公有云或私有云，避免供应商锁定并满足合规与地域要求；混合云架构是公有云与私有云的协同组合，承载不同负载和不同数据敏感级，形成统一的管理和编排。
关键要点：
- 多云驱动来自成本、可用性、合规、性能、地域和供应商谈判；架构设计必须明确业务目标，不能为了多云而多云。
- 资源调度统一通过多云管理平台 CMP 完成，覆盖资源编排、成本治理、身份权限、镜像分发和可观测。
- 数据层面采用分层存储与跨云复制，关键数据走加密链路，配合跨云对象存储和灾备方案。
- 网络通过专线、SD-WAN、跨云 VPC 对等和云交换平台打通，避免公网暴露和延迟抖动。
- 工作负载分发依据合规等级、性能敏感度和成本选择目标云，灾备与演练采用多云双活或多云灾备模式。

### 3. 边缘计算与云边协同
定义：边缘计算是把计算、存储、网络和分析能力下沉到靠近数据源或终端的位置，云边协同是通过统一编排让云中心和边缘节点形成一致的算力供给、模型分发和数据流转体系。
关键要点：
- 边缘形态包括现场边缘、机房边缘、城域边缘和设备边缘，按延迟、带宽与算力需求分级部署。
- 云边协同三件套是统一编排、统一镜像分发和统一可观测，KubeEdge、OpenYurt、SuperEdge 是典型开源项目。
- 数据分级处理在边缘做实时推断、过滤、聚合和异常检测，结果回传到云端做训练、对齐和长期存储。
- 网络要求低延迟、可预测和安全回传，5G、MEC 和工业现场总线为边缘互联提供基础。
- 挑战集中在资源受限、运维复杂、模型更新安全和边缘节点弱网容错，需要轻量化运行时和断网自治能力。

### 4. 可观测性与 SRE 工程实践
定义：可观测性是通过日志 Logging、指标 Metrics 和追踪 Tracing 三类数据理解系统内部状态并主动支撑排障与决策的能力；SRE 是把运维目标工程化和产品化的实践体系，关注稳定性、成本和效率的平衡。
关键要点：
- 三大支柱中日志记录事件，指标反映趋势，追踪串联调用链；三者结合才能形成完整可观测能力。
- 关键指标 RED 表示请求 Rate、Error、Duration，USE 表示资源 Utilization、Saturation、Errors，业务侧关注业务指标与转化漏斗。
- SLO、SLI 和 SLA 是稳定性目标的工程化表达，错误预算把稳定性与发布节奏直接挂钩。
- 告警分级按可行动性划分 P0 到 P3，配合值班响应 Runbook，避免告警疲劳。
- 故障复盘要写出 TimeLine、根因、临时处置、永久改进、跟踪人、验证标准，形成 Toil 减少与可靠性提升闭环。

### 5. 架构成本治理与 FinOps
定义：FinOps 是把财务责任引入云与平台工程的实践体系，通过用云可视化、单位度量、容量预测和优化行动，让架构决策同时考虑性能、可用性与成本。
关键要点：
- 三阶段分别是信息收集、分配归因、持续优化，配合责任矩阵让业务、工程和财务形成共同语言。
- 单位成本指标包括单位请求成本、单位用户成本、单位算力成本、单位存储成本，是架构对比的标尺。
- 优化手段覆盖资源规格、预留实例、Spot 实例、生命周期策略、自动停止、定时回收和架构瘦身。
- 标签治理是分配归因的基础，未打标签的资源等于隐藏成本，必须把标签纳入 CI/CD 强制门禁。
- 引入成本异常检测和预算预警，避免月度账单尾段才发现预算超支，结合可视化和审批形成治理闭环。

## 案例分析题
**题目**：某省级政务一网通办平台经过两年建设，已形成一云多芯混合云架构。平台承载 300 余项政务服务，日均调用量 4000 万次，省内 14 个地市通过省级大集中方式接入。下一阶段将开展三项关键演进：一是把核心交易链路从虚拟机迁移到 Kubernetes 容器化平台，并引入服务网格；二是面向地市提供云边协同的政务边缘节点，支撑基层政务外网与园区自助终端；三是把当前以人工经验为主的运维体系升级为基于可观测和 SRE 实践的统一运营中心。基础环境包括三个公有云专区、一个私有云、行业云接入以及省级政务外网和电子政务外网双平面。请从系统架构设计师角度回答：
1. 云原生演进应如何规划容器、服务网格与不可变基础设施的落地顺序；
2. 多云和混合云架构应如何通过统一身份、统一网络和统一可观测避免管治割裂；
3. 云边协同边缘节点如何选型，怎样实现镜像分发、数据回传和弱网自治；
4. 可观测与 SRE 应设计哪些核心能力，如何制定 SLO 和告警分级策略；
5. 在 FinOps 视角下，如何对外对接财政评审和业务部门，对内做成本分配和持续优化。

**参考答案**：
1. 云原生落地按四步走。第一步完成基础镜像仓库、CI/CD 流水线、命名规范和配置分离，把当前虚拟机上运行的中间件逐步镜像化和版本化。第二步接入 Kubernetes，搭建测试、预发和生产三套集群，按业务逐步纳管，先轻量级再核心链路的策略，先非实时模块再交易主链。第三步引入服务网格，灰度策略从非交易类接口开始验证路由、熔断、可观测和 mTLS 能力，再推广到交易链路。第四步推动不可变基础设施，所有变更通过镜像版本和配置实现，禁止线上 SSH 修改实例；建立 Operator 体系和 GitOps 流水线，让环境收敛到声明式。整个过程配套统一身份、统一可观测和统一日志，从一开始就解决管治割裂问题。
2. 多云与混合云的管治通过"四个统一"实现。统一身份对接政务统一身份认证和云 IAM，建立跨云账号、跨租户的最小权限模型，按 RBAC+ABAC 组合授权。统一网络依托政务双平面和 SD-WAN 打通公有云专区和私有云，重点业务走专线和云交换平台，避免公网暴露；统一规划地址段和 DNS，避免跨云调用时出现解析抖动。统一可观测汇聚多云监控、日志和追踪，使用统一标签和单位口径，把跨云的延迟、可用性和成本可比化。统一资源调度通过 CMP 多云管理平台对资源、镜像、密钥和合规做集中编排，灾备演练以跨云应用切换为目标，避免单机房绑定。
3. 云边协同边缘节点选型遵循三类指标。一是硬件指标，按场景选型为通用 X86、ARM 或嵌入式设备，覆盖园区自助机、基层政务外网终端和边缘网关；二是运行时，要支持轻量化 Kubernetes 发行版和断网自治能力，KubeEdge 或 OpenYurt 配合边缘 Agent 是常见选项；三是网络能力，要支持政务外网、电子政务外网双链路回传和本地缓存。镜像分发建立多级缓存和按需下发，结合版本标签和灰度策略，避免一次性大版本升级。数据回传分级处理，敏感数据经加密链路回传，原始数据在本地脱敏聚合后只传必要字段。弱网自治能力包括本地缓存、本地决策、降级运行、离线排队与回放，确保网络中断时业务不中断。
4. 可观测与 SRE 平台设计四个核心能力。统一采集对接三支柱，日志使用 Sidecar/Agent 采集，指标采用 Prometheus/OpenTelemetry 协议，追踪采用 OpenTelemetry 标准化埋点并贯穿前后端。统一存储按冷热分级，热数据秒级查询，温数据分钟级，冷数据归档。统一告警分级 P0 到 P3，对应业务影响、值班响应、Runbook、自动修复和事后复盘。SLO 设计按业务分级，核心办件链路可用性 99.95%、接口响应 P95 在 800 毫秒以下、错误率千分之五以内；非核心链路分级放宽。错误预算与发布节奏直接挂钩，预算耗尽时暂停新功能上线，集中做稳定性工作。复盘流程要写出时间线、根因、改进项、负责人和验证标准，避免"已读不回"型闭环。
5. FinOps 设计分成对外、对内两条主线。对外把单位成本指标（单位办件、单位用户调用、单位存储）输出给财政和业务部门，作为预算评审依据和绩效考核指标；同步输出月度账单和服务目录，让业务部门看到所用资源与成本。对内建立标签治理体系，按业务条线、地市、系统和环境打标，作为分配归因和共享成本分摊的依据。平台层面引入预留实例、Spot 实例、自动停止和生命周期策略，对存量资源做持续优化；引入异常检测和预算预警，把月度预算切分到周甚至天，并设置告警阈值。最后把 FinOps 接入架构评审和上线门禁，所有新应用必须给出单位成本估算和优化策略，让成本与架构决策同步。

**踩分要点**：
- 云原生演进要给出四步顺序、灰度策略和不可变基础设施，避免只说"容器化"和"上 Kubernetes"。
- 多云治理要点出四个统一、跨云灾备和地址段规划，并说明如何避免公网暴露。
- 云边协同要写清三类指标、镜像多级分发、弱网自治和双平面回传，不要写成"边缘计算降低延迟"的通用描述。
- 可观测要回答三支柱、SLO 数值、错误预算、告警分级和复盘闭环；错误预算挂钩发布节奏是加分项。
- FinOps 必须从对外和对内两条线回答，含标签治理、单位成本指标、预算预警和上线门禁，单写"节省成本"是不够的。

## 记忆口诀
云原生五要素：容器、服务网格、微服务、不可变、声明式。
容器化四件套：镜像仓库、CI/CD、K8s、可观测。
不可变三原则：镜像只读、版本一致、变更靠替换。
多云治理四统一：身份、网络、可观测、资源调度。
云边协同三件套：统一编排、镜像分发、统一可观测。
边缘选型三类指标：硬件、运行时、网络。
弱网自治四能力：本地缓存、本地决策、降级运行、回放对账。
可观测三支柱：日志、指标、追踪；RED + USE 业务指标。
SRE 三件套：SLI、SLO、错误预算；预算挂钩发布节奏。
告警分级四档：P0 到 P3，对应响应 Runbook 与值班。
复盘五要素：时间线、根因、改进、负责人、验证标准。
FinOps 三阶段：收集、归因、优化；标签治理是地基。
单位成本四指标：单位请求、单位用户、单位算力、单位存储。
成本优化六招：规格、预留、Spot、生命周期、自动停止、架构瘦身。
架构门禁三件事：性能、可用性、成本同时评审。
平台演进四步走：试点、纳管、灰度、生产；先非实时后核心链路。
