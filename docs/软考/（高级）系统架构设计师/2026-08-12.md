## 今日核心概念

### 1. 分布式系统一致性模型
定义：分布式系统一致性模型描述在多个节点并发操作、网络分区与时钟漂移条件下，数据副本与操作顺序所呈现的对外可见语义，是分布式架构设计的根本契约。
关键要点：
- 强一致性要求任何读都能看到最近一次写，但跨分区不可用时会出现可用性损失，典型实现是两阶段提交、Quorum 写入与共识协议。
- 弱一致性允许副本间短时间不一致，线性化与顺序一致性是中间形态，对应 Raft、Paxos 与 ZAB 协议。
- 最终一致性常用于多地域部署与异步复制，写后读、单调读、前缀读三类语义保证用户体验连续性。
- CAP 定理指出在分区存在时一致性与可用性不可兼得，PACELC 把延迟也纳入权衡；实际架构按业务分级选择一致性等级。
- 一致性算法选型要综合考虑节点规模、容错能力、吞吐、延迟与运维复杂度，避免算法过度工程化。

### 2. 微服务架构治理与服务设计
定义：微服务架构是把单体系统按业务边界拆分为自治服务集合的架构风格，治理体系围绕服务契约、流量管控、可观测与韧性展开，决定整体的可演进性。
关键要点：
- 服务拆分原则按业务能力、领域驱动和康威定律，避免按技术层拆分导致分布式单体。
- 服务契约优先采用 OpenAPI/gRPC/Protobuf，接口向后兼容，引入语义化版本和契约测试。
- 流量治理通过服务注册、负载均衡、限流、熔断、降级、超时与重试配合实现，服务网格是关键载体。
- 数据治理遵循每服务一库或同库多服务模式，跨服务访问通过事件或 API 编排，避免分布式事务泛滥。
- 可观测覆盖调用链追踪、统一日志、关键指标 RED，贯穿 CI/CD 与生产环境。

### 3. 高可用与容灾架构
定义：高可用与容灾架构是通过冗余、故障检测、流量切换和数据复制，使系统在组件失效与灾难场景下仍能提供可接受服务的工程体系。
关键要点：
- 高可用指标用 N 个 9 表示，对应年度停机时间和成本，常见等级是三到五个 9。
- 容灾等级分本地高可用、同城双活、两地三中心、异地多活与多云灾备，按 RTO 与 RPO 选择。
- 故障切换通过健康检查、流量调度、DNS 切流和数据库主备切换实现，演练常态化才能保证真实切换可靠。
- 数据复制方式有同步、半同步与异步，跨地域异步复制容忍 RPO 增大但成本低，同步复制代价高。
- 混沌工程通过主动注入故障验证韧性，定期演练覆盖网络、节点、依赖、可用性等维度。

### 4. 安全架构与零信任
定义：安全架构是面向身份、网络、数据、应用全栈设计的防护与治理能力，零信任把默认不信、持续验证、最小权限作为核心原则，重塑传统边界防护。
关键要点：
- 零信任三大原则是最小权限、持续验证、默认拒绝，结合微分段、设备态势和身份上下文做访问决策。
- 身份层统一 SSO、MFA、设备绑定与生命周期管理，结合 ABAC/RBAC 组合授权。
- 网络层通过微分段、零信任网络访问 ZTNA、SD-WAN 和 SASE 收敛访问路径，避免 VPN 暴露。
- 数据层加密覆盖静态、传输与使用中，配合数据分类分级、脱敏、水印和 DLP 能力。
- 应用层安全左移到开发阶段，引入 SAST、DAST、SCA、SBOM 与签名验证，把漏洞堵在发布前。

### 5. 架构评估方法与 ATAM
定义：架构评估方法是对候选架构在性能、可用性、安全、可维护性、成本等质量属性上进行系统化度量和权衡的工程实践，ATAM 是其中代表性方法。
关键要点：
- ATAM 流程包括描述业务动机、架构视图、质量属性场景分析、决策点和风险识别，最终输出权衡点与无风险结论。
- 质量属性场景必须可量化、可测量、可验证，包括刺激源、刺激、环境、响应、响应度量。
- 架构决策记录 ADR 是关键工具，把背景、决策、状态、后果结构化，便于团队理解与演进。
- 风险按技术、可用性、性能、安全、可维护性分类，非风险是已接受权衡，无风险是经验证结论。
- 评估应贯穿架构设计与重大变更阶段，避免一次性评审后束之高阁。

## 案例分析题
**题目**：某城市轨道交通集团计划建设新一代线网指挥中心系统，承担 12 条线路的运营调度、应急指挥、客流监测与乘客信息服务。系统日均处理列车运行计划调整指令约 8 万条、应急事件联动操作 1500 次，承载线路控制中心、车站、车辆段、应急指挥车与外部应急单位等多端接入。当前系统存在四个突出问题：一是核心调度指令依赖中心机房单点部署，曾因机房级故障触发全网调度中断；二是跨线路调度依赖人工经验，缺乏系统化的容灾切换与质量属性验证；三是移动应急接入缺少统一身份和最小权限管控，存在账号滥用和数据外泄风险；四是新业务上线周期长，架构决策缺少量化评估，重大变更常引发回退。请从系统架构设计师角度回答：
1. 分布式一致性与服务治理如何支撑高可用指挥中心，应采用何种一致性与容错组合；
2. 高可用与容灾架构应如何规划机房、网络、数据与服务四层冗余，RTO 与 RPO 如何设定；
3. 安全架构如何落地零信任，覆盖身份、网络、数据、应用四个层面；
4. 架构评估应建立哪些机制，如何用 ATAM 支撑关键决策；
5. 在多线路、多端接入与高频变更背景下，可观测与变更治理应如何设计。

**参考答案**：
1. 调度指令链路采用强一致性与可用性兼顾的组合。核心调度指令使用 Raft 共识与 Quorum 写入，保证指令不丢且顺序一致；非关键业务如客流统计、查询走最终一致性，配合读写分离与缓存降低延迟。服务治理通过服务网格实现路由、熔断、降级、超时、重试和 mTLS，把每条线路封装为独立命名空间；引入 API 网关做边缘路由、协议转换与流量染色。事件总线采用 Kafka 类消息中间件做异步解耦，关键事件做对账与幂等处理，避免重复执行；分布式事务优先采用 Saga 与本地事件表，避免两阶段提交阻塞主链路。
2. 高可用与容灾按四层冗余设计。机房层建立本地高可用集群加同城双活，跨机房部署 Kubernetes 多集群与数据库双主双备，网络层采用双平面双链路与负载均衡 DNS 切流。数据层按业务分级，关键调度数据同步复制，RPO 接近零；历史数据分析数据异步复制，RPO 在分钟级。服务层通过多活入口、多活网关和多活注册中心实现流量调度，结合蓝绿、灰度与有状态负载的会话保持。RTO 按业务分级，核心调度链路目标 5 分钟内恢复，乘客服务与查询类目标 30 分钟内恢复；混沌工程每月演练，覆盖节点、机房、网络、依赖与人为误操作五类场景，确保切换真实有效。
3. 零信任按四层落地。身份层统一 SSO 接入调度员、车站、应急人员、外部协同单位，配合 MFA、设备绑定和生命周期管理，按岗位授予 RBAC 加 ABAC 组合权限，敏感操作引入二次审批和操作审计。网络层用 ZTNA 替代 VPN，移动应急车通过 SASE 接入，按身份和设备态势动态授权；微分段按线路、控制中心、应急单位分区，限制横向移动。数据层按密级做分类分级，敏感数据加密存储、传输和脱敏展示，重要导出走审批和数字水印，应用层落实 DLP 与文件外发审计。应用层把 SAST、DAST、SCA、SBOM 和签名验证纳入 CI/CD 流水线，重大漏洞门禁，未通过不发布。
4. 架构评估建立三类机制。第一类是流程机制，关键架构决策走 ADR 模板，重大变更走 ATAM 评审，形成评估-决策-跟踪闭环。第二类是工具机制，引入质量属性场景库、风险登记册、权衡点矩阵，让评估从经验判断走向结构化分析。第三类是复盘机制，把重大故障、重大变更、灰度结果回灌到评估库，更新风险与决策。ATAM 应用要点：先明确业务动机与关键质量属性，再把场景拆解到可度量的刺激与响应度量，最后识别风险、非风险与权衡点，形成可追溯结论。例：调度指令低延迟与强一致性的取舍、高可用与成本的取舍、安全与运维复杂度的取舍，都必须输出 ADR。
5. 可观测与变更治理按统一平台设计。可观测建立日志、指标、追踪三支柱统一采集，按业务域和线路维度打标，调用链贯穿客户端、网关、服务、消息和数据库；RED 指标覆盖每条核心接口，USE 指标覆盖关键资源。告警分级 P0 到 P3，按业务影响和可行动性分级，配合 Runbook、自动修复和值班响应；错误预算与发布节奏挂钩，预算耗尽时暂停非紧急变更。变更治理把所有变更纳入 GitOps 与灰度发布，重要变更走金丝雀、A/B 测试和回滚预案，引入变更窗口和封网期；变更前后必须有可观测比对和验证清单，让变更结果可量化、可回滚、可复盘。

**踩分要点**：
- 一致性回答必须区分核心与非核心，匹配 Raft/Quorum 与最终一致，避免笼统说"高一致性"。
- 容灾回答要点出机房、网络、数据、服务四层冗余，给出 RTO/RPO 数值和混沌演练，避免只说"双活"。
- 零信任必须从身份、网络、数据、应用四层分别回答，含 MFA、ZTNA、SASE、SAST/DAST/SCA 等要点，不要写成"加强安全管理"。
- 架构评估要写明 ADR、ATAM 流程、质量属性场景和风险登记册，体现结构化评估而非经验式评审。
- 可观测与变更治理要把三支柱、错误预算、灰度发布和 GitOps 串起来，单写"日志监控"是不够的。

## 记忆口诀
一致性五形态：强、序、弱、最终、读后写。
共识三协议：Raft、Paxos、ZAB；Quorum 是底座。
微服务四治理：契约、流量、可观测、韧性。
服务拆分三原则：业务能力、领域驱动、康威定律。
跨服务两避免：分布式事务、共享库。
高可用四件套：冗余、检测、切换、演练。
容灾五等级：本地、同城、两地三中心、异地多活、多云。
数据复制三模式：同步、半同步、异步。
RTO RPO 分级：核心 5 分钟、查询 30 分钟。
零信任三原则：最小权限、持续验证、默认拒绝。
零信任四层落地：身份、网络、数据、应用。
身份三件套：SSO、MFA、生命周期。
网络两收敛：ZTNA 替代 VPN、SASE 收敛接入。
应用安全左移：SAST、DAST、SCA、SBOM、签名。
ATAM 五步走：业务动机、架构视图、场景分析、决策点、风险。
质量场景五要素：刺激源、刺激、环境、响应、响应度量。
ADR 四要素：背景、决策、状态、后果。
风险三分类：风险、非风险、无风险。
可观测三支柱：日志、指标、追踪；RED + USE。
告警分级四档：P0 到 P3，对应响应 Runbook。
错误预算挂钩发布节奏，预算耗尽暂停上线。
变更治理三件套：GitOps、灰度、回滚预案。
混沌工程五场景：节点、机房、网络、依赖、人为误操作。
