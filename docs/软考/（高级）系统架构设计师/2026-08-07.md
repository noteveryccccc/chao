## 今日核心概念

### 1. 混沌工程与韧性架构

定义：混沌工程是在生产环境中通过受控实验，主动注入故障、观测系统在异常条件下的行为表现，发现薄弱环节并持续改进，使系统具备可预期的韧性。

关键要点：
- 韧性架构强调在不牺牲业务的前提下承受故障，常见韧性模式有冗余、降级、隔离、超时、重试、熔断、限流和故障转移。
- 混沌工程四大原则是建立稳态假设、围绕真实业务场景设计实验、最小爆炸半径、生产环境演练。
- 常用工具 ChaosBlade、Chaos Monkey、Gremlin、Litmus、Chaos Mesh 分别针对主机、Kubernetes 与多环境，覆盖进程、容器、网络、磁盘和可用区级别故障。
- 实验成熟度按演练环境划分，先在预发做大规模演练，再逐步扩大到生产灰度；按故障域划分，先注入单实例故障，再扩展到可用区、网络和数据库。
- 演练前必须有熔断开关、回滚预案和应急联系人；演练中通过监控实时观察，并能在任意时刻一键终止；演练后进行复盘、完善 Runbook 并沉淀改进项。

### 2. 数字孪生与城市信息模型 CIM

定义：数字孪生是物理实体与数字模型之间通过数据采集、模型映射、双向控制和智能分析形成的闭环系统，使虚拟空间始终与现实世界保持同步；CIM 是面向城市对象的数字孪生，把建筑、道路、地下管网、园区与人口、事件、运行状态叠加在同一空间底座上。

关键要点：
- 数字孪生五要素是物理实体、虚拟模型、数据连接、双向交互和应用服务，五要素缺一不可；没有双向控制的数字孪生只是三维可视化。
- 城市级 CIM 一般采用 GIS 二三维底座 + BIM 精细模型 + IoT 实时感知 + 业务专题数据，融合 BIM 与 GIS 的 CIM 平台常用 Cesium、Three.js、Unreal TwinCity、CityGML。
- 数据层需建立统一的时空编码、空间索引、坐标转换和投影转换能力；高精度地图和倾斜摄影需考虑切片、压缩与按需下发。
- 场景化应用包括园区可视、应急推演、规划评审、施工模拟、能耗优化、客流预测和应急疏散，要求模型可在时间维度滚动运行。
- 数字孪生项目最容易踩坑的是数据采集不全、模型与业务脱节、性能开销大和缺乏运营机制，必须把治理与运营同步建设。

### 3. 绿色计算与可持续架构

定义：绿色计算是指在全生命周期内通过架构选择、资源调度、能效管理和碳排放度量，使计算系统在满足业务目标的前提下降低能耗和碳足迹，实现可持续运行。

关键要点：
- 关键指标包括 PUE、CUE、WUE、IUE 与单业务 PUE，分别衡量数据中心电力、水、网络和空间使用效率；单位业务碳强度是业务侧衡量指标。
- 架构层面常用手段有冷热分层、混部、弹性伸缩、自动休眠、液冷与浸没冷却、机房选址靠近能源与冷源、超大规模集群与高密度部署。
- 应用层通过降采样、特征复用、近似计算、离线批处理合并、潮汐调度和 AI 推理加速，在不显著影响业务的前提下降低算力消耗。
- 用云阶段要建立 FinOps 体系，对账单、标签、容量和碳足迹做持续度量；通过优化区域、优化实例类型、关闭空闲资源和使用 Spot 实例降低能耗与成本。
- 国家与行业合规要求包括数据中心能耗指标、碳排放核算与披露、产品全生命周期评价，绿色架构要在合规要求之上建立量化目标。

### 4. AI 原生架构与 LLMOps

定义：AI 原生架构是面向大模型应用场景，将推理服务、知识增强、上下文工程、可观测与评估体系纳入架构主线的一类新架构形态；LLMOps 是对大模型训练、微调、提示工程、评测、上线和运行进行全生命周期管理的方法与平台。

关键要点：
- AI 原生应用典型形态有对话问答、内容生成、智能检索、Agent 编排与垂直专家系统，对应技术栈涉及向量库、提示工程、检索增强生成、工具调用、Agent 框架与推理加速。
- 检索增强生成 RAG 的关键链路是文档接入、切分、向量化、索引、召回、重排、提示组装、生成与评估；切分粒度和重排模型显著影响效果。
- LLM 推理性能与成本涉及 KV Cache、量化、Continuous Batching、Speculative Decoding、PagedAttention 与多 GPU 推理框架，常见框架 vLLM、TGI、TensorRT-LLM、SGLang 与 LMDeploy。
- LLMOps 需要的能力包括数据集与版本管理、提示词库与模板、评测集与自动评测、人机反馈对齐、安全过滤、A/B 实验和灰度发布。
- 风险控制必须包含越狱防御、提示注入防护、敏感信息过滤、输出合规审计、可追溯日志和回退通道，避免模型能力成为失控面。

### 5. 区块链与可信分布式架构

定义：区块链是一种以区块为基本单元、以链式结构与共识机制保证数据不可篡改、可追溯的分布式账本技术；可信分布式架构结合区块链、隐私计算、可信硬件和审计机制，构建多方参与的、不可抵赖的数据协作环境。

关键要点：
- 区块链三大形态是公有链、联盟链和私有链，联盟链是企业级最常用形态，常见平台 Hyperledger Fabric、FISCO BCOS、长安链、蚂蚁链。
- 核心要素包括区块结构、Merkle 树、共识机制 PoW/PoB/PoS/PBFT、智能合约、链上链下协同、身份与证书体系。
- 隐私计算与区块链互补，常见组合有多方安全计算 MPC、可信执行环境 TEE、联邦学习与零知识证明 ZKP，用于解决数据可用不可见和合规审计问题。
- 架构关键能力包括链节点治理、跨链互通、链上链下协同、合约安全审计、密钥治理和监管接口，单独看链是不够的。
- 典型应用场景有政务数据共享、招投标存证、供应链溯源、电子凭证、司法存证和跨境结算，需要结合业务重新设计账本模型。

## 案例分析题

**题目**：某省级"双碳"与城市治理一体化平台需在一年内完成建设，要求支撑三类核心场景：一是城市级能源与碳排放监测，覆盖园区、企业、重点设备；二是城市信息模型 CIM 试点，对核心城区建筑、道路、管网进行三维可视与应急推演；三是引入大模型能力，把政策、事件、报告、城市运行数据整合，提供智能问答、办事助手和应急辅助决策。基础环境包括政务云、私有算力、政务数据共享平台和数字孪生底座。请从系统架构设计师角度回答：

1. 韧性架构层面，应如何在双活机房、跨可用区和混沌工程之间规划能力建设顺序；
2. 绿色计算层面，针对冷热数据、推理算力与业务高峰应采取哪些具体优化措施；
3. 数字孪生层 CIM 与数字孪生五要素如何落地，需避免哪些常见误区；
4. AI 原生与 LLMOps 应如何设计平台架构以支撑三种模型应用形态；
5. 在合规与可信协作层面，区块链、可信硬件和隐私计算如何组合支撑政务数据共享。

**参考答案**：
1. 韧性架构分四阶段建设。第一阶段完成同城双活核心系统切换演练，覆盖数据库、消息和应用层，使用混沌工程工具 ChaosBlade 在预发注入单实例故障，验证熔断、限流、降级和回退链路。第二阶段扩展到跨可用区故障注入，验证流量调度和负载均衡策略。第三阶段在生产灰度环境演练计划性中断和依赖项抖动，验证 Runbook 与值班响应流程。第四阶段引入 GameDay 演练，由跨团队统一故障剧本，演练跨部门协同能力。每阶段都建立爆炸半径、回滚预案、值班联系人和稳态指标，确保可随时终止并恢复。
2. 绿色计算围绕五条主线。冷热分层把原始明细放在对象存储与冷归档，分析数据放在 SSD 热池，应用查询走 CDN 缓存；存储采用分层纠删码和生命周期策略。混部将大模型离线推理、训练任务、在线推理错峰运行，把资源利用率从低水位提升到中等水位。弹性伸缩按业务曲线提前扩缩容，空闲时段自动休眠推理服务。机房选址靠近电网与冷源，机房内部引入液冷和高密度部署降低 PUE。最后建立 FinOps 看板，按业务域度电、度算力与单位碳强度，把减碳指标纳入考核与上线门禁。
3. 数字孪生按五要素落地。物理实体对接城市管网 IoT 数据、建筑 BIM 设施和政务业务事件流，确保数据来源闭环；虚拟模型分三层构建，宏观采用 GIS 倾斜摄影底座，中观采用 CIM 精细模型，微观采用重点设施 BIM 模型；数据连接通过时空数据库、空间引擎和事件流把物理世界和模型缝合；双向交互先从感知和可视化入手，逐步接入控制和应急指令；应用服务聚焦能源监测、能耗告警、应急推演、规划评审和辅助决策。每条业务线都必须配置运营责任人，避免建成可视化大屏。同时要避免三个常见误区：一是只做可视化不做控制；二是模型与业务脱节；三是数据来源不全、模型更新频率低。
4. AI 原生平台按三层设计。基础设施层对接 GPU 资源池，提供推理框架 vLLM、TGI 和训练框架，并支持 Continuous Batching、量化和 KV Cache 优化。能力中台层提供数据集与版本管理、提示词库、向量库与索引、检索召回与重排、Agent 编排、智能体工具市场和评测平台。应用层针对智能问答、办事助手、应急辅助决策三类场景分别构建 RAG 链路、Agent 链路和工具调用链路，并设置对话记忆、上下文工程、个性化和权限策略。LLMOps 配套自动评测、人机反馈、A/B 实验、灰度发布、敏感词过滤和审计日志。所有上线必须经过红队演练和 PII 合规检查。
5. 合规与可信协作采用组合方案。数据共享清单与目录使用区块链存证，记录目录变更、授权审批和数据调用流水，形成不可篡改的审计证据；多方数据联合计算使用隐私计算平台，敏感计算放入可信执行环境或多方安全计算节点，原始数据不出域；监管侧通过监管链节点和只读接口获取关键事件和计算结果摘要。机制上配套五项能力：统一的身份与证书服务、关键操作的数字签名、跨域授权审批和撤销机制、链上链下对账、可信硬件接入。避免只为了区块链而区块链，所有上链数据必须明确业务目的。

**踩分要点**：
- 韧性架构要点出四阶段、双活先行、混沌工程、爆炸半径、Runbook 与 GameDay，不能只说"做混沌工程"。
- 绿色计算要覆盖冷热分层、混部、弹性、机房选址与 FinOps 度量五个角度，给出可量化指标 PUE 和单位碳强度。
- 数字孪生必须按五要素逐条回答，避免只写三维可视化；风险点至少说明没有运营、可视化大屏化、模型不闭环三类。
- AI 原生要写出 LLMOps 全链路数据集、提示词、向量库、评测、灰度、安全过滤与红队演练，针对三类场景给出差异化架构。
- 区块链与隐私计算必须组合回答，明确什么数据上链、什么计算放 TEE、什么调用走授权审批，并强调链上链下对账和监管接口。

## 记忆口诀

混沌工程四字诀：稳态假设、小爆炸半径、生产演练、持续改进。
韧性模式三件套：冗余 + 降级 + 隔离；再配超时重试熔断限流。
数字孪生五要素：实体、模型、双向、数据、应用；缺一要素变可视化。
CIM 三层模型：宏观 GIS + 中观 CIM + 微观 BIM；时空编码是底座。
绿色计算五指标：PUE + CUE + WUE + IUE + 单位碳强度；冷热分层 + 混部 + 弹性 + 液冷 + FinOps。
LLMOps 七步走：数据集、提示词、向量库、评测、灰度、过滤、复盘。
RAG 五环节：切分、向量化、索引、召回、重排；提示组装与评估不可少。
推理性能四利器：KV Cache + 量化 + Continuous Batching + 推测解码。
区块链三形态：公有链、联盟链、私有链；联盟链是企业级主战场。
可信协作四组合：链上存证 + 链下计算 + TEE/MPC + 监管只读；数据可用不可见。
