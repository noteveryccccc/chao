## 今日核心概念
### 1. 可观测性三大支柱
定义：可观测性(Observability)通过系统外部输出推断内部状态的能力，区别于传统监控的"已知未知"，解决"未知未知"问题；三大支柱分别是日志(Logging-离散事件记录)、指标(Metrics-聚合数值时序)、链路追踪(Tracing-请求级因果)；CNCF统一标准OpenTelemetry(OTel)整合三大支柱数据模型。
关键要点：
1. 日志三级别ERROR/WARN/INFO+结构化JSON日志+TraceID串联；ELK/EFK栈(Elasticsearch+Fluentd+Kibana)集中存储
2. 指标四类型Counter(单调递增)/Gauge(瞬时值)/Histogram(分布)/Summary(分位数)；Prometheus+AlertManager+Grafana标准组合
3. 链路追踪Dapper论文衍生：Span(操作单元)+Trace(完整调用链)+Context传播(TraceID/SpanID/Baggage)；OpenTelemetry SDK+Jaeger/Zipkin/SkyWalking后端
4. RED指标(请求Rate/错误Error/延迟Duration)与USE指标(Utilization/Saturation/Errors)分别面向服务与资源
5. SRE实践SLO(服务等级目标)+错误预算(Error Budget)+告警分级(严重/警告/信息)；AIOps异常检测与根因分析

### 2. 分布式事务解决方案
定义：分布式事务(Distributed Transaction)在跨服务/跨数据库场景下保证数据一致性的机制；强一致方案2PC(两阶段提交)/3PC(三阶段提交)；最终一致方案TCC/Saga/AT/本地消息表/Outbox/MQ事务消息；遵循CAP定理在一致性与可用性间取舍。
关键要点：
1. 2PC两阶段：Prepare(预提交/锁资源)+Commit/Rollback(协调者决策)；缺点同步阻塞/单点故障/数据不一致窗口；Seata/XA协议实现
2. TCC三阶段：Try(预留资源/幂等检查)+Confirm(确认/幂等)+Cancel(释放/幂等)；并发度高但开发侵入性强，需幂等防悬挂
3. Saga长事务拆分N个子事务，每子事务有补偿操作；编排式(Orchestration中央协调器)与协调式(Choreography事件驱动)
4. AT模式(Automatic Transaction)Seata主推，基于快照+undo log自动生成反向SQL，介于2PC与TCC之间
5. 本地消息表+定时扫描+MQ投递实现最终一致；Outbox模式事件表+CDC(Canal/Debezium)+MQ；事务消息(RocketMQ/Kafka Exactly-Once)
6. 最大努力通知+对账补偿兜底；幂等设计三件套：唯一ID+状态机+去重表

### 3. 安全架构与纵深防御
定义：安全架构(Security Architecture)在系统全层级构建防御能力以抵御威胁的体系；纵深防御(Defense in Depth)多层异构防护，不依赖单一防线；零信任(Zero Trust)"永不信任，持续验证"取代传统边界防御。
关键要点：
1. 加密三件套：对称加密(AES-256/SM4高性能+数据加密)、非对称加密(RSA/ECC/SM2密钥交换+签名)、哈希算法(SHA-256/SM3完整性+密码存储bcrypt/Argon2)
2. 认证四要素：密码(知识)+令牌(拥有)+生物特征(特征)+行为分析(位置/设备)；多因素认证MFA组合至少两要素
3. 授权三模型：RBAC(基于角色)、ABAC(基于属性)、ReBAC(基于关系)；OAuth 2.0授权框架+OpenID Connect身份层+JWT令牌
4. 纵深五层：网络层(WAF/DDoS防护/VPC隔离)+主机层(主机入侵检测/漏洞扫描)+应用层(SQL注入/XSS/CSRF防护)+数据层(加密存储/脱敏/水印)+审计层(操作日志/合规追溯)
5. 零信任三大原则：最小权限+持续验证+假定失陷；SDP软件定义边界+ZTNA零信任网络访问+PAM特权访问管理+KMS密钥管理
6. 国产化密码SM2/SM3/SM4/SM9；等保2.0五级(用户自主/审计/标记/结构化/验证)；数据安全法+个保法+网络安全法三法合规

### 4. 性能评估与Amdahl定律
定义：性能评估(Performance Evaluation)通过定量方法测量系统处理能力的技术；核心指标吞吐量(Throughput)/响应时间(RT)/并发数(Concurrency)/资源利用率(Utilization)；Amdahl定律量化并行加速比的理论上限。
关键要点：
1. 性能三指标：TPS(每秒事务数)+QPS(每秒请求数)+RT(响应时间，含平均/中位数P50/P95/P99/P999分位数)
2. 性能测试五型：基准测试(单用户基线)+负载测试(逐步加压)+压力测试(超过设计极限)+容量测试(确定阈值)+稳定性测试(长时间运行)
3. JMeter/Gatling/k6/Tsung工具链；监控APM(SkyWalking/Pinpoint)+Profiler(火焰图async-profiler)+GC日志分析
4. Amdahl定律：S=1/((1-P)+P/N)，P为并行比例N为处理器数；串行部分成为加速瓶颈
5. 性能优化四象限：CPU密集(算法优化+并行计算)/IO密集(异步+缓存+连接池)/内存(JVM调优+对象池)/网络(压缩+CDN+长连接)
6. 利特尔定律(Little's Law)：L=λ×W，并发数=到达率×平均等待时间；用于容量规划与队列分析

### 5. API网关与服务网格
定义：API网关(API Gateway)作为微服务统一入口处理路由/聚合/鉴权/限流的中间层；服务网格(Service Mesh)将服务间通信从应用层剥离到基础设施层的Sidecar代理；二者共同解决东西向与南北向流量治理。
关键要点：
1. API网关核心能力：路由转发(路径/Header权重)+协议转换(HTTP/gRPC/WebSocket)+认证鉴权(OAuth2/JWT)+限流熔断(Sentinel)+聚合编排(BFF层)+日志审计
2. 网关演进四代：硬负载(F5)+软负载(Nginx)+微服务网关(Spring Cloud Gateway/Kong/Zuul)+云原生网关(Envoy/APISIX/Traefik)
3. 服务网格Sidecar模式：业务容器+Envoy代理同Pod部署；控制面(Istio Control Plane)+数据面(Istio Data Plane)分离
4. Istio核心组件：Pilot(配置分发)+Citadel(安全证书)+Galley(配置校验)+Mixer(策略+遥测，已废弃)；新架构istiod单体控制面
5. 网格四能力：流量管理(蓝绿/金丝雀/熔断/重试)+安全(mTLS双向认证+RBAC)+可观测性(指标/日志/追踪)+策略(配额/黑白名单)
6. API网关vs服务网格：网关管南北向(入口)，网格管东西向(服务间)；网关在网络边界，网格在Pod边界；可叠加使用网关+网格组合

## 案例分析题
**题目**：某商业银行分布式核心系统2025年完成微服务化改造，账户/存款/贷款/支付/账务5大服务，日均交易8000万笔，峰值3万QPS，可用性99.99%；技术栈Spring Cloud+K8s+Istio+MySQL分库分表+Redis集群+RocketMQ。近期出现以下问题：①跨服务转账偶发数据不一致(账户扣款成功但存款入账失败)；②某次促销支付链路RT P99从200ms飙升至3秒；③外部攻击者暴力破解网银登录接口。问：
1. 针对跨服务转账数据不一致，请设计分布式事务方案
2. 支付链路RT飙升至3秒，请给出可观测性定位与优化方案
3. 网银接口被暴力破解，请设计纵深防御安全架构
4. 系统计划支撑日均1.5亿笔交易，请用利特尔定律和Amdahl定律做容量评估

**参考答案**：
1. 分布式事务方案：
   - 业务场景拆解：转账=账户扣款+存款入账+账务记录，强一致要求
   - 选型Seata AT模式：业务无侵入自动生成前后快照+undo log，Seata TC(协调者)+TM/RM角色
   - 三步流程：①TM开启全局事务生成XID；②RM分支注册执行业务SQL自动生成前后镜像；③TM根据全局结果提交或回滚
   - 兜底机制：本地消息表+定时扫描对账+差异补偿；幂等设计全局唯一转账单号+状态机(todo/doing/done/failed)+去重表
   - 热点账户优化：账户余额分片(用户ID取模分10片)减少单库压力；异步入账(预扣+确认两阶段)降低RT
   - 一致性监控：TCC链路监控+悬挂/空回滚检测+超时熔断自动转人工
2. 可观测性定位与优化：
   - 链路追踪SkyWalking：TraceID串联入口网关→支付→风控→账户→账务，定位慢在哪个Span
   - 定位手段：①APM看调用链瀑布图找出RT最长Span；②Prometheus查服务/实例QPS+RT+错误率；③日志检索TraceID串联ERROR日志
   - 优化策略：①Redis缓存热点账户余额(MGET批量+本地Caffeine二级缓存)RT降至5ms；②RocketMQ异步化非关键链路(账务记录+对账)；③MySQL慢SQL优化加索引+读写分离+分库分表；④JVM调优G1+堆内存16G+GC日志分析；⑤Istio熔断配置+超时控制(支付800ms/账户500ms)
   - 性能基线：P99<200ms、P95<100ms、P50<50ms；容量评估日均1.5亿=峰值5万QPS
3. 纵深防御安全架构：
   - 网络层：WAF(Web应用防火墙)防SQL注入/XSS/CSRF；DDoS高防IP清洗；VPC隔离+安全组最小开放
   - 接入层：网银API网关统一鉴权OAuth2+JWT令牌；RateLimiter每用户5次/分钟+每IP 20次/分钟；异常IP自动封禁入黑名单
   - 应用层：密码bcrypt(强度12)+MFA短信/指纹二次验证；登录失败5次锁定30分钟；图形验证码防机器人；设备指纹+行为分析风控
   - 数据层：账户密码AES-256加密存储；身份证/银行卡SM4加密+脱敏展示；KMS密钥管理服务定期轮转
   - 审计层：登录日志+操作日志+审计日志三件套，合规保存5年；SOC安全运营中心7×24实时告警
   - 零信任升级：假定网络已失陷，每请求mTLS双向认证+RBAC动态授权+持续信任评估(设备/位置/行为)
4. 容量评估：
   - 利特尔定律：当前L=λ×W=3万QPS×0.2s=6000并发连接；目标日均1.5亿/86400秒≈1736 TPS，平均RT若0.2秒，并发=1736×0.2≈347，峰值按3倍=约1040并发
   - Amdahl定律：设并行化比例P=0.9(90%可并行)，处理器从16核扩到32核：S=1/(0.1+0.9/32)=1/(0.1+0.028)=7.8倍；串行10%成为瓶颈
   - 优化方向：①减少串行比例(同步改异步+无状态化)提升P至0.95；②垂直扩展先(CPU/内存升级)再水平扩展；③热点账户余额分片+缓存降低DB压力
   - 容量规划：数据库连接池HikariCP按并发数1.2倍配置；Redis分片16节点单分片5万QPS；RocketMQ 4节点8 Broker

**踩分要点**：
1. 分布式事务需说明方案选型理由与幂等设计(2分)
2. 可观测性需给出具体定位工具与优化策略(2分)
3. 安全架构需分层设计每层具体防护手段(2分)
4. 容量评估需公式计算+串行瓶颈分析与扩容建议(2分)
5. 综合方案需结合微服务+网格+云原生技术栈(2分)
