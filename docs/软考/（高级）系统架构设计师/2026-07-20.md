## 今日核心概念
### 1. 云原生安全与零信任架构
定义：以"永不信任，持续验证"为核心思想，将传统边界防御转为基于身份、设备、行为上下文的细粒度访问控制，覆盖网络、身份、应用、数据全链路的云原生安全体系。
关键要点：
- 三大支柱：身份认证（IAM）、设备可信（Posture）、最小权限（Least Privilege）
- SPIFFE/SPIRE：工作负载身份标准，通过SVID签发加密身份，解决跨云跨集群服务身份互通
- mTLS双向认证：Service Mesh边车代理自动签发证书，服务间通信全程加密
- 微隔离（Micro Segmentation）：按命名空间、Pod标签、网络策略（NetworkPolicy）划分安全域
- 与传统安全对比：从"城堡护城河"到"零信任网格"，每个调用都需验证

### 2. 可观测性三大支柱与SLO实践
定义：通过指标（Metrics）、日志（Logs）、追踪（Traces）三种数据维度全面刻画系统运行状态，结合服务等级目标（SLO/SLI/SLA）实现从被动告警到主动保障的可观测能力体系。
关键要点：
- Metrics四类：Counter计数器、Gauge仪表盘、Histogram直方图、Summary摘要
- Logs结构化：JSON格式输出，统一字段（timestamp/level/trace_id/span_id）
- Traces链路追踪：Trace树形结构、Span节点、TraceContext跨进程传递
- SLI（指标）→ SLO（目标值）→ SLA（商业承诺）三级体系：99.9% / 99.99% / 99.999%
- 错误预算（Error Budget）：用可用性余量驱动发布决策，预算耗尽则冻结上线

### 3. 数据架构与湖仓一体
定义：融合数据湖（多元原始数据存储）与数据仓库（强Schema分析能力）优势的新型数据管理范式，通过统一元数据与开放存储格式支持批流一体、BI与AI协同的数据基础设施。
关键要点：
- 数据湖三特性：存算分离（OSS/HDFS）、Schema-on-Read、半结构化友好
- 数据仓库三特性：Schema-on-Write、ACID事务、高性能SQL查询
- 湖仓一体代表：Iceberg / Hudi / Delta Lake 三种开源表格式
- 分层架构：ODS原始层 → DWD明细层 → DWS汇总层 → ADS应用层 → DIM维表层
- 与传统数仓对比：T+1离线 → 实时入湖（Kafka+Flink），成本降60%以上

### 4. 边缘计算与云边端协同
定义：将计算、存储、网络资源从中心云下沉到网络边缘侧，在靠近数据源位置提供低延迟、高带宽、本地自治的计算服务，与中心云形成"云-边-端"三级协同架构。
关键要点：
- 三层架构：端设备（IoT/移动）→ 边缘节点（MEC/边缘网关）→ 中心云
- 典型场景：自动驾驶（10ms内决策）、工业控制（1ms实时）、AR/VR（<20ms延迟）
- 关键技术：KubeEdge、OpenYurt、EdgeX Foundry 三大开源框架
- 边缘自治：网络断开时本地继续运行，云边重连后状态同步（最终一致）
- 与5G结合：MEC（Multi-access Edge Computing）UPF下沉至基站侧

### 5. 架构演进与遗留系统现代化
定义：通过对存量遗留系统进行渐进式重构、绞杀者替换、抽象封装等手段，使其逐步适配云原生、微服务化要求的架构演进方法论，避免推倒重来的高风险与高成本。
关键要点：
- 绞杀者模式（Strangler Fig）：新旧系统并存，新请求路由到新服务，逐步替换老功能
- 修缮者模式（Repairer）：保留主干，局部模块逐一重写，适合代码质量尚可场景
- 立法者模式（Legislator）：通过统一规范（API网关/事件契约）约束新旧系统交互
- 数据迁移三策略：双写（Dual Write）、影子流量（Shadow Traffic）、回滚预案
- 评估四维度：业务价值、技术债、改造风险、投入产出比（ROI）

## 案例分析题
**题目**：
某大型制造企业计划将传统MES（制造执行系统）进行云原生改造，现状如下：核心业务为车间生产调度与设备数据采集，日均处理工单50万、设备点位100万、实时数据上报峰值20万TPS；旧系统为单体Java应用部署在物理机，数据库为Oracle RAC；要求改造后支持多工厂接入、边缘设备断网时本地继续运行、生产数据实时入湖供AI质检模型训练；运维团队30人，无Kubernetes经验。请设计云边端协同架构方案，说明关键技术选型，并指出实施过程中的最大风险与应对措施。

**参考答案**：
一、整体架构（三级分层）
1. 端层：PLC/CNC/传感器 → OPC UA协议采集 → IoT边缘网关
2. 边缘层：工厂车间部署KubeEdge集群（5-10节点），承载实时控制与本地自治
3. 云端层：阿里云/华为云Region级K8s集群，承载MES核心业务与AI训练

二、关键技术选型
- 边缘框架：KubeEdge（云边通信、边缘自治、CRD扩展成熟）
- 消息总线：Kafka集群，云边链路通过专线+MQTT桥接
- 数据采集：EMQX（百万级并发连接）+ Flink实时计算
- 数据湖：Iceberg on OSS + Flink CDC入湖，Hive Metastore统一元数据
- AI训练：TensorFlow/PyTorch on K8s，GPU池化（vGPU/MIG）
- 可观测：Prometheus + Grafana + Loki + Jaeger + AlertManager
- 安全：零信任架构SPIFFE身份、Istio mTLS、Vault密钥管理

三、实施路径（绞杀者+立法者组合）
- 阶段1：新建AI质检模块（独立部署），通过Kafka消费设备数据
- 阶段2：抽取工单管理、设备OEE等子域为微服务，与老系统API网关共存
- 阶段3：迁移数据库至PolarDB（兼容Oracle），双写3-6个月后切流
- 阶段4：老系统下线，新系统全量运行

四、团队与运维
- 引入SRE体系，建立GitOps发布流水线（ArgoCD）
- 培训计划：K8s基础（CKA）+ Linux内核 + Service Mesh实战，3个月内完成骨干培训

**踩分要点**：
- 云边端三级分层清晰（5分）
- 边缘自治KubeEdge+Kafka桥接选型合理（4分）
- 绞杀者+立法者迁移策略分阶段落地（4分）
- 数据湖Iceberg+Flink CDC实时入湖路径（3分）
- 零信任+mTLS+Vault安全体系完整（2分）
- 团队转型与GitOps运维保障（2分）
