## 今日核心概念
### 1. 软件架构评估方法
定义：在架构设计完成后、编码实现前，通过系统化方法对架构方案进行质量属性（性能、可用性、可修改性、安全性等）的验证与权衡，识别架构风险、敏感点、权衡点。
关键要点：
- 三大主流方法：SAAM（场景驱动，最早）、ATAM（架构权衡分析法，最常用）、CBAM（成本效益分析法，量化决策）
- 评估核心思想：以质量属性场景（用例）为驱动，让利益相关方参与
- 评估输出：架构决策、风险点、非风险点、敏感点、权衡点
- 适用阶段：ATAM 适用于架构设计早期；CBAM 适用于已确定架构但需多方案选优时

### 2. ATAM（架构权衡分析法）
定义：基于质量属性效用树，对架构进行多质量属性综合评估，揭示风险与权衡点，由 SEI（卡耐基梅隆软件工程研究所）提出。
关键要点：
- 评估流程九步：描述 ATAM 方法、描述业务动机、描述架构、确定质量属性目标→生成质量属性效用树→分析架构方法→分析质量属性→识别风险点与非风险点→讨论结果→生成评估报告
- 核心产出物：质量属性效用树（树根：质量属性；中间层：属性细分；树叶：具体场景）
- 关键术语：风险点（可能导致质量不达标的架构决策）、敏感点（某质量属性对某参数敏感）、权衡点（影响多个质量属性的参数）
- 参与角色：评估小组、项目决策者、架构师、开发人员、用户代表

### 3. CBAM（成本效益分析法）
定义：ATAM 的延伸，将架构决策与业务目标、成本、收益挂钩，对多个可行架构方案进行量化比较，辅助投资决策。
关键要点：
- 核心模型：CBAM = 决策 + 成本 + 效益 + 折现现金流（NPV）
- 评估流程：建立场景集合→对每个方案估算成本与收益→计算期望效用→选择净收益最大方案
- 输出：投资回报率（ROI）、净现值（NPV）、优先级排序
- 与 ATAM 区别：ATAM 关注"架构是否合理"，CBAM 关注"哪个方案最值得投入"

### 4. SAAM（场景架构分析法）
定义：最早的场景化架构评估方法，通过分析用例场景对架构的影响，评估架构对需求的覆盖度与冲突情况。
关键要点：
- 评估流程：定义场景→描述架构→场景分类（直接/间接/不支持）→评估场景交互→生成评估结论
- 核心能力：发现架构中隐含的交互冲突，识别架构待改进点
- 局限性：仅关注可修改性、可靠性等少数质量属性，无显式效用树，对权衡分析能力弱
- 适用场景：小型系统、架构早期快速评估、需求变更影响分析

### 5. 质量属性效用树
定义：ATAM 评估的核心工具，将抽象的质量属性逐层分解为可度量的具体场景，形成树状结构，用于系统化分析架构质量。
关键要点：
- 结构层级：根（质量属性）→ 一级属性（性能/可用性/可修改性/安全性）→ 二级属性（响应时间/吞吐量/MTTF 等）→ 叶子（具体场景）
- 场景描述六要素：刺激源、刺激、环境、响应、响应度量、构件
- 优先级排序：高优先级场景（必须满足）→ 中优先级（重要）→ 低优先级（次要）
- 关键作用：作为评估小组与利益相关方沟通的共同语言，避免歧义

## 案例分析题
**题目**：
某电商系统计划进行架构升级，候选方案 A（微服务架构）和 B（单体架构）。系统关注三个关键质量属性：① 订单峰值并发下响应时间≤2 秒；② 系统可用率≥99.99%；③ 支持快速上线新促销活动功能。架构师采用 ATAM+CBAM 联合评估，ATAM 阶段识别出"服务拆分粒度"是权衡点（影响可用性与可修改性），"数据库连接池大小"是敏感点（仅影响性能）。CBAM 阶段估算方案 A 成本 800 万、收益（年化）650 万；方案 B 成本 300 万、收益 280 万，假设 5 年生命周期，贴现率 10%。
问题：
1. 画出针对三个质量属性的效用树（至少到叶子场景）。
2. 说明"权衡点"与"敏感点"的区别，并分析"服务拆分粒度"为何是权衡点。
3. 计算两方案的 NPV 净现值（按 5 年计算，PV 系数：1/1.1、1/1.21、1/1.331、1/1.4641、1/1.6105），并基于 NPV 给出选型建议。

**参考答案**：
1. 效用树结构：
   - 性能
     - 峰值响应时间
       - 场景：双 11 促销 10000 并发下单→平均响应时间≤2 秒
   - 可用性
     - 系统可用率
       - 场景：单实例故障→30 秒内自动切换，系统可用率≥99.99%
   - 可修改性
     - 促销功能上线
       - 场景：新增满减活动→1 周内上线且不影响主流程

2. 权衡点 vs 敏感点：
   - 敏感点：只影响一个质量属性的参数（例：数据库连接池大小只影响性能）
   - 权衡点：同时影响多个质量属性且互相制约的参数（例：服务拆得越细，可修改性越好但可用性越难保证、分布式事务复杂）
   - 服务拆分粒度是权衡点原因：粒度越细→可修改性提升、新功能上线快，但同时→服务调用链变长→性能下降、故障点增多→可用性下降，三个质量属性互相制约

3. NPV 计算：
   - 方案 A：NPV = -800 + 650×(1/1.1 + 1/1.21 + 1/1.331 + 1/1.4641 + 1/1.6105) = -800 + 650×3.7908 = -800 + 2464.02 = 1664.02 万元
   - 方案 B：NPV = -300 + 280×3.7908 = -300 + 1061.42 = 761.42 万元
   - 结论：方案 A 净现值 1664.02 万元 > 方案 B 净现值 761.42 万元，虽然方案 A 投入高，但 5 年累计收益显著，建议选择方案 A（微服务架构）

**踩分要点**：
- 效用树必须三层以上且叶子为可度量场景
- 权衡点必须明确指出"影响多个质量属性 + 互相制约"
- NPV 计算需写出公式与贴现系数，结论需结合 NPV 数值

## 记忆口诀
**架构评估三方法**：SAAM 早、ATAM 强、CBAM 算（场景溯源早、权衡分析强、成本效益量化）
**ATAM 九步流**：陈业架→属树→构析→属析→危识→议果→报告（陈述方法→陈述业务→陈述架构→确定质量属性→生成效用树→分析架构→分析质量属性→识别风险→讨论结果→报告）
**敏感 vs 权衡点**：敏感单属性、权衡多属性（敏感点只影响一个，权衡点影响多个）
**效用树六要素**：源激环响应构（刺激源、刺激、环境、响应、响应度量、构件）
**质量属性六边形**：性可用改安维移（性能、可用性、可修改性、安全性、可维护性、可移植性）
