## 今日核心概念

### 1. 云原生应用架构与容器化
定义：云原生应用架构是一套以容器、服务网格、微服务、不可变基础设施和声明式 API 为基础的工程方法论，使应用具备弹性、可观测、可灰度、可自愈的云端属性，支撑业务持续交付。
关键要点：
- 容器化以镜像为最小交付单元，遵循十二要素原则，把配置外置、进程无状态、日志走标准输出，便于跨环境一致部署。
- 编排调度以 Kubernetes 为事实标准，通过 Pod、Deployment、StatefulSet、DaemonSet 等控制器管理应用生命周期。
- 不可变基础设施通过镜像替换实现版本变更，杜绝 SSH 改机导致的配置漂移；镜像签名与 SBOM 保障供应链可信。
- 声明式 API 让运维人员描述期望状态，控制器持续调和实际状态与期望状态一致，减少人工脚本。
- 弹性伸缩覆盖 HPA、VPA、Cluster Autoscaler 与 KEDA 事件驱动，配合探针保证扩缩容的健康与稳定。

### 2. 服务网格与流量治理
定义：服务网格是把服务间通信、流量控制、安全、可观测能力从应用代码下沉到独立基础设施层的架构模式，让应用专注业务逻辑，让平台负责通信治理。
关键要点：
- 数据面以 Sidecar 代理拦截进出流量，常用实现为 Envoy、Istio 注入 Linkerd，统一承载路由、熔断、重试。
- 控制面负责配置分发、证书签发、策略执行，常见实现有 Istio、Linkerd、Consul Connect，配合 xDS 协议动态下发。
- 流量治理支持蓝绿、金丝雀、A/B 测试、流量镜像、超时重试、限流熔断和故障注入，是渐进式发布的关键支撑。
- 安全治理通过 mTLS 自动签发证书实现零信任通信，结合 RBAC 与 AuthorizationPolicy 做身份与策略鉴权。
- 可观测自动采集 L7 指标、调用链与访问日志，与外部 Tracing、Metrics、Logging 系统协同形成完整观测闭环。

### 3. 多云与混合云架构
定义：多云与混合云架构指企业同时使用公有云、私有云、边缘节点与本地数据中心，通过统一管控和跨云网络实现资源调度与业务连续性的架构形态。
关键要点：
- 多云选型分主动与被动两种：主动多云规避厂商绑定，被动多云用于灾备、合规和性能区域覆盖。
- 网络互联通过专线、SD-WAN、云联网和 IPSec VPN 打通，注意跨网延迟、带宽成本和路由策略统一。
- 资源抽象层通过 Kubernetes 多集群、Cluster API、Crossplane 把不同云资源统一为声明式对象，降低迁移成本。
- 数据层通过跨云存储复制、对象存储多活、数据网格解决跨地域数据一致与主权合规要求。
- 治理层通过 IaC、GitOps、策略即代码 OPA/Kyverno 统一多云配额、成本、变更和安全基线。

### 4. 边缘计算与云边协同
定义：边缘计算是把计算、存储、网络资源下沉到靠近数据源或用户的位置，云边协同是云端统一调度与边缘自治结合的体系结构，用于满足低时延、带宽节省、离线可用的场景。
关键要点：
- 边缘节点分类包括 CDN 边缘、运营商 MEC、工业现场边缘、车边端和 IoT 网关，对应不同算力与网络条件。
- 云边协同三层分工：云端负责训练、模型分发、策略编排；边缘负责推理、数据预处理、本地决策；端侧负责采集、初步过滤和安全启动。
- 边缘自治要求弱网断网下仍能本地决策、定时同步、断点续传，恢复后做冲突合并与对账。
- 编排调度通过 KubeEdge、OpenYurt、K3s 把 Kubernetes API 延伸到边缘，统一应用下发与状态回传。
- 典型场景覆盖工业互联网、车联网、视频 AI、智慧城市和元宇宙入口，对延迟敏感业务尤为关键。

### 5. 云原生可观测性与 SRE
定义：云原生可观测性是通过日志、指标、追踪三大支柱及衍生用户体验数据，主动洞察系统内部状态的能力；SRE 是以错误预算、SLI/SLO 和运维工程化保障服务可靠性的实践体系。
关键要点：
- 三大支柱采集各司其职：Metrics 聚合趋势、Logs 记录离散事件、Traces 串联调用链，互为补充不可替代。
- SLI 量化用户体验、SLO 设定可承诺目标、错误预算把可靠性与发布节奏挂钩，预算耗尽时暂停非紧急变更。
- AIOps 与可观测结合能自动发现异常、根因定位、容量预测与告警收敛，提升值班效率。
- 告警分级按业务影响与可行动性划分，配合 Runbook、自动修复和值班响应，避免告警疲劳。
- 持续演练包括故障注入、混沌工程、桌面推演和年度全链路切换，确保故障时人和系统都能从容应对。

## 案例分析题
**题目**：某省级交通投资集团正在建设面向高速公路干线、桥梁隧道、收费稽核、应急救援与出行服务的综合一体化平台，预计接入 18 条高速、超过 4 万路视频和 240 个收费站，日均采集过车数据 1.2 亿条、对外发布路况与诱导信息 6000 万次。集团明确提出五个目标：一是新业务上线从月级缩短到天级；二是视频与 AI 推理下沉到路段收费站减少回传带宽；三是各类事故和恶劣天气的应急响应时延压缩到秒级；四是核心收费与稽核系统全年可用性不低于 99.99%；五是杜绝多云之间的厂商绑定和数据孤岛。当前架构面临五个痛点：业务部署仍以虚拟机为主，每周手动变更导致故障率居高不下；服务间耦合严重，新业务上线必须协调 6 个团队；路段视频回传带宽占用高，AI 应用受限于网络；应急事件处置依赖人工经验，缺乏统一事件总线和联动规则；多云资源使用分散，资源利用率不到 30%。请从系统架构设计师角度回答：
1. 云原生与容器化改造路径如何规划，应怎样分阶段推进以兼顾业务连续性；
2. 服务网格与流量治理如何支撑高频发布与跨团队协作；
3. 边缘计算与云边协同如何重构视频与 AI 链路，带宽与时延如何量化收益；
4. 可观测与 SRE 体系如何建设，SLI/SLO 与错误预算如何分层落地；
5. 多云与混合云架构应怎样设计统一管控、数据治理与成本治理体系。

**参考答案**：
1. 云原生改造采用四阶段推进。第一阶段建立容器与镜像基线，把非关键业务和新业务先容器化，使用同一套 CI 流水线构建镜像并签名入库。第二阶段引入 Kubernetes 与 GitOps，把测试与预发环境迁移到容器平台，部署采用 Helm+Kustomize 模板化和 ArgoCD 声明式同步。第三阶段把核心收费、稽核、应急等关键系统迁移到容器和 K8s，配合 StatefulSet、有状态中间件 Operator 和分级调度保证稳定。第四阶段建立多集群联邦与服务网格，对外实现跨地域、跨云统一调度。改造期间用双跑并行、蓝绿切换、灰度引流逐步切流，业务连续性优先于技术先进性。
2. 服务网格与流量治理按四层设计。第一层引入 API 网关统一边缘入口、协议转换、流量染色与限流，把集团内部、合作伙伴和外部出行应用分类管控。第二层在 K8s 之上引入 Istio 类服务网格，把跨团队服务统一接入注册中心和 mTLS，按业务域划分命名空间减少相互影响。第三层在网格上启用金丝雀、A/B 测试、流量镜像和按地域灰度，让每个业务团队独立发布不需集中排期。第四层把熔断、降级、超时、重试、限流策略模板化，团队按业务特性自助配置，网关和网格提供统一观测与回滚通道。
3. 边缘计算与云边协同按"云训练—边推理—端采集"重组。第一步在路段收费站、桥隧现场部署边缘节点，集成 GPU/NPU 与 K3s 容器运行时，对外提供实时视频分析、抛洒物检测、车流统计和异常事件识别能力。第二步通过 KubeEdge 或 OpenYurt 把云端模型、策略、配置统一下发，边缘节点在弱网下具备本地决策、缓存与断点续传能力，恢复后与云端做冲突合并与数据对账。第三步视频流从原始回传改成"边缘结构化、云端摘要"模式，只回传元数据、特征和事件片段，带宽占用可下降 80% 以上，AI 告警时延从分钟级降至秒级。第四步建立边缘资源池化与统一调度，按路段负载动态调度推理任务，确保边缘资源利用率与业务体验平衡。
4. 可观测与 SRE 按支柱—预算—演练体系搭建。采集层用 OpenTelemetry 统一采集指标、日志、追踪，结合 eBPF 与 APM 工具覆盖 OS、容器、应用和业务四层；按业务域、路段、地域、版本等多维度打标，支持任意维度聚合。SLI 定义必须贴近用户体验，比如过车数据端到端时延、收费交易成功率、视频 AI 事件检出率、应急指令下发时延。SLO 按业务分级，核心收费与稽核按 99.99% 承诺，AI 告警与视频按 99.9% 承诺，对外出行服务按 99.5% 承诺。错误预算按月滚动结算，预算耗尽触发非紧急变更暂停并启动可靠性专项。SLO 例行演练包括故障注入、混沌工程、桌面推演和年度灾备切换，让组织形成肌肉记忆。
5. 多云与混合云按统一管控、数据治理、成本治理三层设计。统一管控用 IaC 工具把不同云的资源抽象为声明式对象，通过 GitOps 统一变更；用 Cluster API 和 Crossplane 实现多集群和多云资源编排，把跨云网络、身份、策略收口到策略即代码 OPA 之上。数据层按"热数据本地、温数据跨云、冷数据归档"分级存储，关键收费与稽核数据跨云同步复制，AI 与视频特征走对象存储多活，分析与日志走冷归档降低成本；建立数据目录、血缘和质量闭环，杜绝数据孤岛。成本治理通过 FinOps 平台汇聚云资源账单，按业务域打标分配，按团队月度对账；引入预留实例、Spot、Savings Plans 与自动关停策略，让资源利用率从 30% 提升到 60% 以上，同时保留多云议价能力。

**踩分要点**：
- 云原生与容器化必须分阶段写，分阶段表述要明确"非关键先上、关键后上"，避免一次性全面铺开。
- 服务网格与流量治理要点出网关、网格、灰度、熔断四层，注意团队自助和统一管控并行。
- 边缘计算回答必须包含云边分工、带宽下降比例、时延改善、弱网自治，不要写成"边缘部署就行"。
- 可观测与 SRE 要明确 SLI/SLO 分级、错误预算机制和混沌演练；SLI 必须贴近用户，不能只写技术指标。
- 多云与混合云要写出 IaC、GitOps、策略即代码、跨云数据同步和 FinOps，体现治理而非简单堆叠。

## 记忆口诀
云原生四要素：容器、服务网格、不可变基础设施、声明式 API。
容器三件套：镜像、运行时、注册中心。
编排调度一标准：Kubernetes + CRD + Operator。
十二要素口诀：基准声明、依赖隔离、配置外置、后端服务、无状态进程、端口绑定、并发无共享、优雅启停、开发生产等价、日志流式、后台任务一次起、管理进程随取用。
弹性伸缩四招：HPA、VPA、CA、KEDA。
服务网格两面：数据面 Sidecar、控制面 xDS。
服务网格五能力：路由、灰度、熔断、可观测、安全。
API 网关六职能：路由、协议转换、鉴权、限流、染色、可观测。
蓝绿 vs 灰度：蓝绿瞬切、灰度比例引流。
云边三段式：云训练—边推理—端采集。
边缘自治三件事：本地决策、断点续传、冲突合并。
K8s 边缘四件套：K3s、KubeEdge、OpenYurt、Cluster API。
带宽下降比例：原始视频—边缘结构化，可省 80%。
可观测三支柱：日志、指标、追踪；外加用户体验。
SLI 三贴近：贴近用户、贴近业务、贴近结果。
SLO 分级三档：核心 99.99、重要 99.9、对外 99.5。
错误预算三挂钩：发布节奏、变更冻结、可靠性专项。
AIOps 三能力：异常检测、根因定位、容量预测。
多云两类型：主动多云、被动多云。
跨云三互联：专线、SD-WAN、云联网。
多云治理三工具：IaC、GitOps、策略即代码。
策略即代码两实现：OPA、Kyverno。
数据三温分级：热数据本地、温数据跨云、冷数据归档。
跨云数据复制两模式：同步复制、异步复制。
FinOps 三动作：资源打标、成本分摊、自动优化。
预留三件套：RI、SP、Spot。
多云议价三基础：账单透明、对账闭环、可迁移能力。
云原生安全左移四件：SAST、DAST、SCA、SBOM。
镜像供应链三要素：构建、签名、扫描。
声明式 API 三步走：期望状态、控制器调和、状态收敛。
零信任通信两件套：mTLS、AuthorizationPolicy。
发布四模式：蓝绿、金丝雀、A/B、流量镜像。
故障注入四手法：延迟、异常、断网、资源耗尽。
混沌演练四频率：日级别、周级别、月度专项、年度全链路。
SRE 四价值：可靠性工程化、错误预算、自动化、故障复盘。
