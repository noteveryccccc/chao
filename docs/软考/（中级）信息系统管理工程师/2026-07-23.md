## 今日核心概念

### 1. 国产化替代与信创工程
定义：信创即信息技术应用创新，是围绕芯片、操作系统、数据库、中间件、办公软件、应用系统和信息安全等领域推进自主可控替代的系统工程，目的是摆脱关键信息基础设施对国外产品和技术的依赖，筑牢网络安全和数据安全底线。
关键要点：
- 信创覆盖"两软一硬"及上下游生态，包括CPU、操作系统、数据库、中间件、办公套件、打印机、扫描仪、密码模块和整机等。
- 替代路径通常按"先外围后核心、先办公后业务、先试点后推广"的原则分阶段推进，避免一次性大规模替换引发业务中断。
- 推进信创必须同步开展应用改造、兼容性测试、性能压测、数据迁移和运维能力建设，否则会出现"换得动、用不稳、运维难"的问题。
- 党政机关、关键基础设施和重要行业应优先推进，替代过程中应保留必要容错、回退和应急通道。
- 信创不是简单的产品替换，而是涉及技术路线选型、生态适配、标准制定和人才队伍建设的整体转型。

### 2. 零信任安全架构
定义：零信任是一种以"持续验证、最小授权、动态评估"为核心思想的安全架构，假设网络内部和外部均不可信，所有访问请求都必须经过身份鉴别、设备评估、权限校验和行为分析后才允许执行。
关键要点：
- 零信任遵循"Never Trust，Always Verify"原则，打破传统边界防护中"内网可信、外网不可信"的假设。
- 核心组件包括身份治理、终端可信、网络微分段、软件定义边界、持续诊断与缓解、动态访问控制和安全分析平台。
- 访问决策综合考虑用户身份、设备状态、网络位置、访问时间、应用敏感度和行为风险，单一因素不再自动授权。
- 实施步骤通常从身份治理和终端可信入手，再逐步推进应用接入、微分段和动态访问。
- 零信任不是单一产品，而是覆盖身份、设备、网络、应用和数据的体系化能力。

### 3. 数字化转型与数字政府
定义：数字化转型是利用新一代信息技术对政府治理、机构运行、服务供给和决策方式进行系统性重构的过程；数字政府是其重要载体，强调以数据驱动、平台支撑、协同治理和智能服务为核心的新型治理模式。
关键要点：
- 数字化转型包含技术变革、业务重构、组织调整和制度配套四个维度，单纯技术升级不构成真正的转型。
- 数字政府建设通常围绕"一网通办、一网统管、一网协同"三条主线推进，重点解决跨部门数据共享、业务协同和统一服务入口问题。
- 建设内容包括政务云、政务数据资源平台、统一身份认证、统一电子证照、统一公共支付和智能客服等基础支撑。
- 评价维度包括服务便捷度、群众满意度、数据共享率、事项办理时长、跨部门协同效率和安全保障能力。
- 推进过程中应注重制度规范、数据治理、安全可控和队伍建设，避免出现"重建设、轻应用、轻运维"的问题。

### 4. 数据资产价值评估
定义：数据资产价值评估是对组织所拥有的数据资源，按照其质量、应用范围、合规成本和未来收益等因素进行识别、计量和分析的管理活动，是数据资产管理、数据流通和数据要素市场建设的基础。
关键要点：
- 评估维度通常包括数据质量、应用场景、业务贡献、获取成本、稀缺性、合规风险和潜在风险。
- 常用方法包括成本法、收益法、市场法和综合评估法：成本法按采集、存储、清洗和治理投入估算；收益法按应用带来的收入或成本节约估算；市场法参考同类数据交易价格；综合法组合多维度打分。
- 评估对象可以是单条数据、数据集、数据接口、数据模型或数据服务，粒度越细越能反映真实价值。
- 评估结果应支撑数据资产入表、数据共享定价、数据安全分级和数据交易决策。
- 数据资产价值具有时效性、场景依赖性和合规约束性，必须结合具体业务和合规要求动态评估。

### 5. 业务连续性管理BCP与灾难恢复DRP深化
定义：业务连续性管理是识别关键业务中断风险、制定响应预案、保证关键业务在可接受时间内恢复的管理体系；灾难恢复计划是其执行支撑，专注于信息系统和数据层面的恢复能力建设。
关键要点：
- BCP的核心流程包括业务影响分析、风险评估、策略制定、预案编写、资源保障、演练测试、持续改进和应急沟通。
- 关键指标包括RTO恢复时间目标、RPO恢复点目标、MTPD最大可容忍停机时间和MBCO最小业务连续性目标。
- 恢复策略常见模式有冷备、温备、热备、同城双活、两地三中心和异地多活，应根据业务等级选择匹配方案。
- 预案应包含组织指挥、通讯联络、应急处置、资源调度、回退方案、外部协同和事后复盘，避免成为无法访问的"抽屉文件"。
- 重要系统每年至少开展一次实战演练，演练后必须形成问题清单、责任分工、整改闭环和预案修订。

## 案例分析题

**题目**：
某市承担全省政务服务平台国产化替代试点，要求在一年内完成一百二十个核心系统从 X86 加 Oracle 加 Windows 架构向国产芯片加麒麟操作系统加达梦数据库加东方通中间件的迁移。审计与运行半年后，发现以下问题：
一是部分单位片面追求进度，将尚未完成兼容性测试的核心业务系统直接上线，运行一周内出现三次接口超时和两次数据不一致问题，被迫临时回退。
二是身份认证仍依赖原有 AD 域账号体系，但国产终端未能完全支持原有域账号协议，部分用户采用本地账号登录，导致零信任要求的"持续验证、最小授权"无法落地。
三是试点系统未同步建立数据资产清单，价值评估、安全分级和共享定价缺乏依据，跨部门共享仍通过邮件、U 盘和 FTP 完成。
四是核心数据库虽完成迁移，但备用机房仍采用老旧存储，未启用同步复制和两地三中心架构，最近一次演练因存储链路故障 RTO 超过八小时，超出合同约定的四小时。
五是项目推进中只关注系统上线数量，未同步建立信创运维团队、应急响应流程和回退预案，发生故障后厂商响应不一致，运维人员不会处理国产数据库故障。
请从信息系统管理工程师角度，分析上述问题，并提出针对性改进措施。

**参考答案**：

一、信创推进节奏与兼容性测试不足的问题
- 原因：未严格遵循"先外围后核心、先试点后推广"原则，将未完成兼容性测试、性能压测和数据验证的核心系统直接上线。
- 措施：制定分阶段迁移路线图，先办公类、邮件类、辅助类系统，再业务类、交易类、核心类系统；每个系统上线前必须完成功能验证、兼容性测试、性能压测、数据校验和回退演练；建立灰度发布、白名单切换和新旧系统并行运行机制，异常时一键回退。

二、零信任与身份治理脱节的问题
- 原因：终端切换后身份认证体系未同步改造，存在本地账号、弱口令、多套账号并存的情况，零信任缺乏可信身份基础。
- 措施：建立统一身份治理平台，统管组织、用户、角色、权限和账号生命周期；所有终端和应用接入零信任网关，强制身份鉴别、设备可信评估、最小授权和持续验证；定期清理本地账号、孤儿账号和共享账号，统一强密码策略并启用多因素认证。

三、数据资产管理与共享治理薄弱的问题
- 原因：未建立数据资产清单、价值评估和安全分级，跨部门共享缺乏目录、定价和安全管控。
- 措施：组织数据资产盘点，建立覆盖数据资源、数据集、数据接口和数据模型的资产目录；按数据质量、应用贡献、获取成本、合规风险等维度开展价值评估；结合评估结果实施分级保护、共享审批、脱敏处理和操作留痕；推动数据通过统一共享平台交换，禁止邮件、U 盘和 FTP 方式传递敏感数据。

四、业务连续性与灾备能力不达标的问题
- 原因：核心数据库迁移后备用机房未同步升级，未实现同步复制和两地三中心，演练 RTO 超合同要求。
- 措施：按业务等级重新确定 RTO、RPO 和恢复策略，重要系统采用同城双活或两地三中心架构；备用机房同步升级存储、网络和密码模块，启用同步复制或准同步复制；每年至少两次灾备演练，演练覆盖切换、验证、回切和业务验证；将 RTO、RPO 和可用性纳入 SLA 考核并与厂商责任挂钩。

五、信创运维能力与应急体系缺失的问题
- 原因：只关注系统上线数量，未同步建设国产化运维团队、应急流程和厂商协同机制，运维人员不熟悉国产技术栈。
- 措施：建立信创运维团队，针对国产芯片、操作系统、数据库和中间件开展分层培训和认证；编写覆盖故障分级、应急响应、厂商升级、版本变更和数据修复的专项预案；与各生态厂商签订 SLA，明确响应时效、升级窗口、远程支持和现场支持要求；建立故障案例库、知识库和复盘机制，逐步沉淀自有运维能力。

**踩分要点**：
- 信创推进要答出"先外围后核心、先试点后推广"，并强调兼容性测试、性能压测、数据校验和回退演练。
- 零信任要答出"持续验证、最小授权、动态评估"，并结合统一身份治理、终端可信和多因素认证。
- 数据资产管理要答出资产目录、价值评估、安全分级、共享审批和脱敏，并强调禁止邮件、U 盘、FTP 传递。
- 灾备要答出 RTO、RPO、同城双活、两地三中心、同步复制、实战演练和 SLA 考核。
- 运维能力要答出培训认证、专项预案、厂商 SLA 和知识库沉淀，避免"重建设、轻运维"。
- 每个问题均采用"原因加措施"结构作答，措施必须紧扣题干现象，不能泛泛而谈。
