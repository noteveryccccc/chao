## 今日核心概念
### 1. 项目整合管理
定义：在项目全过程中，对各管理领域的目标、计划、变更、风险和资源进行统一协调，使项目各部分形成有机整体的管理活动。
关键要点：
1. 主要过程包括制定项目章程、制定项目管理计划、指导与管理项目工作、实施整体变更控制、结束项目或阶段。
2. 项目章程明确项目目标、范围边界、主要干系人、总体里程碑和项目经理权限，是项目正式启动的依据。
3. 项目管理计划整合范围、进度、成本、质量、资源、沟通、干系人、风险和采购等内容，不能用单项计划替代整体计划。
4. 整体变更控制包括提出申请、影响分析、审查批准、实施变更、验证结果和归档记录。
5. 变更批准前必须评估对范围、进度、成本、质量、风险和资源的影响，未经批准不得直接修改基线。
6. 项目经理的核心职责不是单纯“催进度”，而是识别冲突、统筹决策并保持项目目标与组织战略一致。

### 2. 项目范围管理
定义：确定项目需要完成的工作，控制项目边界，防止遗漏必要工作或纳入无效工作，确保项目交付成果符合需求的管理活动。
关键要点：
1. 主要过程包括规划范围管理、收集需求、定义范围、创建工作分解结构、确认范围和控制范围。
2. 需求应形成需求文件，并通过需求跟踪矩阵建立“需求—设计—开发—测试—交付”之间的对应关系。
3. 项目范围说明书详细说明项目范围、主要交付成果、验收标准和除外责任，是范围确认的重要依据。
4. 工作分解结构应逐层分解，覆盖百分之百的项目工作；上层是项目，下层是可管理、可估算、可分派的工作包。
5. 范围基准由范围说明书、工作分解结构和工作分解结构词典共同构成，未经正式变更不能随意扩大。
6. 确认范围关注“交付成果是否被客户接受”，控制范围关注“实际工作是否偏离批准范围”，两者不能混淆。

### 3. 项目进度管理
定义：按照项目目标安排活动顺序、估算持续时间、编制进度计划，并在执行过程中识别偏差、采取纠偏措施的管理活动。
关键要点：
1. 主要过程包括规划进度管理、定义活动、排列活动顺序、估算活动持续时间、制定进度计划和控制进度。
2. 依赖关系包括完成—开始、开始—开始、完成—完成、开始—完成，编制计划时还要考虑资源约束和外部条件。
3. 关键路径是决定项目最短工期的最长活动路径；关键路径上的活动通常总时差为零或最小。
4. 总时差表示活动在不影响项目总工期或后续约束的前提下可以延误的时间。
5. 赶工通过增加资源压缩工期，成本通常上升；快速跟进将原本顺序开展的活动部分并行，返工风险通常增加。
6. 进度控制应持续比较计划与实际，分析偏差原因，预测完工影响，并提出预防措施和纠正措施。

### 4. 项目质量管理
定义：通过规划质量、管理质量和控制质量，使项目成果满足相关方需求、适用标准和验收要求的管理活动。
关键要点：
1. 规划质量管理确定质量标准、质量指标、测量方法、验收方式和质量保证活动。
2. 管理质量关注过程和体系，侧重审计、过程改进、标准化和预防缺陷；控制质量关注成果，侧重检验、测试、测量和验收。
3. 质量成本包括预防成本、评价成本、内部失败成本和外部失败成本，预防投入通常能够降低后续失败成本。
4. 常用质量工具包括流程图、因果图、帕累托图、核对表、直方图、散点图和控制图。
5. 质量控制不能只检查最终成品，应在需求、设计、开发、测试和上线各阶段设置质量门。
6. 发现缺陷后要记录、分类、分析原因、分派责任、验证修复并进行趋势分析，避免同类问题重复发生。

### 5. 项目成本管理
定义：在批准的预算范围内，对项目成本进行估算、预算编制、监控和预测，确保项目资金使用合理并实现预期效益的管理活动。
关键要点：
1. 主要过程包括规划成本管理、估算成本、制定预算和控制成本。
2. 成本基准是经过批准且按时间段分配的项目预算，是衡量项目绩效的重要依据。
3. 计划价值表示截至某时点计划完成工作的预算价值；实际成本表示截至某时点完成工作实际发生的成本；挣值表示截至某时点实际完成工作的预算价值。
4. 进度偏差等于挣值减计划价值；成本偏差等于挣值减实际成本。
5. 进度绩效指数等于挣值除以计划价值；成本绩效指数等于挣值除以实际成本。
6. 完工估算通常等于项目总预算除以成本绩效指数；应结合风险、剩余工作量和变更影响综合预测。
7. 成本控制不能只追求少花钱，还要考虑质量、进度、范围和风险之间的平衡。

## 案例分析题
**题目**：某市人力资源和社会保障局建设“智慧就业服务一体化平台”，项目总工期为18个月，批准预算为3000万元。平台包括就业事项网上办理、人才服务、政策发布、数据分析和移动端服务等功能。项目执行到第8个月时，发生了以下事件：
事件一：新任分管副局长要求新增“人工智能政策匹配”功能，并要求在两个月内上线。项目团队直接安排开发人员开始编码，没有履行变更审批手续。
事件二：需求调研阶段只形成了一页会议纪要，没有建立需求跟踪矩阵。开发过程中，业务处室先后提出多项新需求，团队对“哪些工作属于原范围”产生争议，部分已开发功能被迫返工。
事件三：第8个月进度监测数据显示：计划价值为1200万元，挣值为1000万元，实际成本为1100万元。此时项目已发生严重进度延误，数据库查询功能还存在响应时间过长的问题。
请回答：
1. 事件一中项目经理应如何实施整体变更控制？
2. 事件二反映出项目范围管理存在哪些问题？应如何整改？
3. 根据事件三的数据，计算进度偏差、成本偏差、进度绩效指数和成本绩效指数，并判断项目状态。
4. 针对平台当前问题，提出进度、质量和成本方面的综合改进措施。

**参考答案**：
1. 事件一应立即暂停未经批准的新功能开发，防止范围、成本和质量风险继续扩大。具体步骤如下：
   （1）由提出方提交正式的变更申请，说明新增功能的目标、必要性和期望完成时间。
   （2）项目经理组织相关人员开展影响分析，评估对项目范围、进度、成本、质量、资源、风险和干系人的影响。
   （3）提交变更控制机构或授权审批人审查；涉及范围基准、进度基准或成本基准的重大变更，必须由有权机构批准。
   （4）批准后更新项目文件、相关计划和合同，更新范围、进度及成本基线，并将变更内容传达给所有相关人员。
   （5）按照批准后的方案实施，测试和验证功能效果，跟踪变更后的绩效，形成书面记录并归档。
   （6）若变更未被批准，应说明理由和影响，恢复原计划执行，不能以领导口头要求代替正式程序。
2. 事件二反映的主要问题及整改措施如下：
   （1）需求收集不充分。应通过访谈、问卷、原型、观察和专题会议等方式充分获取业务需求，明确业务规则、优先级和验收标准。
   （2）缺少需求文件。应形成规范的需求文件，记录功能需求、非功能需求、约束条件、假设条件和排除项。
   （3）未建立需求跟踪矩阵。应为每项需求建立唯一编号，并追踪到设计、编码、测试用例和交付成果，确保双向可追溯。
   （4）范围定义和分解不足。应编制范围说明书，必要时建立工作分解结构，明确项目工作包、责任人和验收标准。
   （5）变更控制不严。新需求应先申请、评估和批准，再决定是否纳入范围基准；对未经批准的工作不得直接承诺或实施。
   （6）范围确认不到位。每个阶段或交付成果应进行阶段性验收，及时发现需求遗漏、误解和范围蔓延。
3. 计算如下：
   （1）进度偏差=挣值－计划价值=1000－1200=－200万元，说明截至第8个月项目实际完成工作的预算价值低于计划，项目进度落后。
   （2）成本偏差=挣值－实际成本=1000－1100=－100万元，说明完成相同工作所花的成本超过预算，项目成本超支。
   （3）进度绩效指数=挣值÷计划价值=1000÷1200≈0.83，说明实际完成工作的预算价值仅达到计划的百分之八十三左右。
   （4）成本绩效指数=挣值÷实际成本=1000÷1100≈0.91，说明实际成本效率低于预算，成本控制不理想。
   综合判断：项目处于进度落后且成本超支状态，挣值指标显示项目需要重点进行进度纠偏和成本控制。
4. 综合改进措施如下：
   （1）进度方面：重新审查关键路径，分解剩余工作，明确关键任务和责任人；对确实影响总工期的工作评估赶工或快速跟进的可行性；设置阶段性里程碑和滚动式计划，及时清理阻塞事项。
   （2）质量方面：对数据库查询问题开展根因分析，从需求、数据库设计、索引、查询语句、服务器资源和网络环境等方面定位原因；制定测试计划，进行功能、性能、安全和回归测试；建立缺陷分级、修复、验证和关闭机制。
   （3）成本方面：核对人工、外包、设备、软件许可和运维等实际成本，查找超支原因；优化资源投入和工作优先级，严格执行采购、合同和付款审核；将新增功能单独评估预算影响，不能用其他工作预算掩盖变更成本。
   （4）管理方面：建立统一的项目计划、变更台账、问题台账和风险台账；由项目经理组织阶段评审，及时向项目管理机构和主要干系人报告绩效；所有范围、进度和成本调整均形成可追溯记录。
   （5）决策方面：若新增功能与原目标冲突，应依据审批结果决定纳入、延期、分阶段实施或取消，并同步调整范围、进度和成本基线。

**踩分要点**：
1. 整体变更控制必须答出“申请—影响分析—审查批准—实施—验证—归档”完整流程。
2. 要指出未经批准的新增功能属于范围蔓延，不能仅凭领导口头要求直接开发。
3. 范围管理要答出需求收集、范围定义、工作分解结构、范围确认和范围控制。
4. 需求跟踪矩阵是高频踩分点，要答出需求与设计、开发、测试、交付成果的对应关系。
5. 进度偏差和成本偏差必须使用正确公式：进度偏差=挣值－计划价值；成本偏差=挣值－实际成本。
6. 进度绩效指数=挣值÷计划价值，成本绩效指数=挣值÷实际成本。
7. 数据结论必须答出“进度落后、成本超支”，并能结合结果提出纠偏措施。
8. 赶工与快速跟进的区别是高频考点：赶工通常增加资源并提高成本；快速跟进通常增加并行和返工风险。
9. 质量管理要同时关注过程和成果，不能只写“加强测试”，还要写审计、预防、缺陷闭环和持续改进。
10. 改进方案要覆盖范围、进度、成本、质量、风险和沟通，不能只写“加强管理”这种空泛表述。

## 记忆口诀
**整合管理五过程口诀**：「章计指变收」
（制定项目章程→制定项目管理计划→指导与管理项目工作→实施整体变更控制→结束项目或阶段）

**范围管理六过程口诀**：「规收定建确控」
（规划范围管理→收集需求→定义范围→创建工作分解结构→确认范围→控制范围）

**进度管理六过程口诀**：「规列排估制控」
（规划进度管理→定义活动→排列活动顺序→估算活动持续时间→制定进度计划→控制进度）

**质量管理三过程口诀**：「规管控」
（规划质量管理→管理质量→控制质量；管理质量管过程，控制质量管成果）

**成本管理四过程口诀**：「规估制控」
（规划成本管理→估算成本→制定预算→控制成本）

**挣值判断口诀**：「先看偏差，再看指数；小于一，进度成本都不理想」
（进度偏差或成本偏差小于零，进度绩效指数或成本绩效指数小于一，均说明对应绩效未达计划）

**赶工快速跟进口诀**：「赶工加资源，快速并行做；前者多花钱，后者返工多」
