## 今日核心概念
### 1. 服务可用性计算与可靠性指标
定义：可用性指在规定时间内服务保持可用的能力，用可用率衡量；可靠性衡量系统无故障运行的能力。

关键要点：
- 可用率 = 可用时间/(可用时间+不可用时间) = MTBF/(MTBF+MTTR)
- MTBF（平均无故障时间）：两次故障之间的平均间隔，越大越好
- MTTR（平均修复时间）：从故障发生到恢复的平均时长，越小越好
- 每年可用率换算：99.9%（三个9）年停机≤8.76小时；99.99%≤52.6分钟；99.999%≤5.26分钟
- 月度可用率计算要与SLA约定一致，常用于违约判定
- 并联冗余可提高可用率：可用率=1-(1-A1)×(1-A2)

### 2. 发布与部署管理
定义：将经过测试的变更成果正式发布到生产环境的过程，是变更管理在实施阶段的具体落地。

关键要点：
- 发布类型：重大发布、小型发布、紧急发布（对应变更三类型）
- 发布计划四要素：发布范围、发布时间窗口、回滚方案、干系人通知
- 部署策略：蓝绿部署（Blue-Green）、金丝雀/灰度发布、滚动发布（Rolling）、全量停机
- 回滚预案是发布必选项，发布失败立即回退到上一稳定版本
- 与变更管理关系：变更通过CAB审批后，由发布管理负责实施与部署

### 3. 信息安全事件管理与上报
定义：对安全事件进行识别、响应、处置、恢复并按规定上报的全过程管理。

关键要点：
- 事件分类：恶意代码、网络攻击、数据泄露、系统入侵、违规操作、物理破坏
- 处置流程：检测响应→抑制根除→恢复→总结报告（对应应急响应阶段）
- 上报要求：重大事件第一时间上报（一般≤1小时），按等级分级上报
- 组织：CERT/CSIRT应急响应组织（国家/行业/单位三级）
- 事后复盘：根因分析、整改措施、纳入知识库，防止重复发生

### 4. 供应商与合同管理
定义：对外包服务商或软硬件供应商进行选择、签约、履约监督、评价与退出的全过程管理。

关键要点：
- 合同关键条款：服务范围、SLA指标、费用与付款、违约与罚则、保密条款、退出机制
- SLA指标要可量化可测量（可用率、响应时间、解决时间、满意度）
- 供应商评价：定期绩效评估（协议达成率、服务质量、配合度）
- 多供应商时划分责任边界，避免互相推诿
- 合同到期评估续签或更换，退出时做好数据交接与资产回收

### 5. 服务报告与度量体系
定义：通过收集、整理、分析运维数据，形成规范的服务报告，支撑服务改进与决策。

关键要点：
- 报告类型：日常日报、周报、月报、年度报告；按对象分管理层/业务层/操作层
- 常见度量指标：事件量、问题解决率、SLA达成率、工单平均响应/解决时长、可用率、客户满意度CSAT
- 度量要符合SMART原则：具体、可测量、可实现、相关、有时限
- 报告是CSI（持续服务改进）的数据基础，要形成"度量-分析-改进-再度量"闭环
- 数据来源：服务台工单系统、监控系统、CMDB、满意度调查

## 案例分析题
**题目**：某市政务云平台承载一网通办、协同办公等核心业务，与运营商签订SLA约定月可用率≥99.9%。某月发生两次故障：
- 故障一：硬件故障导致服务中断6小时，MTTR=6小时；
- 故障二：漏洞升级导致中断40分钟。
该月共30天。运维团队同时面临发布管理漏洞（曾有一次未经充分测试直接全量发布导致故障回滚），且未建立安全事件上报流程。

问题：
1. 请计算该平台该月的可用率，判断是否满足SLA约定的99.9%，并说明依据（按每月30天计算）。
2. 针对发布管理漏洞，请给出三种安全的部署策略，并分别说明其适用场景。
3. 若发生一起涉及公民个人隐私数据泄露的重大安全事件，请说明其上报要求与处置流程要点。

**参考答案**：
1. 可用率计算：
   - 月总可用时间 = 30天×24小时 = 720小时
   - 总不可用时间 = 6小时 + 40分钟/60 = 6 + 0.667 = 6.667小时
   - 可用率 = (720-6.667)/720 × 100% = 713.333/720 = 99.074%
   - 结论：99.074% < 99.9%，不满足SLA约定
   - 分析：SLA约定月可用率≥99.9%对应月停机上限 = 720×(1-0.999) = 0.72小时（约43.2分钟），实际停机6.667小时远超上限，构成SLA违约，应按合同追究违约责任

2. 三种安全部署策略：
   - 蓝绿部署：两套环境（蓝/绿）并行，只有一套承担流量，新版本在另一套验证后再切换。适用：允许双环境投入、对停机敏感的政务核心系统
   - 金丝雀/灰度发布：先让小比例流量（如5%-10%）访问新版本，观察无异常后逐步扩大至全量。适用：用户量大的互联网化平台，风险逐步释放
   - 滚动发布：按批次滚动更新实例，始终保持服务在线。适用：无状态、多实例的微服务架构
   - 说明：以上策略均需配备回滚预案，失败立即回退上一稳定版本

3. 重大安全事件上报与处置：
   - 上报要求：第一时间（通常≤1小时）向单位安全负责人及上级/监管部门报告，重大事件按规定向网信、公安部门报告；报告内容含事件时间、范围、影响、涉及数据、处置进展，并持续更新
   - 处置流程要点：检测确认→快速抑制（隔离受影响系统、断开外联、止损）→根除原因（清除木马/漏洞、重置口令）→恢复业务（验证数据完整性后恢复）→总结复盘（RCA根因分析、整改、纳入知识库、完善预案）

**踩分要点**：
- 第1题：必须算准720小时总时间、6.667小时停机、99.074%结果；要明确低于99.9%构成违约；若能写出43.2分钟上限更具说服力
- 第2题：三种策略各要写清原理+适用场景；回滚预案是加分点
- 第3题：上报要答"第一时间+分级上报+向监管部门"；处置务必按"检测-抑制-根除-恢复-复盘"五步，漏一步扣分

## 记忆口诀
### 可用率口诀
**「三七五，876小时」**
- 99.9%（三个9）＝年停机≤8.76小时
- 99.99%（四个9）＝年停机≤52.6分钟
- 99.999%（五个9）＝年停机≤5.26分钟

### 可用率公式口诀
**「可用率，MTBF比上MTBF加MTTR」**
- 可用率 = MTBF/(MTBF+MTTR)
- MTBF越大越好，MTTR越小越好

### 部署策略口诀
**「蓝绿切换金丝雀，滚动不停全量停」**
- 蓝绿：双环境切换
- 金丝雀：灰度小流量试错
- 滚动：分批更新不停机
- 全量：停机发布（风险最高）

### 安全事件处置口诀
**「检测抑制根除恢复复盘」**
- 检测：识别确认
- 抑制：隔离止损
- 根除：清除原因
- 恢复：验证后恢复
- 复盘：RCA+整改入库

### 报告度量口诀
**「数准可用达成满意」**
- 数：数据齐全
- 准：指标量化
- 可：可用率
- 达：SLA达成率
- 满：满意度CSAT
- 意：符合SMART原则
