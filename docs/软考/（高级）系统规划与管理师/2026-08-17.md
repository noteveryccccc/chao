## 今日核心概念

### 1. IT服务运营管理（ITSM中的运营层）

定义：IT服务运营是 ITIL生命周期中确保服务交付与支持得以日常执行的核心阶段，涵盖事件管理、问题管理、请求履行、监控与控制等流程，是服务可用性目标达成的主战场。

关键要点：
- 运营层是技术管理最频繁发生活动的层级，7x24小时不间断
- 核心流程：事件管理（Incident）、问题管理（Problem）、请求履行（Request Fulfillment）、访问管理（Access Management）
- 事件管理目标是尽快恢复服务（不是找根因），问题管理目标是找根因并防再现
- 一线解决率（First Call Resolution, FCR）是关键运营指标，目标一般 ≥ 70%
- 重大事件（Major Incident）需立即启动升级流程，2小时内未恢复升级至L2/L3

### 2. 服务级别管理（SLM）与SLA设计

定义：服务级别管理是通过协商、签订、监控、评审SLA，确保IT服务交付满足业务预期并持续改进的流程，是连接IT与业务的价值桥梁。

关键要点：
- SLA结构：服务范围、可用性指标（99.9%/99.99%）、响应时间、解决时间、违约金条款
- 可用性计算公式：可用率 = MTBF / (MTBF + MTTR)
 - 99.9% = 月停机 ≤ 43.8分钟
 - 99.99% = 月停机 ≤ 4.38分钟
- 服务级别协议（OLA）与支撑合同（UC）是内部/外部支撑SLA
- SLA评审每季度一次，根据业务变化动态调整，避免"签完就锁死"
- 服务质量评价（SQAP）支撑SLA达成率量化监控

### 3. 服务连续性与可用性管理（SCAM）

定义：服务连续性管理（SCM）确保关键IT服务在任何中断下都能恢复并继续运行；可用性管理（AM）则从设计、运行、改进三阶段系统性提升服务可用性。

关键要点：
- 连续性三件套：BIA（业务影响分析）、风险评估、RCP（恢复策略）
 - BIA识别关键业务功能 MTPD / RTO / RPO 三大量化指标
- 可用性管理四要素：可靠性（Reliability）、可维护性（Maintainability）、可服务性（Serviceability）、安全性（Security）
- 备份策略：全量+增量+差异组合，3-2-1原则（3份副本、2种介质、1份离线）
- 容灾等级：本地、同城、异地，云灾备三副本+跨可用区是底线
- 演练每年至少1次，桌面演练→模拟演练→真实切换逐步升级

### 4. 信息安全与风险管理

定义：在IT服务全生命周期中，通过PDCA循环系统识别、评估、处置、监控信息安全风险，确保CIA（机密性、完整性、可用性）三大属性的持续保障。

关键要点：
- 信息安全PDCA：Plan（风险评估+策略制定）→ Do（措施落地）→ Check（监控审计）→ Act（持续改进）
- 风险评估5×5矩阵：可能性（1-5）×影响度（1-5），得分≥15为高风险
- 风险处置四种策略：规避、转移、降低、接受（避转降受）
- 等保2.0五级五要素：物理、网络、主机、应用、数据 + 管理
- 三级以上系统每年测评一次，四级半年一次，CII（关键信息基础设施）必须第三级以上

### 5. 供应商管理与合同管理

定义：通过全生命周期管理外部供应商及合同条款，确保外包服务质量、成本、风险可控，是IT服务管理"对外协同"的集中体现。

关键要点：
- 供应商管理五阶段：规划→选择→合同签订→管理→评估/退出
- 合同类型三件套：SLA（服务质量协议）、OLA（内部协议）、UC（外部支撑合同）
- 违约处理三步走：违约记录→违约金扣减→严重时启动退出
- 退出管理：知识转移、数据归还、人员交接、应急预案，避免被单一供应商绑架
- 评估维度：交付质量（40%）+ 响应速度（30%）+ 成本控制（20%）+ 配合度（10%）

## 案例分析题

**题目**：

某省级政务云平台承载社保、医保、公积金等7个核心业务系统，2026年3月发生两次重大故障：
1. 3月10日因存储阵列单点故障导致社保系统中断4小时，用户大面积无法查询缴费记录；
2. 3月25日因DDoS攻击导致政务云入口瘫痪2小时。

事后复盘发现：
- SLA约定可用性99.95%，但实际月度可用率仅99.7%
- 事件管理流程形同虚设，一线坐席对存储故障无任何应急手册
- 问题管理未建立根源分析机制，同类存储故障6个月内发生3次
- 供应商合同中未明确安全防护责任，DDoS防护缺失
- 连续性演练仅走过场，未真正切换过

问题：
1. 依据可用性计算公式，分析该平台可用率未达标的原因（列出量化差距）
2. 针对3月10日存储故障，指出事件管理与问题管理的核心差异，并提出具体改进措施
3. 从供应商管理与连续性管理角度，分别给出DDoS防护缺失和连续性演练失效的整改方案

**参考答案**：

1. 可用率量化差距分析：
   - 月度理论停机时间（按SLA 99.95%）：43200分钟×(1-99.95%) ≈ 21.6分钟
   - 实际停机：240分钟（存储故障）+ 120分钟（DDoS攻击）= 360分钟
   - 实际可用率：(43200-360)/43200 ≈ 99.17%
   - 缺口：相比SLA差0.78个百分点，超额停机 338分钟
   - 触发SLA违约金条款（按合同约定百分比扣减服务费）

2. 事件管理 vs 问题管理核心差异及改进措施：
   - 核心差异：
     - 事件管理：目标是尽快恢复服务（速度优先），针对故障现象本身
     - 问题管理：目标是找到根因并防止再现（治本优先），针对故障根本原因
   - 具体改进措施：
     - 建立存储故障应急手册（事件）：一线坐席3分钟内启动切换脚本
     - 建立重大事件升级机制（事件）：30分钟未恢复自动升级至L3
     - 引入RCA根因分析（问题）：每次重大事件5个工作日内输出5Why分析报告
     - 建立已知错误库（KEKB）：存储单点列入高风险项，制定改造计划
     - 引入事件分级P1/P2/P3，匹配不同响应时效

3. 供应商管理 + 连续性管理整改方案：
   - DDoS防护缺失整改（供应商管理维度）：
     - 合同补充：明确安全防护责任边界，将DDoS防护纳入SLA
     - 供应商要求：必须提供T级DDoS清洗能力，纳入资质门槛
     - 监控告警：部署异常流量监测，触发阈值自动启动清洗
     - 安全审计：每季度对供应商安全能力进行评估打分
   - 连续性演练失效整改（连续性管理维度）：
     - 重做BIA（业务影响分析）：识别社保为RTO30分钟、RPO 5分钟级核心系统
     - 制定分级演练计划：桌面演练季度一次、模拟演练半年一次、真实切换年度一次
     - 引入第三方监理：演练过程需有记录、有录像、有签字
     - 建立演练评估机制：演练后30天内输出改进项并跟踪闭环

**踩分要点**：
- 可用率计算必须列出公式与量化数字（21分钟 vs 360分钟）
- 事件管理/问题管理必须答出"速度 vs 治本"的本质区别
- 改进措施要落到具体动作（应急手册、RCA、KEKB、5Why）
- 供应商管理必须涉及合同条款+资质门槛+评估审计
- 连续性管理必须包含BIA更新+分级演练+第三方监理
- 整改方案要可量化、可执行、可验证，不能只写"加强管理"

## 记忆口诀

**1. ITIL运营四流程口诀："事件问题请求访"**
- 事件管恢复、问题管根因、请求管履行、访问管授权

**2. 可用性等级口诀："三九四九五九"**
- 99.9% = 一年停机8.76小时（中小企业）
- 99.99% = 一年停机52.6分钟（核心系统）
- 99.999% = 一年停机5.26分钟（金融级）

**3. 风险处置四策略口诀："避转降受"**
- 规避（不做）、转移（外包/保险）、降低（措施）、接受（残余风险）

**4. 连续性三件套口诀："BIA风险RCP"**
- 业务影响分析、风险评估、恢复策略

**5. SLA违约口诀："月季年，三轮评"**
- 月度监控数据、季度评审改进、年度协议重谈

**6. 服务管理五维度口诀："质成风客战"**
- 质量保证、成本控制、风险管理、客户满意、战略对齐

**7. 供应商五阶段口诀："规选签管退"**
- 规划、选择、签订合同、管理、退出

**8. 安全CIA口诀："机完可"**
- 机密性（Confidentiality）、完整性（Integrity）、可用性（Availability）
