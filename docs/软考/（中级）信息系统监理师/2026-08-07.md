# 2026-08-07 学习笔记（第38次）

## 今日核心概念

### 1. 信息系统工程监理概述
定义：信息系统工程监理是依法设立且具备相应资质的监理单位，受建设单位委托，依据国家法律法规、标准和信息系统工程合同，对信息系统工程项目实施专业化监督管理的社会化服务活动，目标是控制工程质量、进度、投资并保障工程安全合规。
关键要点：
- 监理依据：《招标投标法》《合同法》《信息系统工程监理暂行规定》（信部信〔2002〕570号）等
- 监理性质：独立性、公正性、科学性、服务性，与业主、承建方形成三方制衡
- 监理范围：信息化工程、网络工程、软件工程、信息安全工程、信息系统集成工程
- 监理与项目管理区别：监理受建设单位委托代表甲方利益监督，PM代表承建方管理项目实施
- 总监理工程师、专业监理工程师、监理员三级岗位，监理工程师需持证上岗

### 2. 监理工作的主要任务与内容
定义："四控三管一协调"是信息系统工程监理的核心工作框架，监理围绕质量控制、进度控制、投资控制、安全控制、合同管理、信息管理、安全管理与组织协调开展工作。
关键要点：
- 四控：质量控制（核心）、进度控制、投资控制、安全控制
- 三管：合同管理、信息管理、安全管理
- 一协调：协调建设单位、承建单位、监理单位三方关系
- 质量控制：方案审查、过程旁站、平行检验、阶段性验收
- 进度控制：里程碑节点、网络图审查、进度偏差分析与纠偏
- 投资控制：工程量清单审核、变更费用审核、结算审核
- 安全控制：物理安全、网络安全、数据安全、应急安全的全方位监督

### 3. 监理工作程序与阶段划分
定义：信息系统工程监理工作按"准备—实施—验收"三阶段推进，每阶段有明确的监理工作程序与文档交付物，监理需按阶段有序介入。
关键要点：
- 招标阶段：协助建设单位编制监理招标文件、评标、定标
- 准备阶段：组建项目监理机构、编制监理规划与监理细则、参与设计交底
- 实施阶段：审批开工报告、审查实施方案、组织图纸会审、旁站监理、平行检验
- 验收阶段：组织初验、审核竣工资料、协助竣工验收、出具监理评估报告
- 监理文档：监理规划、监理细则、监理日志、监理月报、监理通知单、监理工作联系单、监理评估报告
- 监理工作遵循"事前审批、事中监督、事后验收"全流程闭环

### 4. 监理单位与人员资质管理
定义：监理单位资质与监理人员资格是开展信息系统工程监理业务的法定前提，监理行业实行单位资质与个人资格双重准入制度。
关键要点：
- 监理单位资质：分为甲级、乙级、丙级，甲级可承揽全国范围，乙级限于省级，丙级限于本地
- 资质标准：注册资金、技术人员数量、监理业绩、办公场所等硬性要求
- 总监理工程师：需具备信息系统监理师证书（软考中级）+ 工程实践经验
- 专业监理工程师：本科及以上学历、3年以上工程经验、经过监理培训
- 监理员：大专及以上学历、经过监理业务培训
- 监理工程师实行执业资格制度，软考"信息系统监理师"是核心执业资格

### 5. 监理责任与风险防范
定义：监理单位与监理人员因执业行为造成损失的，需承担相应的法律责任，监理应通过规范化执业规避执业风险。
关键要点：
- 监理责任形式：违约责任、侵权责任、行政责任、刑事责任
- 监理人员违规行为：与承建方串通、弄虚作假、降低标准、收受贿赂
- 监理责任界定：以监理合同约定为准，以监理通知单、监理日志为依据
- 风险防范：坚持旁站与平行检验、保留过程文档、重大事项书面请示、定期内部审核
- 监理责任保险：部分监理单位投保职业责任保险转移风险
- 监理人员对违规签字、虚假报告承担终身责任，监理单位承担连带赔偿责任

## 案例分析题
**题目**：某市"智慧政务"信息化工程项目总投资8000万元，包括政务外网升级、政务大数据平台、统一身份认证三大子系统。建设单位通过公开招标选择A公司承建、B监理公司承担监理。监理公司任命王某为总监理工程师，李某、张某为专业监理工程师。建设过程中发生以下事件：事件一，承建单位进场后未提交开工报告即开始施工；事件二，承建单位将核心交换机的品牌由原招标要求的核心交换机私自更换为国产品牌；事件三，监理工程师在审核中发现某模块代码存在严重SQL注入漏洞，要求整改但被承建单位拒绝；事件四，监理工程师李某私下接受承建单位宴请并收受购物卡。问题：
1. 事件一中，承建单位未提交开工报告即施工，监理应如何处理？
2. 事件二中，承建单位私自更换核心交换机品牌，监理应如何处理？涉及哪些监理依据？
3. 事件三中，监理要求整改被拒绝，应采取什么措施？该漏洞属于哪类安全风险？
4. 事件四中，监理工程师李某的行为违反了哪些规定？应如何处理？

**参考答案**：
1. 事件一的处理：监理工程师应立即下达《工程暂停令》，要求承建单位停止施工；同时签发《监理通知单》要求承建单位限期补交开工报告；审核开工报告中的施工组织设计、人员设备配置、进度计划、质量保证措施；待开工报告审批通过后签署《工程复工令》准予复工。监理处理依据是"未经监理工程师批准不得开工"的监理工作程序。
2. 事件二的处理：① 监理工程师应立即下达《工程暂停令》，制止私自更换行为；② 签发《监理通知单》要求承建单位说明情况并补办变更手续；③ 审查承建单位的设备变更申请，核心设备的品牌、规格、性能变更属于重大变更，应报建设单位审批并履行设计变更程序；④ 涉及金额变更的，应重新报审工程变更费用；⑤ 处理依据：监理合同约定的质量标准、招标投标文件的技术规格书、《合同法》关于标的物变更的条款、信息系统工程监理规范。未经批准擅自更换，监理不得签字确认工程量，不得支付相应款项。
3. 事件三的措施：① 监理工程师应再次签发《监理通知单》，明确指出SQL注入漏洞的严重性，要求承建单位限期整改；② 若承建单位拒不整改，监理应报告建设单位，建议暂停支付相应款项；③ 必要时签发《工程暂停令》并报告建设单位；④ 漏洞严重时及时报告行业主管部门。SQL注入属于Web应用安全风险中的注入类攻击（OWASP Top 10第一大风险），可能导致数据库信息泄露、数据篡改、系统被控等严重后果。
4. 事件四的处理：① 李某私下接受宴请、收受购物卡的行为违反《信息系统工程监理人员职业道德行为准则》，构成"与承建方存在不正当利益关系"的违规行为；② 违反《监理工程师执业准则》中的"廉洁自律"要求；③ 监理单位应对李某进行批评教育或行政处分，情节严重的应解除劳动合同；④ 同时将处理结果报告建设单位与行业主管部门；⑤ 重新审查李某已签字的所有监理文件的有效性；⑥ 该事件不影响监理单位对项目的正常监理工作，监理单位应更换监理人员并加强廉政教育。

**踩分要点**：
① 事件一：监理必须下达停工令、补审开工报告、批准后复工
② 事件二：擅自更换核心设备属重大违约，监理应停工+补办变更+重新审批+拒绝支付
③ 事件三：SQL注入是OWASP第一大风险，监理整改被拒应上报+暂停支付+停工令
④ 事件四：违反监理廉政准则，需批评教育+解除合同+报告主管+更换人员
⑤ 监理核心工具：监理通知单、工程暂停令、工程复工令、监理工作联系单
⑥ 总监理工程师负责制 + 三方制衡机制 + 终身责任
